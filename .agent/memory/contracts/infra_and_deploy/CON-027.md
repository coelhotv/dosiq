# CON-027 — createAnvisaDatabase + StorageAdapter (core on-demand ANVISA)

**Status:** proposed (2026-06-22) · **Spec:** 037 · **ADR:** ADR-073

## Interface

```
// packages/core/src/services/anvisaDatabase.js
createAnvisaDatabase({
  baseUrl,        // string — <supabase>/storage/v1/object/public/dosiq-assets/anvisa/v1
  fileKey,        // 'medicineDatabase' | 'laboratoryDatabase'
  storageAdapter, // StorageAdapter (abaixo)
  ttlMs = 7d,
  timeoutMs = 30s,
}) → {
  load(): Promise<NormalizedEntry[]>,   // cache-first + revalida; offline/erro → [] sem throw
  search(query, limit): Promise<Entry[]>,
  getByName(name): Promise<Entry|null>,
}

// StorageAdapter (injetado por plataforma)
{
  read(fileKey):  Promise<{ manifest, data } | null>,
  write(fileKey, { manifest, data }): Promise<void>,   // falha de write não quebra load
}
```

## Adapters
- **Web:** Cache Storage API. Guard `typeof caches !== 'undefined'` → fallback memória (jsdom/non-secure).
- **Mobile:** AsyncStorage (chaves por fileKey).

## Invariantes
- `load()` NUNCA lança (degradação graciosa); offline sem cache → `[]`.
- API pública dos 2 web services + retorno do hook mobile **inalterados** (consumidores).
- fetch com AbortController/timeout (R-168). Bucket público (sem auth, A3).

## Consumidores
- web `medicineDatabaseService` / `laboratoryDatabaseService` (casca)
- mobile `useMedicineDatabase` (Slice 2)
