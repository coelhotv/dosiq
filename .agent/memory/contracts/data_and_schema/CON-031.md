# CON-031 — criticalAuditService / dose_critical_events

**Status:** accepted (spec 042 Slice A) · **Decisão:** ADR-077 · **Tier:** 2

## Interface (`@dosiq/core`)

```js
import {
  createCriticalAuditService,
  criticalAuditEventSchema,
  CRITICAL_AUDIT_EVENTS,
  CRITICAL_AUDIT_PLATFORMS,
  CRITICAL_AUDIT_ACTORS,
} from '@dosiq/core'

const audit = createCriticalAuditService({ client, getUserId }) // getUserId opcional
await audit.emit({ doseInstanceId?, event, platform, actor, detail?, userId? })
// → { ok: boolean }  (NUNCA lança — fail-open)
```

### Resolução de `user_id` (SEC-2)
1. `evt.userId` explícito (cenário **server**: worker sem sessão deriva o dono da `dose_instance`).
2. `getUserId()` (mobile/web: usuário logado).
3. `null` → evento **órfão** → não insere, retorna `{ ok:false }`.

### Fail-open
Qualquer erro (Zod inválido, rede, RLS, throw do client) é capturado → `{ ok:false }`.
Auditoria jamais quebra o fluxo dono (alarme / registro de dose / push).

## Tabela `public.dose_critical_events`
`id · user_id · dose_instance_id? · event · platform · actor · detail? jsonb · created_at`
- **RLS** por `user_id = (select auth.uid())` — SELECT + INSERT do próprio (SEC-1).
- **Append-only** — sem UPDATE/DELETE para `authenticated`; prune só `service_role`/cron (SEC-4).
- **Prune 90d** via `pg_cron` (`prune-dose-critical-events`, `0 3 * * *`).
- Enums via CHECK, espelhados no Zod (R-270).

## Domínios
- **event** (11): `alarm_scheduled alarm_fired alarm_suppressed nag_fired snoozed resolved push_sent push_failed surface_transitioned push_skipped_no_token token_captured`
- **platform**: `ios android server` · **actor**: `user system server`
- **detail**: jsonb livre, **sem PII** (nunca nome de medicamento, token ou segredo) (SEC-3).

## Slice 067 C — `occurred_at` + regra de emissão do `push_skipped_no_token` (entregue)

### `occurred_at` — o instante do FATO (FR-042, ADITIVO)
`emit` aceita `occurredAt?: string | null` (ISO 8601 com offset) → coluna
`dose_critical_events.occurred_at timestamptz NULL`. **Semântica, e ela é o contrato:**

| coluna | significa | quem preenche |
|---|---|---|
| `occurred_at` | quando o FATO aconteceu | o EMISSOR, na origem |
| `created_at` | quando a LINHA entrou | o banco (`default now()`) |

- **NULL = hora do fato desconhecida** — não é "faltou preencher". É o estado honesto do evento iOS
  derivado no foreground (AP-257, que carrega `captured_at_foreground` no `detail`) e de **toda**
  linha anterior a esta migração (13.138 linhas; nenhuma foi reescrita).
- **NUNCA `default now()` no banco.** O default carimbaria a hora do INSERT e reintroduziria o erro
  com aparência de dado bom — foi o motivo de a coluna existir.
- **Consulta:** série longa usa `COALESCE(occurred_at, created_at)`; série precisa usa
  `WHERE occurred_at IS NOT NULL`. A escolha é de quem consulta, explicitamente.
- **É telemetria, nunca insumo de autorização** (RC-SEC/S-6): vem do relógio do device. Decisão de
  registro continua com o `now()` do servidor dentro da RPC.
- Medido em device: alarme 17:45:00.354 com a linha gravada 18:01:01.716 — **Δ 961s**, porque o
  takeover deixa o app `top-sleeping` (tela apagada) e o flush só roda em AppState `active`.

### Regra de emissão de `push_skipped_no_token` (FR-040 — passa a fazer parte do contrato)
O evento **não** é "não havia token". É *"quem PODIA ter Live Activity está sem token"*:
1. **Candidatura** — só emite se o usuário tem `notification_devices.platform='ios'`, de qualquer
   provider e **inclusive `is_active=false`** (Decisão 23). Sem device iOS não há recurso no
   aparelho, e ausência de recurso inexistente não é evento clínico. O teste NÃO é
   "`apns_liveactivity` ativo" — zeraria justamente o iPhone cujo push parou, que é o alvo do sinal.
2. **Uma vez por ocorrência** — a trava é a própria trilha (consulta por `dose_instance_id`), sem
   coluna nova. Antes o loop de minuto repetia ~60 linhas por dose, para sempre.
3. **Fail-open preserva o SINAL, não o silêncio** — erro nas checagens ⇒ emite. Ruído é bounded e
   reversível; perder diagnóstico de um iPhone real, não. E as checagens nunca alteram o desfecho do
   dispatch (`skipped` não pode virar `failed` por causa de um evento de diagnóstico).

Escala do corte, medida em 7 dias: 2.498 linhas do evento, das quais ~1.079 de usuário Android-only.

### FR-009 revogada
A limitação *"telemetria confiável só em Android até o Slice C"* **cai aqui**: com `occurred_at`, a
diferença entre plataformas deixa de ser silenciosa — iOS declara NULL em vez de fingir um instante.

### Não-breaking
`occurredAt` é opcional no emit e a coluna é nullable ⇒ cliente antigo segue válido (só não escreve).
Nenhum evento existente mudou de significado; nenhum valor de enum foi criado (R-271 não acionada).
