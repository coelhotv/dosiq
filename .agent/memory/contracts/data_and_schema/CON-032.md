# CON-032 — Motor da Evolução do tratamento (titulação N2)

**Status**: accepted · **Spec**: 029 (Slice F3) · **ADR**: ADR-080 · **Criado**: 2026-07-16
**Adiado do F2** (o serviço nasceu aqui, no slice do motor).

## Superfície pública (`@dosiq/core`)

### Decisão (pura, nível A strict, clock-free)

```ts
resolveTitrationAdvanceFromSteps(
  steps: TitrationStepEngineLike[] | null | undefined,
  todayLocal: string,          // 'YYYY-MM-DD' no fuso do DONO (getTodayLocal(tz))
  tz?: string                  // IANA; fallback 'America/Sao_Paulo' (R-254)
): TitrationAdvancePlan | null

interface TitrationAdvancePlan {
  transition: 'dose_change' | 'medicine_switch' | 'target_reached'
  completed: { id: string; endedAtIso: string }[]
  activated: TitrationStepTarget | null   // dose_change: nova vigente
  pending:   TitrationStepTarget | null   // medicine_switch: aguarda confirmação
  totalSteps: number
}
```

`null` = nada vence. Cobre os degenerados que o legado também ignorava: sem etapa `current`
(pausada), `current` sem `started_at` (**titulação dormente** — o dado real de prod), `current`
contínua (`duration_days` NULL = alvo atingido), duração inválida.

### Leitura (F2 — assinaturas gêmeas das legadas)

```ts
resolveTitrationStageAtFromSteps(steps, at)   → {stageIndex, dosage} | null
calculateTitrationDataFromSteps(steps, now?)  → {...} | null
getTitrationSource()                          → 'n1' | 'n2'   // env TITRATION_SOURCE, default 'n1'
```

### Escrita (SQL — `confirm_titration_switch(p_step_id uuid) → jsonb`)

`{success, already_confirmed?, transition?, step_id, protocol_activated?, protocol_paused?}` ou
`{success:false, reason:'nao_pendente'|'step_obsoleto'|'nao_autenticado'}`.

## Invariantes do contrato (quebrar = bug clínico)

1. **As etapas são INJETADAS e vêm FILTRADAS por `protocol_id = protocol.id`.** O walk-forward
   soma durações; com a escada inteira, um caso cross-medicamento adotaria a dose de OUTRO
   medicamento para as instâncias do executor vigente. Filtradas: intra-med migrada = paridade
   exata com o N1; cross-med para na etapa do protocolo (que é o comportamento desejado enquanto
   o switch aguarda confirmação). O filtro é ESTRUTURAL: embed `titration_steps(...)` via FK.
2. **O motor NUNCA troca de medicamento sozinho.** `medicine_switch` só marca a PRÓXIMA etapa como
   `pending_confirmation`; a vigente permanece `current` e segue regendo a dose (Decisões §3.2/§10).
3. **Assinaturas legadas intactas** (`resolveTitrationStageAt`/`calculateTitrationData`): o cutover
   é a troca da FONTE no chamador, não a reescrita dos call-sites. `titrationAdapter.test.ts` é o
   contrato de paridade N1↔N2.
4. **Idempotência por ESTADO, não por token** (AP-221): o claim (`WHERE status=...`) é a exclusão
   mútua; retry/double-tap caem em `already_confirmed`, nunca duplicam protocol/evento.
5. **Fronteira N2→N1 de unidade**: `NULLIF(intake_unit,'cp')` ao escrever em `protocols` (AP-299).

## Consumidores

| Consumidor | Como recebe as etapas |
