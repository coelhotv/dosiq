# CON-032 — Motor da Evolução do tratamento (titulação N2)

**Status**: accepted · **Spec**: 029 (Slices F3 + F3.1) · **ADR**: ADR-080 · **Criado**: 2026-07-16
**Atualizado**: 2026-07-17 (F3.1 — demolição do andaime N1; ver §F3.1 no fim)
**Adiado do F2** (o serviço nasceu aqui, no slice do motor).

## Superfície pública (`@dosiq/core`)

### Decisão (pura, nível A strict, clock-free)

```ts
resolveTitrationAdvance(
  steps: TitrationStepEngineLike[] | null | undefined,
  todayLocal: string,          // 'YYYY-MM-DD' no fuso do DONO (getTodayLocal(tz))
  tz?: string                  // IANA; fallback 'America/Sao_Paulo' (R-254)
): TitrationAdvancePlan | null

interface TitrationAdvancePlan {
  transition: 'dose_change' | 'medicine_switch' | 'target_reached'
  completed: { id: string; endedAtIso: string }[]
  activated: TitrationStepTarget | null   // dose_change: nova vigente
  pending:   TitrationStepTarget | null   // medicine_switch: aguarda confirmação
  totalSteps: number
}
```

`null` = nada vence. Cobre os degenerados que o legado também ignorava: sem etapa `current`
(pausada), `current` sem `started_at` (**titulação dormente** — o dado real de prod), `current`
contínua (`duration_days` NULL = alvo atingido), duração inválida.

### Leitura (nomes canônicos desde o F3.1 — não existe variante N1)

```ts
resolveTitrationStageAt(steps, at)    → {stageIndex, dosage} | null   // dose vigente num instante
calculateTitrationData(steps, now?)   → {...} | null                  // progresso p/ exibição
```

⚰️ Removidas no F3.1: `getTitrationSource()` (a flag nunca foi lida em web/mobile — Vite troca
`process.env`→`{}`, Expo só inlina `EXPO_PUBLIC_*`; só o Node a via), as legadas
`resolveTitrationStageAt(protocol)`/`calculateTitrationData(protocol)`, o tipo `TitrationProtocol`,
o campo `stageNote` e `advanceTitrationStage()` (write-path N1 sem chamador — AP-301).
O sufixo `*FromSteps` morreu com a fonte dupla: **steps são a única fonte**.

### Escrita (SQL — `confirm_titration_switch(p_step_id uuid) → jsonb`)

`{success, already_confirmed?, transition?, step_id, protocol_activated?, protocol_paused?}` ou
`{success:false, reason:'nao_pendente'|'step_obsoleto'|'nao_autenticado'}`.

## Invariantes do contrato (quebrar = bug clínico)

1. **As etapas são INJETADAS e vêm FILTRADAS por `protocol_id = protocol.id`.** O walk-forward
   soma durações; com a escada inteira, um caso cross-medicamento adotaria a dose de OUTRO
   medicamento para as instâncias do executor vigente. Filtradas: intra-med migrada = paridade
   exata com o N1; cross-med para na etapa do protocolo (que é o comportamento desejado enquanto
   o switch aguarda confirmação). O filtro é ESTRUTURAL: embed `titration_steps(...)` via FK.
2. **O motor NUNCA troca de medicamento sozinho.** `medicine_switch` só marca a PRÓXIMA etapa como
   `pending_confirmation`; a vigente permanece `current` e segue regendo a dose (Decisões §3.2/§10).
3. **O estado zumbi é IRREPRESENTÁVEL.** CHECK `titration_steps_current_exige_started_check`:
   `status <> 'current' OR started_at IS NOT NULL` — vale em INSERT **e** UPDATE (verificado no
   preflight, 8/8). Todo caminho que ativa uma escada SETA o relógio; o banco recusa o resto.
   Corolário que NÃO é invariante: escada **sem** etapa `current` é estado legítimo (alvo atingido
   e pausada) — não virou trava, senão quebraria o §2 e o F4 não conseguiria honrá-la.
   *(Substituiu o invariante de paridade N1↔N2, revogado no pivô: `titrationAdapter.test.ts` media
   paridade com um cadáver — AP-301.)*
4. **Idempotência por ESTADO, não por token** (AP-221): o claim (`WHERE status=...`) é a exclusão
   mútua; retry/double-tap caem em `already_confirmed`, nunca duplicam protocol/evento.
5. **Fronteira N2→N1 de unidade**: `NULLIF(intake_unit,'cp')` ao escrever em `protocols` (AP-299).

## 🔄 Pivô da 029 (2026-07-16) — o que mudou neste contrato

A 029 deixou de ser **migração** e virou **construção**: a titulação N1 nunca funcionou em produção
em 6 meses (**AP-301**), a feature tinha **zero usuários** e o dado foi apagado.

**O núcleo deste contrato sobrevive inteiro** — inclusive porque o desenho já era o certo:

| Caso do produto (escopo novo) | Transição derivada (ADR-080) |
|---|---|
| **same-med** — só muda a quantidade de comprimidos, mesma dosagem | `dose_change` (automático) |
| **multi-med** — a dosagem muda ⇒ outro medicamento (injetável ou não) | `medicine_switch` (confirmação) |

O tipo é **derivado comparando `medicine_id`** entre etapas adjacentes — nunca um campo/toggle. Isso
já era verdade no F3; o pivô só deu nome de produto ao que o modelo fazia.

**Morreu**: invariante 3 (paridade), `getTitrationSource`, a flag, `migrated_from_protocol_id`.
**Nasceu**: o CHECK anti-zumbi como invariante do contrato (a escada só é "vigente" se o relógio
começou).


## 🔨 F3.1 (2026-07-17) — a demolição do andaime

O F3 entregou o motor com um andaime de migração em volta (flag `TITRATION_SOURCE`, dual-read,
funções legadas, `migrated_from_protocol_id`, suíte de paridade). O pivô provou que o andaime
segurava um prédio que nunca existiu. O F3.1 removeu tudo — **o núcleo do contrato não mudou**;
mudou o que estava em volta.

| Antes | Depois |
|---|---|
| duas fontes (jsonb N1 / steps N2) + flag | **fonte única**: `titration_steps` |
| `*FromSteps` ao lado das legadas | nomes canônicos, sem variante |
| paridade N1↔N2 como contrato | **CHECK anti-zumbi** como contrato (§3) |
| web escreve titulação (Wizard + "Status Manual") | **web read-only**; a escada nasce no app (F4) |

**A leitura web continua** (badge/timeline/PDF de consulta), agora sobre o N2 — o
`consultationDataService` lê `protocol.titration_steps` do embed que já vinha no select.

> ✅ **Decisão do PO (2026-07-17), fechada:** a **web MANTÉM a leitura** da escada. Razão: *"é o
> mínimo de consistência que precisamos entre o estado mobile x web"*. A web escreve nada (freeze
> do F3.1) e lê tudo — um tratamento em evolução tem que se parecer com um tratamento em evolução
> nas duas superfícies. O F6/T033b **reponta** `TitrationBadge`/`TitrationTimeline`/`TitrationStep`
> e o `titrationService.ts` web para o N2 (não deleta). Não reabrir a pergunta.

**`stageNote` não existe no N2** e é decisão de PRODUTO, não coluna faltando: a etapa se descreve
por medicamento+dose (Decisões §2). `titration_steps` **não tem** `description` — conferido no banco.
Quem for "resolver" isso somando o campo a um select reproduz o #749 (AP-300/R-295).
