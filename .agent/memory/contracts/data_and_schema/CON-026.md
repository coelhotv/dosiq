# CON-026 — `createDoseLogService` factory interface no core

## Assinatura da Factory

```javascript
import { createDoseLogService } from '@dosiq/core'

const doseLogService = createDoseLogService({
  client,      // Cliente Supabase
  getUserId,   // Função async () => string (resolve user_id)
})
```

## Métodos do Serviço

### 1. `registerDose(logData, options = {})`

Registra uma tomada de dose **atômica no banco** (RPC `register_dose_atomic`).

- **Parâmetros**:
  - `logData`: `{ medicine_id: string, protocol_id: string|null, taken_at: string, quantity_taken: number, notes?: string|null }`
  - `options`: `{ instanceId?: string|null }` (ID da ocorrência materializada a ancorar)
- **Retorno**: `Promise<MedicineLog>` (com `dose_instance_id` resolvido se ancorado)
- **Validação**: valida `logData` com `logSchema`; resolve snap (`findAnchorInstance`) quando não há `instanceId`.
- **Atomicidade**: insert + `consume_stock_fifo` + marcação da ocorrência numa única transação; falta de estoque ⇒ banco reverte tudo (sem log órfão — AP-231 eliminada).
- **Ancoragem**: `instanceId` explícito = **estrito** (ocorrência inelegível/double-click aborta a transação); snap = **best-effort** (log persiste avulso se não marcar).

### 2. `undoDose(instanceId)`

Desfaz o registro de uma dose ancorada a uma ocorrência.

- **Parâmetros**:
  - `instanceId`: `string` (UUID da dose_instance)
- **Retorno**: `Promise<{ success: boolean }>`
- **Comportamento**:
  - Busca a ocorrência (repo) para obter `medicine_log_id`.
  - Com log: delega à RPC `delete_dose_log_atomic` (estorno + revert da ocorrência + delete numa transação).
  - Sem log (estado anômalo): apenas reverte o status via `revertToUnregistered`.
  - Status pós-undo (`pending`/`missed`) usa a tolerância da própria ocorrência, fallback `DEFAULT_TOLERANCE_MINUTES` (120).

### 3. `updateOrphanLog(logId, updates)`

Atualiza um log avulso (PRN/orphan) reajustando o estoque.

- **Parâmetros**:
  - `logId`: `string`
  - `updates`: `{ taken_at?: string, quantity_taken?: number, medicine_id?: string, notes?: string|null }`
- **Retorno**: `Promise<MedicineLog>` (log atualizado)
- **Comportamento**:
  - Delega à RPC `update_dose_log_atomic`. Campos não informados (`null`) preservam o valor antigo (COALESCE no banco).
  - Se quantidade ou medicamento mudarem: estorno + update + reconsumo numa única transação; falha de estoque ⇒ banco reverte a atualização inteira.

### 4. `deleteOrphanLog(logId)`

Exclui um log devolvendo o estoque ao inventário (RPC `delete_dose_log_atomic`).

- **Parâmetros**:
  - `logId`: `string`
- **Retorno**: `Promise<{ success: boolean }>`
- **Comportamento**:
  - Estorno (`restore_stock_for_log`) + revert da ocorrência ancorada + delete do log, tudo na mesma transação.
  - Revert da ocorrência usa a tolerância da própria linha, fallback `DEFAULT_TOLERANCE_MINUTES`.

### 5. `registerDoseMany(logsData)`

Registro em lote. Cada dose é uma transação atômica **isolada** (`register_dose_atomic`): a falha de uma não reverte as demais (Edge Case #2). Ancoragem em lote é best-effort.

- **Retorno**: `Promise<Array<{ id, instanceId, success, data?, error? }>>` — `instanceId` ecoado em cada item desacopla side-effects (ex.: cancelamento de alarme) de índice posicional.
