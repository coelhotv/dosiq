# CON-030 — Dose Activity Surface (Android)

Superfície de estado contínuo da dose no Android (Spec 039 / F2). Promove o spike
`devDoseActivitySpike` a produção. Renderiza UMA dose como ongoing notification "companheira"
consumindo [[CON-029]] (`selectActiveDoseActivity`). A máquina de estados vive no core; esta
camada só APRESENTA. F3 (iOS Live Activity) espelha o mesmo contrato.

## Forma

`apps/mobile/src/platform/doseActivity/`
```js
// doseActivitySurfaceService.js
showDoseActivity(activity, { now?, discreet?, doseItem? }) -> Promise<void>  // exibe/atualiza/encerra
showDoseDone({ instanceId, medicineLabel?, takenAt?, doseItem? }) -> Promise<void> // card 'done' (3min)
readSurfaceLabel(instanceId) -> Promise<string|null>  // nome da superfície ATIVA (auto-gate do done)
endDoseActivity(instanceId) -> Promise<void>                                 // cancel-on-resolve
ensureSurfaceChannel() -> Promise<void>                                      // canal DEFAULT idempotente
DOSE_ACTIVITY_CHANNEL_ID = 'dose-activity-v1'   // canal próprio, separado dos de alarme
LATE_CHRONO_CAP_MINUTES = 120                    // CL-3 / T021a
DONE_CARD_TIMEOUT_MS = 3 * 60 * 1000             // auto-dismiss do card 'done'
SURFACE_ACTION = { REGISTER, SNOOZE }            // ids estáveis (R-222)

// DoseActivityBridge.jsx — monta no AppRoot; deriva a dose ativa e exibe/encerra.
// SEM toggle próprio: gate = userId + dose critical_alarm pendente (extensão do alarme crítico).
```

## Invariantes (atualizado pós-smoke F2 — 2026-06-28; ver spec §9.7)

- **Canal DEFAULT silencioso e separado** (`dose-activity-v1`) — NUNCA tocar nos canais de alarme
  (`dose-alarm-v3`/`-critical-v2`, [[R-261]]). Sem som / sem loop / sem full-screen.
- **id da notificação = `${doseInstanceId}:surface`** (id PRÓPRIO via `surfaceId()`): coexiste com o
  alarme (id=`doseInstanceId`) no T0 sem sobrescrever o trigger dele — Notifee só admite **1 trigger
  pendente por id**; ids iguais fariam a superfície matar o alarme fullscreen no T0 (bug smoke). `endDoseActivity`/
  cancel usam `surfaceId(instanceId)` (cancel-on-resolve [[AP-235]] / PO-2.2).
- **"Registrar" ABRE a modal bulk** (decisão PO smoke): `handleAlarmAction` detecta `SURFACE_ACTION.REGISTER`
  e navega via `navigationRef` p/ deeplink (`bulk-plan` se `treatmentId`, senão `dose-individual`) — o
  botão usa `launchActivity:'default'`. Motivo: sítio de aplicação do injetável só é selecionável na
  modal. **"Adiar"** segue soneca canônica (`SURFACE_TO_ALARM_ACTION` = só SNOOZE). Handler de
  background lazy-require ([[AP-205]]); press do CORPO (sem launch) não navega ([[AP-207]]).
- **SEM toggle** (CL-4, decisão PO): superfície é extensão do alarme crítico. Gate = `userId` + dose
  `critical_alarm` pendente. (A invariante antiga "toggle opt-in default OFF / CL-2" foi REVOGADA.)
- **Sem filtro de lead-time no bridge** (revisto): quem decide a elegibilidade é a state factory do core
  ([[CON-029]]) — `d ≥ 240min` → `null` (sem superfície). Bridge busca janela `[now−3d, now+3d]`
  (lookback p/ `late`/`now` vencidas; `missed` é podada por `selectActiveDoseActivity`).
- **TRIGGER-DRIVEN** (re-trabalho pós-smoke — US2.1 exige transição com app FECHADA): as transições
  de estado são agendadas como **triggers nativos** (`Notifee TimestampTrigger` + `alarmManager.allowWhileIdle`
  → fura Doze) e ENCADEADAS — `armDoseActivity` exibe o estado atual + agenda o PRÓXIMO boundary;
  na entrega (`onBackgroundEvent`/`onForegroundEvent` DELIVERED) `advanceDoseActivity` agenda o seguinte.
  Boundaries vêm de `doseActivityBoundaryTimes` ([[CON-029]]) + cap do `late`. O modelo flip-timer
  (`setTimeout` foreground) foi APOSENTADO (só transicionava em foreground). Validado no spike DEV.
- **Countdown**: crono regressivo (`direction:'down'`) em `upcoming`/`now`. Como o Chronometer nativo
  não para no zero, o boundary **T0 re-exibe "agora" ESTÁTICO** (trigger no horário exato) → para o
  countdown antes do negativo, com a app fechada.
- **Marca-passo do alarme** (fix race do T0): o `fullScreenAction` do alarme traz a app a foreground no
  T0 e a race pode dropar o DELIVERED do boundary `:surface` → cadeia trava. `reconcileDoseActivityFromAlarm`
  re-arma a superfície a cada entrega/ação do alarme (bg+fg) — alarme é o marca-passo confiável que
  mantém a máquina viva atravessando T0 e a soneca (PR #691). Coexiste por id próprio (`:surface`).
- **CL-3:** `late` mostra count-up só ≤ `LATE_CHRONO_CAP_MINUTES`; acima → `showChronometer:false`
  + corpo estático via `daysAgoLabel` (semanal/GLP-1).
- **Estado `done`** (spec.md:366): card verde "Tomada às HH:mm ✓", `ongoing:false`, auto-dismiss
  `DONE_CARD_TIMEOUT_MS` (3min — spec pedia 3s, ilegível). Disparo em **fonte única**: o choke point
  `doseService._cancelAlarmBestEffort` via `readSurfaceLabel` (auto-gate: só doses que TINHAM superfície,
  via `__surface:'true'`), capturado ANTES do `cancelAlarm` (que apaga a notif pelo mesmo id). Cobre
  todos os caminhos de registro (modal, in-app, alarme). `registerTaken` NÃO chama `showDoseDone`
  direto — duplicava IPC + flicker (PR #691 / Gemini #901). `formatClock` extrai HH:mm do `Date` +
  zero-pad (NÃO `Intl.DateTimeFormat` — ICU limitado no Hermes, [[AP-218]]; PR #691 #898).
- **`missed`** é terminal → encerra a superfície (não ocupa ongoing).
- **Modo discreto** (PO-SEC-1): `discreet` → `android.visibility=PRIVATE` (SO redige no bloqueio);
  nome real SEMPRE no conteúdo. Título=`nome · dose` via `formatDoseItem` (R-272); corpo=`estado · HH:mm`.
