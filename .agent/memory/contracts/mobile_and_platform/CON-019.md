# [CON-019] dispatchNotification Interface

## Purpose
Centralized gate for all domain notifications. Enforces suppression policies (Quiet Hours, Modes), normalizes payloads, and logs deliveries for Inbox persistence.

## Interface (Zod)
```javascript
const dispatchInputSchema = z.object({
  userId: z.string().min(1),
  kind: kindSchema, // From buildNotificationPayload.js
  channels: z.array(z.string()).default([]),
})
```

## Input Arguments
- `userId`: Target user ID.
- `kind`: Notification type (must be in `kindSchema` enum).
- `payload`: (Optional) Pre-built payload `{ title, body, pushBody, metadata }`.
- `data`: (Optional) Raw data to build payload if `payload` is missing.
- `channels`: Explicit list of channels or empty (uses `resolveChannelsForUser` if empty).
- `context`: `{ correlationId, ... }`.

## Delivery Policy
- **Realtime Alarms** (`dose_reminder`, `stock_alert`): Suppressed by `Quiet Hours` and non-realtime modes.
- **Reports/Digest** (`adherence_report`, `daily_digest`): Bypass Quiet Hours; suppressed ONLY by `silent` mode.

## Implementation
Location: `server/notifications/dispatcher/dispatchNotification.js`
Usage: Preferred way to send any notification in the project to ensure RLS and Inbox compliance.
