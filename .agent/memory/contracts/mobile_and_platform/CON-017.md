## Contract

**Function:** `resolveChannelsForUser({ userId, repositories })`

**Input:**
- `userId` (string, uuid): ID do usuário Supabase
- `repositories` (object): Dependency injection com:
  - `repositories.preferences.getByUserId(userId)` → preferência
  - `repositories.preferences.hasTelegramChat(userId)` → boolean
  - `repositories.devices.listActiveByUser(userId, provider)` → array de devices

**Output:**
- Array of strings: `[]`, `['telegram']`, `['mobile_push']`, `['web_push']`, ou combinações entre esses canais.

## Decision Logic

### Legacy preference mode

Enquanto `notification_preference` existir como compatibilidade, a decisão legada continua válida para `telegram` e `mobile_push`.

| Preferência | Telegram? | Expo devices? | Resultado |
|-------------|-----------|---------------|-----------|
| none | T/F | T/F | `[]` |
| telegram | T | T/F | `['telegram']` |
| telegram | F | T/F | `[]` |
| mobile_push | T/F | T | `['mobile_push']` |
| mobile_push | T/F | F | `[]` |
| both | T | T | `['telegram', 'mobile_push']` |
| both | T | F | `['telegram']` |
| both | F | T | `['mobile_push']` |
| both | F | F | `[]` |

### Explicit channel flags (Wave N2+)

Quando `user_settings` possuir flags explícitas, elas são a fonte de verdade:

| Flag | Disponibilidade exigida | Canal retornado |
|------|-------------------------|-----------------|
| `channel_mobile_push_enabled === true` | Device ativo com `provider = 'expo'` | `mobile_push` |
| `channel_web_push_enabled === true` | Device ativo com `provider = 'webpush'` | `web_push` |
| `channel_telegram_enabled === true` | `telegram_chat_id` ativo | `telegram` |

`web_push` nunca deve ser inferido apenas pela existência de subscription. A flag explícita e o device ativo precisam coexistir.

## Usage (Sprint 6.2+)

```js
// Em dispatcher ou job (após Sprint 6.2)
const channels = await resolveChannelsForUser({ userId, repositories })
if (channels.length === 0) {
  return { success: true, delivered: 0, failed: 0 } // nenhum canal ativo
}
const result = await dispatchNotification({ userId, channels, ... })
```

## Acceptance Criteria

- ✅ Retorna sempre array (nunca null/undefined)
- ✅ Responde em <50ms (repositories já cacheados)
- ✅ Suporta 4 valores de preferência validados por CHECK constraint durante a compatibilidade legada
- ✅ Suporta flags explícitas para App, Web (PWA) e Telegram
- ✅ Testes: matriz de preferência legada + flags explícitas × disponibilidade de devices
- ✅ Used by: dispatchNotification (Sprint 6.2), jobs (Sprint 6.4)
