# CON-029 — DoseActivityState API

Núcleo da máquina de estados de dose em `@dosiq/core` (`utils/doseActivityState.js`).
Fonte ÚNICA das superfícies contínuas (iOS Live Activity / Dynamic Island, Android
ongoing notification). Puro, server-free, aditivo a [[CON-024]] (`classifyDose` inalterado).

## Forma

```js
deriveDoseActivityState(item, now = getRawNow(), opts = {}) -> DoseActivityState | null
selectActiveDoseActivity(items, now = getRawNow(), opts = {}) -> (DoseActivityState & {groupSize}) | null
DOSE_ACTIVITY_STATES = { UPCOMING, NOW, LATE, DONE, MISSED }  // 'upcoming'|'now'|'late'|'done'|'missed'
```

`item` aceita DoseItem (camelCase, saída de `buildDoseItemsFromInstances`) OU dose_instance
crua (snake_case). `now` aceita `Date` OU ISO string (paridade `splitDayTimeline`); inválido →
`getRawNow()`. `opts` = `{ lateWindowMinutes, nowWindowMinutes, upcomingWindowMinutes }`
(override de teste; default das janelas de `classifyDose`).

### DoseActivityState (efêmero, não persistido)
```
state, instanceId, treatmentId, scheduledFor, remainingSeconds, isCritical,
isRegistered, medicineLabel
```
`remainingSeconds` negativo p/ atrasada (base do count-up); positivo p/ próxima (countdown).

## Invariantes

- **Dois `null` distintos:** instante inválido/ausente → `null` (sem superfície); instante
  válido pós-tolerância → `'missed'` (terminal). Nunca confundir.
- **`later` colapsa em `upcoming`** (superfície de 1 dose não distingue).
- **`selectActiveDoseActivity` retorna SEMPRE ≤1 superfície** (FR-002): prioridade
  `atrasada > crítica > now > próxima`, empate → menor `remainingSeconds`. `done`/`missed`
  não competem.
- **Agrupamento por `treatment_plan`** (espírito [[R-191]]): `groupSize` = nº de doses
  actionáveis do plano vencedor; avulsas (`treatmentId null`) não agrupam entre si (groupSize 1).
  `partitionDoses` vive no bot (server-side) — core NÃO importa; reimplementa o agrupamento.
- **Puro / tz-safe:** sem `new Date('...')`; `now` inválido → `getRawNow()` (R-020).

## Consumidores

- F2 (Android): serviço de superfície Notifee consome `selectActiveDoseActivity`.
- F3 (iOS): bridge Live Activity consome o mesmo core (paridade).
