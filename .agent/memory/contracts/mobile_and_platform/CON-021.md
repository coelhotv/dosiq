# [CON-021] Notification Metadata Schema Resilience

## Objetivo
Garantir que os consumidores de notificações (Mobile/Web) consigam interpretar corretamente os IDs de protocolo independentemente da convenção de nomenclatura (snake_case vs camelCase) enviada pelo backend ou dispatcher.

## Contrato de Dados
O campo `data` (ou `metadata`) de uma notificação DEVE conter pelo menos um dos seguintes formatos para identificação de protocolos:

### Identificador Único
- `protocol_id`: string (UUID) - Padrão Banco de Dados / L1.
- `protocolId`: string (UUID) - Padrão Dispatcher / L2.

### Múltiplos Identificadores
- `protocol_ids`: string[] (UUIDs) - Padrão Banco de Dados / L1.
- `protocolIds`: string[] (UUIDs) - Padrão Dispatcher / L2.

## Regra de Consumo
Consumidores DEVEM implementar a lógica de fallback:
`const id = metadata.protocol_id || metadata.protocolId;`
