# AP-347 — Gate em shell reprova SEM DIZER POR QUÊ (`grep` sem casamento sob `set -e`)

## O padrão

`grep` devolve **exit 1 quando não casa nada** — que não é erro, é resposta. Sob `set -e` (ou
`set -euo pipefail`), esse 1 derruba o script **na hora e sem imprimir nada**. O operador vê um
gate que reprovou, com as verificações anteriores impressas em verde e **nenhuma linha dizendo o
que falhou**.

```bash
# ERRADO — some sem mensagem quando um arquivo legitimamente não tem a linha
qr_data() { grep '^|' | grep -vE '^\| *DO *\|'; }
for f in "${ARQUIVOS[@]}"; do extract qr "$f" | qr_data >> "$SAIDA"; done

# CERTO — "não casou" é um resultado válido, não uma falha do gate
qr_data() { grep '^|' || true; }
qr_rows() { qr_data | { grep -vE '^\| *DO *\|' || true; }; }
```

## Por que é grave num GATE, e não só chato

Um gate existe para responder **passou / não passou E por quê**. Quando ele morre calado, os dois
diagnósticos possíveis ficam **indistinguíveis**: "o artefato está errado" e "o verificador tem um
bug". A tentação imediata é acreditar no gate e ir mexer no artefato — que estava certo. É a
mesma família do [[AP-325]] pelo lado espelhado: lá o gate **passa** sem ter executado; aqui ele
**reprova** sem ter avaliado.

Agrava porque o caso que dispara é o **legítimo**: o arquivo que não tem a linha porque *não devia
ter*. No incidente de origem, 3 das 7 skills não recebem nenhuma linha do Quick Reference — o
comportamento correto — e foi exatamente isso que matou o verificador.

## Sintoma que identifica

Script com `set -e` que termina com **exit ≠ 0 e stdout que para no meio**, sem nenhuma linha de
erro. Se a última coisa impressa foi um "OK" de etapa anterior, suspeite do `grep` (ou de `[ ]`,
`let`, `expr`, `diff` — todos devolvem ≠ 0 como *resposta*, não como falha).

## Prevenção

- Todo `grep` cujo "zero casamentos" é resultado esperado ganha `|| true` — e o `|| true` fica
  **dentro** do bloco `{ ... }` quando está no meio de um pipeline;
- todo caminho de reprovação do gate imprime a causa **antes** de sair (`fail() { echo ... >&2; exit 1; }`);
- teste o gate com a entrada degenerada (arquivo vazio, lista sem casamento) — não só com o caso feliz;
- `set -o pipefail` torna isto **mais** provável, não menos: o 1 do `grep` no meio do pipe passa a
  derrubar o pipe inteiro.
