# AP-348 — O parâmetro redireciona a leitura e não a verificação

## Sintoma

Um verificador aceita um parâmetro que troca **o que ele lê** (`--file`, `--repo`, `--root`, uma env
var) mas mantém **o que ele confere** amarrado a uma constante — a raiz derivada do `__dirname`, um
caminho relativo fixo, um `origin/main` hardcoded. O comando sai **0**, imprime a mensagem de
sucesso, e a checagem que ele diz ter feito foi feita **noutro alvo**.

É a família do [[AP-325]] (gate que reporta sucesso de operação que não ocorreu) com uma agravante:
aqui a operação ocorreu de verdade — só que no arquivo errado. Não há sintoma nenhum para ver.

## Como apareceu (078/Slice 5, `scripts/attempts.mjs`, 2026-09-05)

Duas instâncias no MESMO arquivo, em uma sessão:

1. `REPO_ROOT` vinha de `path.resolve(__dirname, '..')`. Com `--file` apontando para um repo
   temporário, o script lia aquele ledger e cobrava os **reverts do dosiq**. Pior: dois testes
   **passaram pelo motivo errado** — o dosiq tem 2 reverts antigos não registrados, e eram eles que
   faziam a asserção `exit == 1` fechar. Teste verde sobre mecanismo inexistente.
2. Corrigido o item 1, a checagem de monotonicidade ainda montava `git show ${BASE_REF}:${LEDGER_REL}`
   com o caminho **constante**, e não com o arquivo realmente lido.

Um terceiro efeito, específico do macOS, escondeu a correção por mais uma rodada: `git rev-parse
--show-toplevel` devolve o caminho **resolvido** (`/private/tmp/...`) e o argumento chegava como
`/tmp/...`, então `path.relative` produzia `../../..` e a checagem virava **skip silencioso** —
falha degradando para "não conferido", que é o pior default possível.

## Regra

- Todo parâmetro que redireciona a leitura redireciona **também** a verificação: derive o alvo
  conferido **do artefato realmente lido**, nunca de uma constante paralela.
- Raiz de repo sai do **diretório de trabalho** (`git rev-parse --show-toplevel`), não do caminho do
  script — o script é uma ferramenta, o repo é o objeto.
- Normalize os dois lados com `realpathSync` antes de qualquer `path.relative` (symlink de `/tmp` no
  macOS), e trate arquivo inexistente **explicitamente**, sem deixar exceção virar skip.
- **Um teste de gate tem que falhar pela razão certa**: escreva o caso negativo num repo temporário
  **vazio de história**, para que a asserção não possa fechar por lixo do repo hospedeiro. Se o teste
  passa igual com o mecanismo desligado, ele não testou o mecanismo (é o mesmo guard da PO-25 desta
  spec: contra-prova, não só prova).

## Detecção

`grep -n "__dirname" scripts/*.mjs` em ferramenta que aceite `--file/--repo/--root`: cada
ocorrência é candidata. E rodar o gate **de dentro de outro repositório** — se ele passa, está
conferindo o repo errado.
