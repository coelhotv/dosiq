# AP-316 — Gate mecânico não cobre `xcodebuild` real

## O que aconteceu
PR 1.1 da spec 055 (bump Expo SDK 53→54) fechou todos os gates prescritos —
`expo-doctor` 18/18, `tsc --noEmit` 0 erros, `lint` 0 erros, `jest` mobile 61/61 — e RC5/RC6
não acusaram nada. Nenhum deles compila código nativo. Só quando o PO rodou
`npx expo run:ios`/EAS build de verdade, localmente, é que apareceu: `@react-native-firebase`
v21 quebra sob o toolchain mais estrito do Xcode 26/RN 0.81 em DUAS classes de erro —
(1) include não-modular de headers React em módulo de framework
(`-Werror,-Wnon-modular-include-in-framework-module`, mitigável via `CLANG_ALLOW_NON_MODULAR_INCLUDES_IN_FRAMEWORK_MODULES=YES`
nos Pods) e (2) macro `RCT_EXPORT_METHOD` do submódulo `analytics` virando `-Wimplicit-int`
fatal (não mitigável sem suprimir warning de C real — a raiz é o pacote v21 desatualizado).
Android não foi afetado — build local rodou limpo, o que fez o gap não ficar óbvio.

## Por que nenhum gate pegou
- `expo-doctor` valida metadata/versões declaradas, não compila nada.
- `tsc`/`lint` cobrem TypeScript/JS — Objective-C/Swift/CocoaPods estão fora do escopo.
- `jest` roda em JS puro (Metro/Babel), nunca passa por `xcodebuild`.
- RC5/RC6 leem diff + arquivos — não executam build.
- CocoaPods (`pod install`/`xcodebuild`) só falha ao compilar de verdade, e isso normalmente só
  acontece em `eas build` (CI, custa tempo real de fila) ou num build local manual — nenhum dos
  dois é gate automático de PR.

## Fix aplicado (parcial)
Achado 1 mitigado via config plugin novo (`withFirebasePodfileFix.js`, `withDangerousMod` no
Podfile — `ios/` é efêmero, edição direta não sobrevive ao prebuild). Achado 2 registrado como
débito: bump de `@react-native-firebase` para versão compatível vira item obrigatório de um PR
seguinte da mesma spec (decisão do PO — não suprimir warning de C às cegas, resolver a causa raiz).

## Regra
Bump de SDK nativo (Expo/RN/qualquer coisa que gera `ios/`+`android/` via prebuild) **exige um
build real como gate**, não só typecheck/lint/expo-doctor — pelo menos `npx expo run:ios` E
`npx expo run:android` localmente (ou `eas build --profile preview` se local não for viável)
ANTES de declarar o PR pronto para RC5. As duas plataformas podem divergir (aconteceu aqui:
Android limpo, iOS quebrado) — testar as duas, nunca extrapolar de uma pra outra.

Ver [[AP-251]] (Android: gate cego a asset nativo ausente — mesma família, plataforma oposta).
