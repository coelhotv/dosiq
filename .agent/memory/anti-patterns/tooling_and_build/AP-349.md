# AP-349 — Gate de frescor com hash de mtime

## O padrão

Um artefato derivado (índice compilado, cache, bundle de metadados) ganha gate de frescor que
compara um `sourceHash` calculado sobre `caminho:mtimeMs:tamanho` das fontes. Parece barato e
correto: mudou a fonte, mudou o hash.

Mas **`mtime` não é propriedade do conteúdo, é do checkout**. `git checkout`, `git merge`, `git
clone` e `git stash pop` reescrevem o mtime de arquivos cujo conteúdo não mudou uma vírgula. O gate
então reprova sobre um artefato **idêntico** ao que deveria estar lá.

O dano não é a reprovação — é a **erosão**: um gate que grita em toda operação rotineira de git
ensina a sessão a recompilar no reflexo, sem ler, e a próxima reprovação — a legítima — recebe o
mesmo reflexo. Alarme falso rotineiro é treinamento para ignorar o alarme.

## Como apareceu (078/Slice 5, 2026-09-06)

Logo após o squash-merge do PR #826, `node scripts/compile-memory-index.mjs --check` saiu **1**
("índice desatualizado: recompile") com a árvore de trabalho **limpa**. Recompilado, o diff do
artefato foi **só o campo `meta.generatedAt`**: mesmas 575 regras, byte a byte
(`só antes: [] | só depois: [] | mudaram: 0`). Nenhuma fonte havia mudado — o merge apenas
reescreveu mtimes.

O gate está certo no espírito (R-289: a fonte moveu, o derivado não) e errado no **sinal** que usa.

## Regra

- Hash de frescor se calcula sobre **CONTEÚDO** (`sha256` do texto das fontes, ordenado), nunca
  sobre metadado de sistema de arquivos.
- Se o custo de ler as fontes for proibitivo, mtime pode ser **filtro rápido**, jamais veredicto:
  mtime diferente ⇒ leia e compare conteúdo antes de reprovar.
- Um artefato derivado que carrega timestamp de geração (`generatedAt`) não pode ter esse campo
  dentro do que se compara — ele muda sozinho e torna todo diff não-vazio.

## Detecção

`grep -n "mtimeMs\|statSync" scripts/*.mjs` em qualquer script com `--check`. E o teste decisivo:
`git checkout HEAD~1 && git checkout -` e rodar o gate — se ele reprovar, o hash é de mtime.
