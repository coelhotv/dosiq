# AP-312 — Cast que parece desleixo mas é contorno de resolução: "limpar" quebra o gate

**Status:** active · **Layer:** warm · **Domain:** tooling_and_build
**Criado:** 2026-07-20 (RC6 do PR #763) · **trigger_count:** 1

## Sintoma

Um `import * as X` seguido de `X as any` parece dívida óbvia — o tipo de coisa que revisor
(humano ou IA) marca como "silencia o type checker, troque por import nomeado". A troca é
tecnicamente superior **e quebra o build**:

```ts
// o que parece certo — e falha
import { ChevronRight } from 'lucide-react-native'
// error TS2305: Module '"lucide-react-native"' has no exported member 'ChevronRight'
```

`ChevronRight` obviamente existe. O erro não é sobre o símbolo.

## Causa

Dependência **peer não hoisted**, num monorepo com resolução assimétrica:

- `lucide-react-native` → `/node_modules` (raiz, hoisted)
- `react-native-svg` → `apps/mobile/node_modules` (não hoisted)

O `.d.ts` do lucide abre com `import { SvgProps } from 'react-native-svg'`. O tsc resolve esse
import **a partir da localização do .d.ts** (raiz), sobe a árvore, não acha. O módulo inteiro
degrada para "sem exports" — e **todo** símbolo passa a "não existir", não só o que você tocou.

O cast não estava escondendo um typo. Estava contornando um módulo cujos tipos não resolvem.

## Por que engana

1. **O sintoma aponta para o lugar errado.** A mensagem fala do símbolo; a causa é do peer.
   Um nome válido e um nome inventado produzem erro idêntico.
2. **O gate certo pega, o gate errado não.** `lint`, `jest` e `tsc` do programa da app passam —
   quem acusa é o check **cross-program** (`strict-island.sh`). Quem valida só com a suíte
   comemora a "limpeza" e quebra o CI.
3. **É indistinguível de dívida real.** Não há como saber pela linha se aquele `as any` é preguiça
   ou contorno. A diferença mora no layout de `node_modules`, três diretórios acima.

## Regra

1. **Cast sem justificativa escrita é dívida; cast COM causa raiz documentada é decisão.** Ao
   contornar resolução, o comentário registra: o que quebra, por quê, e o que foi verificado.
   Sem isso, o próximo a passar "limpa" e quebra o build — e paga o custo de rediagnosticar.
2. **Antes de remover um cast em import de biblioteca**, rodar o gate cross-program — não só a
   suíte local. Se o símbolo "não existe" mas você sabe que existe, suspeite do **peer**, não do nome.
3. **Revisor que propõe trocar cast por import nomeado precisa provar que o módulo resolve.**
   A sugestão é correta em princípio e pode ser inaplicável no layout concreto.

## Caso concreto (PR #763)

O RC6 marcou como **critical** que `CircleQuestionMark` não existiria em `lucide-react-native`,
mandando trocar por `CircleHelp`/`HelpCircle`. Verificado em `dist/icons.d.ts` (1703 ícones):
`CircleQuestionMark` **é** o nome atual; `CircleHelp` e `HelpCircle` **não existem** nesta versão
(são os nomes históricos, renomeados upstream). O fix proposto causaria o crash que ele descrevia.

O risco de fundo, porém, era legítimo, e a tentativa de corrigi-lo com import nomeado foi o que
revelou a causa raiz acima. Resultado: cast mantido, causa documentada no arquivo, nomes conferidos
contra o `.d.ts` do pacote.

**Correção estrutural** (não feita — fora do escopo de um fix de UI): hoistar `react-native-svg`
para a raiz ou mapear `paths` no `apps/mobile/tsconfig.json`. Mexe em layout de dependências e
merece entrega própria.
