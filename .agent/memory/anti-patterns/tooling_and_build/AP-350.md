# AP-350 — Gate de monorepo com runner único no glob

## O padrão

Hook de commit (ou job de CI) escreve o glob pela FORMA do caminho — `apps/*/src/**/*.ts` — e
pendura nele **um** runner. Num monorepo onde os workspaces usam runners diferentes (vitest na web,
jest no mobile; pytest e go test; rspec e jest), o glob varre workspace que o runner não sabe rodar.

O resultado não é "cobertura menor". É **falha dura na superfície inteira**: no dosiq, o
`vitest related` recebia arquivos de `apps/mobile` e morria ao parsear `react-native/index.js`
(sintaxe Flow: `import typeof`), então **todo commit que tocasse `apps/mobile/src` era revertido pelo
pre-commit**, com um erro que não tem nenhuma relação com o diff de quem estava commitando.

## Por que passa despercebido

O gate não estava mentindo — estava **inalcançável**. Ninguém tinha commitado produto naquele
workspace desde que o hook voltou a rodar de verdade (o próprio `.lintstagedrc.mjs` registra que ele
passou anos carregando `module.exports` num repo ESM, isto é, sem nunca executar). Cinco semanas de
trabalho de ferramental depois — todo ele na web e em `scripts/` — a primeira tentativa de entregar
código mobile bateu no muro.

⇒ **Gate novo (ou reativado) só está verificado nas superfícies que alguém exercitou depois da
mudança.** As outras estão num estado desconhecido que se parece com "funciona".

## Detecção

```bash
# 1. quais workspaces o glob alcança vs qual runner o comando invoca
grep -rn "apps/\*\|packages/\*" .lintstagedrc.* .github/workflows/*.yml
# 2. o runner de cada workspace (podem divergir)
for f in apps/*/package.json packages/*/package.json; do
  echo "$f: $(python3 -c "import json,sys;print(json.load(open('$f')).get('scripts',{}).get('test','-'))")"
done
```
Divergência entre (1) e (2) = este AP.

## Antídoto

Um glob por runner, nomeando o workspace — nunca `apps/*`:

```js
"{apps/web/src,server,api}/**/*.{js,jsx,ts,tsx}": ["vitest related --run --passWithNoTests"],
"apps/mobile/src/**/*.{js,jsx,ts,tsx}": (files) =>
  [`npm test --workspace @dosiq/mobile -- --findRelatedTests ${files.join(' ')} --passWithNoTests`],
```

E **provar nas duas direções**, senão troca-se um gate quebrado por um falso verde (AP-325): que ele
executa (contagem de testes > 0) e que ele barra (assertion invertida de propósito → commit
recusado). Medido no PR #829: 8 suítes / 97 testes na direção positiva; `[FAILED] … pre-commit
script failed` na negativa.

## Origem
