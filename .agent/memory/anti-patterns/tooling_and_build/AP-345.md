# AP-345 — Wrapper de shell que otimiza tokens TRUNCA a saída, e o comando vira amostra sem avisar

**Categoria**: tooling_and_build · **Severidade**: alta · **Detectado**: 2026-09-03 (spec 078 Slice 0, PR #818)

## O que aconteceu

O ambiente roda todo comando de shell através do `rtk`, cujo trabalho **é** cortar saída para
economizar token. Isso é correto quando o humano/agente **lê** o resultado. É destrutivo quando o
mesmo comando é a **fonte de dados** de uma medição:

```bash
git log --oneline | wc -l          #   50   ← saída já truncada pelo rtk
rtk proxy git log --oneline | wc -l  # 2276   ← a real
```

O `wc -l` conta as linhas que o `rtk` deixou passar, não as que o `git` produziu. Se o minerador
de corpus da 078 tivesse chamado `git log` pela shell, o corpus nasceria **~20× menor**, com
`exit 0`, JSON bem-formado e um número plausível — e toda conclusão sobre `recall@k` seria tirada
de uma amostra arbitrária de 50 commits. Nenhum gate pega: não há erro, não há warning, o formato
está certo.

## Por que é a mesma família de [[AP-186]] e [[AP-329]]

As três são **truncamento sem sinal**: o PostgREST corta em ~1000 linhas (AP-186), o `>` zera o
arquivo antes de o gerador existir (AP-329), o wrapper de token corta a saída (aqui). O que muda é
**quem** corta: no AP-186 é o servidor, no AP-329 é o shell, aqui é uma camada *instalada de
propósito para cortar* — o que a torna a mais fácil de esquecer, porque cortar é o comportamento
correto dela.

## Antídoto

- Comando cuja saída **alimenta código** (contagem, corpus, parsing, laço): chamar o binário
  direto, sem passar pelo wrapper — em Node, `execFileSync('git', [...])`; em shell, `rtk proxy`.
- **Farol:** `| wc -l`, `| head`, `$(...)` ou `for x in $(cmd)` sobre um comando que o wrapper
  otimiza (`git log`, `grep`, `find`, `ls`, `diff`). Se o número alimenta uma decisão, conferir
  contra `rtk proxy` **uma vez** antes de confiar.
- Canário barato: comparar o total pela via otimizada e pela via crua. Divergência ⇒ está lendo
  amostra. Foi exatamente assim que apareceu (50 vs 2276).
