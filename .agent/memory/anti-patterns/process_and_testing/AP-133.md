# AP-133: Sub-agente Commitando Direto na Main sem PR

## Context
Lint waves E e F foram executadas por sub-agentes com permissão implícita para commitar código. Os sub-agentes fizeram commits diretamente na `main` sem branch de feature, sem PR, sem review do Gemini e sem aprovação humana.

## Anti-Pattern
Sub-agente recebe tarefa de refatoração (lint, cleanup, wave) → implementa → commita direto na `main` sem passar por branch + PR + review.

## Consequências
- Regressões de layout em produção (dashboard, breakpoints, tablet/mobile)
- Logout broken (Workbox blocking Supabase signOut)
- AdminSection nunca renderizando (campo inexistente usado para detecção)
- Uma sessão inteira gasta para reparar os danos
- Usuário perdeu budget de tokens da semana

## Correct Approach
Todo sub-agente deve:
1. Criar branch de feature (`refactor/wave-X/nome`)
2. Implementar mudanças
3. Rodar gate de validação
4. Reportar resultado ao agente principal
5. **Parar** — aguardar aprovação humana para abrir PR
6. Jamais auto-merge (R-060)

## Prompt Obrigatório para Sub-agentes
Incluir explicitamente: "NÃO commite direto na main. Crie branch, implemente, reporte gate — aguarde aprovação humana."

1 (lint-waves-E-F, 2026-W19)
