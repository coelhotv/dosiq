# AP-297 — Slice vai a PR sem RC5 (self-review pré-PR) → revisor externo vira o 1º revisor

**Layer:** hot · **Domain:** process_and_testing · **Trigger count:** 1 (F2 #747) · **Origem:** 029 F2

## Sintoma

Volume alto e recorrente de comentários do revisor externo (Gemini) por PR — 8 a 11 findings,
a maioria **mecânica**: `afterEach` ausente num teste Vitest **apesar de o CLAUDE.md já exigir**,
JSDoc que diz "retorna null em X" mas o código não retorna, guard SQL faltando, ergonomia de
query. O padrão se repete PR após PR (ver a assinatura "pego só por revisor externo" em
[[AP-266]], [[AP-276]], [[AP-285]]).

## Causa-raiz

O workflow pulou o **RC5 / pre-landing self-review** (DEVFLOW R1) e foi direto
`C4 → commit → gh pr create → aguardar Gemini`. Sem o self-review, o revisor externo assume o
papel de **primeiro** revisor — e devolve exatamente a classe de coisa que o RC5 Pass 1 +
fix-first pegaria de graça, **com o contexto ainda quente** (o agente que escreveu o código tem
o modelo mental completo; o revisor externo parte de cold-start). O custo some não porque o
código ficou pior, mas porque a ordem de revisão está invertida.

Dois vetores concretos no F2:
1. **Regra da casa não aplicada a si mesma:** CLAUDE.md §Testes exige
   `afterEach(() => { vi.clearAllMocks(); vi.clearAllTimers() })` em todo teste com `vi.fn/mock`.
   O teste novo nasceu sem. Uma regra documentada só protege se houver um passo que a verifica
   ANTES do PR.
2. **JSDoc é contrato, mas não foi verificado no C4:** o comentário de
   `calculateTitrationDataFromSteps` prometia "retorna null quando não há etapa vigente FINITA";
   o código seguia com `totalDays=0` (progresso 0%, `daysRemaining` negativo). O C4 file-by-file
   confere que a mudança EXISTE, mas não confere doc↔comportamento.

## Guard

- **Rodar RC5 antes de `gh pr create`** em todo slice Tier 1+ (`/devflow code-review` standalone
  serve). Findings AUTO-FIX (afterEach, dead code, guard óbvio, doc↔código) são resolvidos ANTES
  do PR; o revisor externo vira a **segunda** rede, não a primeira.
- Checklist mínimo do RC5 para este projeto, além do Pass 1 CRITICAL:
  - teste novo com `vi.fn/mock` tem `afterEach(clearAllMocks/clearAllTimers)`? (CLAUDE.md)
  - todo JSDoc que afirma um retorno/condição bate com o código? (ler a função, não só o call site)
  - migração/SQL passou pela tabela de failure-modes do [[R-270]] (incl. gotchas Postgres)?
- **Métrica de saúde:** se um PR volta com >2 findings mecânicos que uma regra existente já cobre,
  é sinal de RC5 pulado — não de revisor zeloso.
