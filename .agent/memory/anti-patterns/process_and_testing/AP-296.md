# AP-296 — Feature espelhada web↔mobile com trava presente só de um lado (defesa em profundidade assimétrica)

**Domínio:** process_and_testing (família do "verde ilusório" — [[AP-289]]/[[AP-290]]/[[AP-291]])
**Detectado:** spec 046 Slice B, re-review Gemini do PR #745 (não pelos nossos testes)

## Sintoma

Numa feature entregue em paralelo para web e mobile (o gate de consentimento LGPD), duas travas de
**defesa em profundidade** existiam no mobile e **faltavam no web** — e nada falhava:

1. **Guard de consentimento no `signUp`.** `authService.signUpWithEmail` (mobile) tinha
   `if (options.healthConsent !== true) throw` — a conta não nasce sem opt-in nem por caller fora do
   form. O `signUp` web (`supabase.ts`) **não** tinha o guard: gravava `health_consent:
   options.healthConsent === true` e criava a conta de qualquer jeito.
2. **`gate.refresh()` após revogar.** O card mobile (`PrivacyConsentSection`) chamava
   `gate.refresh()` no sucesso do revoke → trava o app na hora. O card web fazia `await load()` e
   **não** reavaliava o guard raiz → o app seguia navegável até o próximo ciclo de foreground.

Nenhum teste pegou: **o gate de UI web** (form bloqueado, navegação gated) **mascarava a ausência
da trava de serviço** e do re-lock imediato. Pior: os testes do lado web **codificavam o
comportamento incompleto** (o teste do revoke não afirmava `gate.refresh`, então a ausência passava
por "comportamento esperado"). Só a re-revisão de branch inteira do revisor de IA — que compara os
dois lados sem a premissa de que já estavam pareados — levantou os dois gaps como HIGH.

## Causa

Feature "espelhada" tratada como duas entregas independentes, sem um diff superfície-a-superfície
entre as plataformas. A trava extra de um lado (belt beyond the UI gate) é invisível pelo teste do
outro lado porque **a UI passando esconde a falta do cinto**: o form web bloqueado e a navegação
gated fazem o fluxo feliz funcionar, então o serviço desprotegido e o re-lock ausente não geram
erro nem vermelho.

## Correção

- `signUp` web ganhou o mesmo guard `throw` (paridade com o mobile) — commit 11aa07c5.
- `PrivacyConsentSection` web ganhou `useConsentGate()` + `gate.refresh()` no revoke + try/catch/finally,
  e um teste que **afirma** `gate.refresh` chamado 1x no sucesso.

## Regra / Farol

- Feature entregue em paralelo web↔mobile: **diff as duas implementações superfície-a-superfície**.
  Uma trava (guard/refresh/teardown) presente num lado é **item de checklist** para o outro —
  especialmente defesa em profundidade (a trava ALÉM do gate de UI).
- **Farol:** "o mobile tem uma trava a mais que o web (ou vice-versa) na mesma feature espelhada" ·
  "o teste do lado faltante afirma o comportamento incompleto como se fosse o esperado".
- O gate de UI passar **não prova** que a trava de serviço existe — testar a trava no NÍVEL dela
  (o serviço/o refresh), não pelo fluxo de UI que a contorna. Irmão de [[AP-291]]/[[AP-294]]
  (lá o verde codifica a omissão; aqui codifica a assimetria de plataforma).
