# AP-139 — Redundant Null Check in Initialized Metrics

## O que é?
Adicionar verificações defensivas para valores que nunca serão nulos/undefined devido à garantia do contrato (Schema Zod com `.default()`) ou inicialização de métricas (ex: `comparison: { prev: 0, current: 0 }`).

## Por que é um problema?
1. **Ruído Visual**: O código fica mais longo e difícil de ler com `if`s desnecessários.
2. **Confusão de Contrato**: Sugere para futuros desenvolvedores que o valor *pode* ser nulo, levando a mais código defensivo em cascata.
3. **Pessimização Prematura**: Embora o custo de CPU seja ínfimo, o custo cognitivo é alto.

## Como evitar?
Confie nos schemas Zod. Se um campo é obrigatório ou tem default, use-o diretamente. Se a métrica é inicializada em um objeto de estado, não verifique sua existência antes de usá-la.

**ERRADO (Verificação redundante):**
```javascript
const stats = { total: 0, count: 0 };
// ...
if (stats && stats.total > 0) { // Stats nunca é nulo aqui
  const avg = stats.count / stats.total;
}
```

**CERTO:**
```javascript
const stats = { total: 0, count: 0 };
// ...
if (stats.total > 0) {
  const avg = stats.count / stats.total;
}
```
