# AP-289 — Suite de teste que NÃO CARREGA é cobertura zero silenciosa (gate verde que não executa)

**Categoria**: process_and_testing
**Layer**: hot
**Status**: active
**Origem**: 044 F5 (2026-07-13) — dívida herdada, achada por acaso na F4b
**Relacionados**: [AP-263](../infra_and_deploy/AP-263.md) (imports extensionless), [R-282](../../rules/infra_and_deploy/R-282.md) (extensão `.js` obrigatória em Node ESM puro)

## O problema

`npm test --workspace @dosiq/mobile` reportava **325 testes passando, 0 falhando** — verde.
Mas **8 suites não carregavam**:

```
Cannot find module './contracts.js' from '../../packages/config/src/index.ts'
```

Isso **não é um teste vermelho — é uma falha de CARGA**. O Jest não conta uma suite que
não conseguiu importar: ela simplesmente não aparece no total. As 8 suites incluíam
`TodayScreen`, `StockScreen`, `alarmService`, `buildConfirmLogs`, `buildBulkOutcome`,
`useMedicineDatabase` e `supabase.smoke` — telas e serviços de primeira linha, com
**cobertura silenciosamente ZERO**. O gate seguia verde enquanto protegia menos do que anunciava.

Pior que um gate vermelho: um vermelho GRITA. Este mentia por omissão, e o número absoluto
(325) parecia saudável demais para levantar suspeita.

## A causa

O `moduleNameMapper` do `jest.config.js` do mobile mapeava os aliases (`@dosiq/core`, `@shared/…`)
mas **não** o import relativo com extensão `.js` que o **R-282 EXIGE** dentro de `packages/`
(Node ESM puro: `./contracts.js` em runtime aponta pro `.ts` em compile). Vite/Metro resolvem;
o Jest, não. Mesma classe do AP-263 — a extensão do R-282 quebrando um resolver que não a entende.

## O fix (1 linha)

```js
moduleNameMapper: {
  '^(\\.{1,2}/.*)\\.js$': '$1',   // ANTES dos aliases
  '^@/(.*)$': '<rootDir>/src/$1',
  // …
}
```

Resultado: 325 → **384 testes**, 46 suites, **zero vermelho novo**. O medo de "ligar as suites vai
acender vermelhos apagados há tempo" não se materializou — mas era um medo legítimo, e a decisão
de encarar (em vez de adiar) foi barata justamente porque foi tomada de olhos abertos.

## Como evitar

**Um gate de teste tem DUAS asserções, não uma:**
1. `failed == 0` (a que todo mundo checa)
2. **`suites_carregadas == suites_no_disco`** (a que ninguém checa)

Ao mexer em resolver (`moduleNameMapper`, `transformIgnorePatterns`, `paths`, `exports`) ou ao
introduzir uma convenção de import nova (foi o que o R-282 fez): **comparar a contagem de suites
antes/depois**. Um delta negativo silencioso é o sintoma.

Regra prática: **desconfie do número absoluto de testes.** Se ele nunca é conferido contra
`ls **/__tests__/*` , ele pode cair 20% sem que ninguém veja.
