# AP-335 — Teste de código morto mantém o código morto vivo

**Severidade:** 🟠 alto (dívida que se disfarça de cobertura)
**Origem:** spec 064 · RC3-1 (2026-08-21) · limpeza no PR #807
**Família:** [[AP-290]] (gate que não mede o que promete) · [[AP-333]] (duas implementações do mesmo contrato)

## O que aconteceu

`apps/web/.../costAnalysisService.ts` tinha uma função `calculateDailyIntake` — **nome idêntico** ao
do core, sem conversão de líquido e sem `frequencyDailyFactor`. Sombra de anos, com **zero chamador
de produção**: o único importador era o próprio `__tests__/costAnalysisService.test.ts`.

Ela sobreviveu porque *parecia usada*: aparecia no grep, tinha testes verdes, e qualquer varredura
de "código não coberto" a dava como coberta. A suíte era o único consumidor — e por isso o único
motivo de ela continuar existindo.

## Por que é caro

Sombra com o nome do símbolo canônico é pior que duplicata anônima: quem lê o call site não
desconfia, e quem "consolida" um dia pode consolidar na direção errada. No 064, a existência dela
custou uma task de análise inteira só para provar que o custo real já usava o core.

## Farol

Antes de tratar uma função como viva, rodar o grep de chamadores e olhar **de onde** vêm:

```bash
rtk grep -rn "nomeDaFuncao" apps/ packages/ server/ | grep -v __tests__ | grep -v '\.test\.'
```

Zero linhas ⇒ o único consumidor é a suíte ⇒ **deletar a função E o `describe` dela**. Não
"deprecar": um `@deprecated` com teste verde continua parecendo vivo.

## Regra derivada

Teste não é consumidor. Cobertura de teste sobre símbolo sem chamador de produção é **cobertura de
nada** — mede a suíte, não o produto.
