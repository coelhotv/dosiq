## Anti-Pattern

Aplicar a sugestão de correção de um revisor automatizado (Gemini Code Assist, etc.) confiando na **causação afirmada por ele**, sem abrir e ler a definição do símbolo alterado. O fix compila, passa no lint e nos testes existentes — e mesmo assim **preserva (ou introduz) um bug**, porque a causa raiz afirmada pelo revisor estava errada.

```ts
// Revisor (Critical): "remover o 2º arg `true` de formatLocalDate causa o crash;
//                       mantenha-o para incluir o horário na string".
// Fix aplicado, confiando na causação:
const formatted = (formatLocalDate as any)(parseISO(takenAt), true)
return formatted.split(' ')[1].substring(0, 5)   // HH:mm
```

O revisor assumiu que `formatLocalDate(date, includeTime)` honra um 2º parâmetro. A definição real:

```ts
export function formatLocalDate(date) {            // 1 parâmetro só
  return `${year}-${month}-${day}`                 // "2026-07-06" — sem hora, sem espaço
}
```

Consequência: `"2026-07-06".split(' ')[1]` → `undefined` → `.substring()` → `TypeError`. O crash **independe** do `true` (o core sempre o ignorou). O fix apenas silenciou o compilador — e o `as any` escondeu justamente o `TS2554` que o modo strict deveria ter surfado.

## Exemplo Real (040 Fase 5, PR #721)

Migração TS de `apps/mobile`. Gemini marcou `DoseListItem._formatTakenTime` como Critical com causação errada. O agente de dev aplicou o fix sugerido e registrou no comentário "2º arg já era ignorado em runtime — mesmo resultado" — racionalizando um crash como "comportamento preservado". `tsc`/lint/37 testes verdes porque **nenhum teste renderiza uma dose tomada com `takenAt`** (o ramo `isTaken && takenAt` de `DoseListItem` L67 nunca é exercitado nos testes). Detectado pelo RC6 (revisão independente do DEVFLOW), que aplica *causation discipline* — ler o callee antes de atribuir causa.

## Sinais de alerta

- Fix de revisor que **muda a assinatura de uma chamada** (adiciona/remove argumento) sem que você tenha lido a assinatura real do callee.
- Comentário que justifica com "mesmo resultado" / "comportamento preservado" sem citar a linha que prova.
- `as any` / cast introduzido só para "satisfazer o compilador" numa fase cujo objetivo é *ganhar* cobertura de tipos.
- Suíte verde num caminho que os testes comprovadamente não cobrem.

## Solução Correta

1. Antes de aplicar qualquer fix que mexa numa chamada, **abrir e ler a definição do callee**; confirmar a causação com a linha que a prova.
2. Não usar `as any` para silenciar um erro de tipo que está apontando um bug real — o erro é o diagnóstico.
3. Se a suíte passa num caminho suspeito, **adicionar o teste que exercita esse caminho** antes de declarar o fix correto.

```ts
// ✅ Fix real (tz-aware, strict-clean, sem as any):
function _formatTakenTime(takenAt: string): string {
  const d = getUserTime(parseISO(takenAt))   // getHours()/getMinutes() no fuso do usuário
  return `${String(d.getHours()).padStart(2, '0')}:${String(d.getMinutes()).padStart(2, '0')}`
}
```
