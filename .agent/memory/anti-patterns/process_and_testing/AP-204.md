# AP-204 — Mock de hook que retorna função nova a cada chamada desestabiliza dep de useCallback → loop infinito no teste

## Categoria
process_and_testing

## Contexto
F4.3f.2 — teste do hook `useSettingsState` (Vitest + RTL `renderHook`). O hook consome
`useComplexityMode()` e usa `setOverride` na lista de dependências de `useCallback(fetchData)`,
que por sua vez é dep de um `useEffect`.

## Sintoma
`waitFor(() => expect(result.current.loading).toBe(false))` estoura timeout (10s) em **todos**
os testes do arquivo. stderr floda o **mesmo** nome de teste dezenas de vezes (sinal de
re-render em cascata). `loading` nunca assenta em `false` mesmo com o fetch mockado resolvendo.

## Causa
O mock retornava uma **referência nova** a cada render:
```js
vi.mock('@dashboard/hooks/useComplexityMode', () => ({
  useComplexityMode: () => ({ mode: 'simple', setOverride: vi.fn(), overrideMode: null }),
}))
```
`setOverride: vi.fn()` cria uma função nova a cada chamada → a dep de `useCallback(fetchData)`
muda a cada render → o `useEffect` que depende de `fetchData` re-dispara → novo render →
loop infinito. O componente real não sofre disso porque o hook real memoiza `setOverride`.

## Correção
Referência **estável** no mock — criar a função uma vez, fora do factory, e retornar sempre a mesma:
```js
const setOverrideStable = vi.fn()
vi.mock('@dashboard/hooks/useComplexityMode', () => ({
  useComplexityMode: () => ({ mode: 'simple', setOverride: setOverrideStable, overrideMode: null }),
}))
```

## Regra
Mock de hook cujo retorno alimenta dep de `useMemo`/`useCallback`/`useEffect` do consumidor
DEVE retornar **referências estáveis** (funções/objetos criados uma vez), não literais recriados
a cada chamada. Sintoma diagnóstico: stderr repetindo o mesmo teste N vezes = re-render em loop.

## Relacionados
- Regra de hooks: memoização de callbacks expostos por hooks compartilhados.
