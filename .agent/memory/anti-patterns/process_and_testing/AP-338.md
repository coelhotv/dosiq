# AP-338 — Gate de EXISTÊNCIA implementado como gate de PROGRESSO some justamente para quem concluiu

**Categoria:** process_and_testing · **Severidade:** 🔴 · **Origem:** 073 PR 1 (Slice G / F-24), 2026-08-22

## O sintoma

O PDF de consulta da conta de teste — 4 tratamentos, 12 degraus de titulação no banco — saía com
**zero menção à titulação**. A seção existia, o gate existia (`if (titrationRows.length > 0)`), o
código estava correto na leitura do gate. A escada simplesmente nunca chegava lá.

## A causa

`calculateTitrationData` devolve `null` **de propósito** quando a etapa vigente é CONTÍNUA (dose de
manutenção, sem duração): o contrato dela é PROGRESSO, e manutenção não tem progresso. O extrator a
montante fazia `if (!titrationData) return null`, ou seja, **usava a ausência de progresso como
ausência de escada**.

O resultado inverte a intenção clínica: a seção aparece enquanto o paciente está subindo a escada e
**desaparece no momento em que ele chega à dose alvo** — exatamente o estado que o médico precisa
ver para decidir manter, subir ou recuar.

## Por que passou por tudo

- O gate do renderizador estava **certo** — quem revisa lê `length > 0` e marca como correto.
- Nenhum teste cobria "etapa vigente sem duração": os fixtures tinham degrau com `duration_days`.
- Ausência não gera erro. Uma seção que some não deixa log, não quebra layout, não falha asserção.
- A função de cálculo também estava certa: o defeito não estava em nenhuma das duas pontas, e sim
  na **tradução entre elas**.

## A regra

Quando um gate de EXISTÊNCIA (“tem escada?”, “tem histórico?”, “tem plano?”) é alimentado por um
cálculo de ESTADO (“qual o progresso?”, “quanto falta?”), o `null` do cálculo não é resposta para a
pergunta do gate. Perguntas diferentes exigem predicados diferentes:

- não altere a função de estado para “devolver algo” no caso concluído — o contrato dela está certo,
  e afrouxá-lo contamina todos os outros consumidores (aqui: CON-032);
- corrija o **tradutor** (o extrator), que é quem conhece as duas perguntas;
- teste o **caso concluído** como caso de primeira classe, não só o em-andamento e o vazio. O trio é
  `vazio | em andamento | concluído` — o terceiro é o que some em silêncio.

**Farol:** `if (!calculo) return null` dentro de um extrator que alimenta uma seção de UI · função de
progresso documentada como “retorna null quando não há X a exibir” consumida por quem decide se a
seção EXISTE · feature que “funciona” para quem começou e some para quem terminou.
