# AP-245 — Roteamento editar-vs-registrar dose por `isOrphan` em vez de presença de log

**Domínio:** react_and_ui
**Detectado em:** smoke mobile pós-688 (PR #688, hotfix)

## Sintoma
Editar uma dose agendada **já tomada** no histórico mobile (ex.: alterar o sítio de aplicação de um
injetável) falha com `P0001 "Ocorrência já registrada ou indisponível"`. Doses órfãs (avulsas/PRN)
editam normalmente; só as agendadas tomadas quebram.

## Causa
`DoseActionSheet.handleSaveEdit` roteava a edição apenas por `isOrphan` (`source === 'log'`):

```js
if (isOrphan) { onUpdateLog?.(logId, payload) }
else { onRegisterRetro?.({ ...payload, medicine_id, protocol_id }, instanceId) }
```

Dose agendada tomada **não é órfã** → caía no `else` → `registerRetro` → `register_dose_atomic`
(INSERT). A RPC rejeita re-registro de uma ocorrência já registrada (guard de double-click, P0001).
O sintoma confunde porque o caminho "errado" (registrar) é o default de toda dose não-órfã, mas só
explode quando a ocorrência já tem log.

## Fix
Rotear pela **presença de `logId`** (log de apoio), não pela origem. Toda dose tomada — órfã OU
agendada — carrega `logId` (`medicine_log_id`, via `timelineService.instanceToEvent`):

```js
if (logId) { onUpdateLog?.(logId, payload) }        // tem log → UPDATE atômico (update_dose_log_atomic)
else { onRegisterRetro?.({ ...payload, medicine_id, protocol_id }, instanceId) } // sem log (pending/missed) → registro retroativo
```

## Regra-mãe
Editar ≠ registrar. A decisão de UPDATE vs INSERT de uma dose deve checar se **já existe log de apoio**
(`logId`), nunca a origem da instância (`isOrphan`/`source`). `register_dose_atomic` é insert-only e
rejeita duplicata por design — usá-lo para editar uma ocorrência já tomada sempre bate em P0001.
