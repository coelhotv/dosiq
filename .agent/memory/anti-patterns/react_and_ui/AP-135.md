# AP-135: user_metadata.role para Detecção de Admin (Campo Inexistente)

## Context
Sub-agente implementou detecção de admin usando `user.user_metadata?.role === 'admin'`. Este campo não existe no schema do Dosiq — `user_settings` não tem coluna `role` e o Supabase Auth não está configurado com custom claims de role.

## Anti-Pattern
```js
// ❌ ERRADO — campo não existe neste projeto
const isAdmin = user?.user_metadata?.role === 'admin'
setIsAdmin(isAdmin) // sempre false → AdminSection nunca renderiza
```

## Consequências
- `isAdmin` sempre `false`
- AdminSection nunca renderiza na tela de Settings
- Links para DLQ invisíveis para o admin real
- Silencioso — sem erro no console

## Correct Approach
```js
// ✅ CORRETO — comparar com VITE_ADMIN_CHAT_ID
const adminChatId = import.meta.env.VITE_ADMIN_CHAT_ID
if (adminChatId && String(settings.telegram_chat_id) === String(adminChatId)) {
  setIsAdmin(true)
  const { count } = await supabase.from('dead_letter_queue')
    .select('*', { count: 'exact', head: true })
  setDlqCount(count || 0)
}
```

## Como Verificar
Ver `DATABASE.md` — tabela `user_settings` não tem coluna `role`. Admin = quem tem `telegram_chat_id` igual a `VITE_ADMIN_CHAT_ID`.

## Nota sobre R-202
R-202 diz "prefer metadata-based role checks" — essa regra é genérica e não se aplica ao Dosiq. Neste projeto, usar sempre o padrão acima baseado em `telegram_chat_id`.
