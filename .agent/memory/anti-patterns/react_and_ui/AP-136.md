# [AP-136] Wide useMemo Dependencies

**Symptom:** Unnecessary re-renders and performance degradation in components with heavy memoization logic.
**Domain:** `apps/web`, `apps/mobile`

## Problem
Passing a whole object (e.g., `dashboardData`) to a `useMemo` or `useCallback` dependency array instead of the specific primitive or nested properties actually used in the calculation.

## Why it's bad
- If any unrelated property in the object changes, the memoized value is discarded and recalculated.
- In Redux/Context environments, "wide" objects change reference frequently, defeating the purpose of memoization.

## Fix
Destructure only the required stable references or specific properties needed for the calculation.

### ❌ Bad
```javascript
const criticalItems = useMemo(() => {
  return filterCritical(dashboardData.items);
}, [dashboardData]); // Re-runs if dashboardData.user or dashboardData.settings changes
```

### ✅ Good
```javascript
const items = dashboardData?.items;
const criticalItems = useMemo(() => {
  return filterCritical(items);
}, [items]); // Only re-runs if items reference changes
```
