# AP-303 — Estado indeterminado de gate tratado como bloqueio (mata offline-first)

**Spec:** 046 (gate de consentimento LGPD) · **Plataforma:** mobile · **Severidade:** HIGH (app inacessível offline em produção)

## O furo

O guard raiz do mobile (`NavigationTree`, `Navigation.tsx`) recebia a decisão pura
`resolveConsentGate` — que classifica corretamente `indeterminate` como **`locked: false`**
(*"não conseguimos LER a trilha; não libera NEM bloqueia — é carregando/erro"*). Mas o guard
**ignorava** essa semântica e fazia um early-return de **tela de erro full-screen** (*"Não foi
possível verificar suas preferências de privacidade… tente de novo"*) sempre que
`consent.mode === 'indeterminate'`.

Resultado: sem rede (4G/3G instável é a norma no BR), a leitura da trilha falha → `state: null` →
`indeterminate` → **app inteiro travado**. Quebrou o **offline-first** — valor central do produto,
prometido nas landings web e mobile (navegar doses/estoque e registrar ações offline p/ sync
posterior). Passou batido pelo smoke porque o smoke roda online.

## Por que estava errado (inclusive juridicamente)

- LGPD trava **tratamento** de dado sensível (coleta/uso/transmissão/compartilhamento). Titular
  **ver o próprio dado já no device** (AsyncStorage) não é tratamento novo — é acesso do titular
  aos próprios dados (art. 18, **direito**, não risco). Ler cache local offline = zero transmissão,
  zero coleta, zero fato gerador de risco.
- A proteção legítima do 046 é contra **escrita** (materializar/ressuscitar consentimento REVOGADO
  numa oscilação de rede — furo HIGH do Slice A). Essa proteção mora na **leitura**
  (`getStatus()` lança → `state: null` → nada é escrito) — **não** em barrar a renderização.
  Renderizar offline não materializa consentimento algum → bloquear a UI dá **zero** benefício
  jurídico e só destrói UX.
- Confusão de conceito: `revoked` (fato conhecido → trava `blocked_revoked` continua correta) ≠
  `indeterminate` (desconhecido/offline). O agente foi conservador **na direção errada**: puniu o
  titular por uma falha de rede nossa.

## Fix

Remover o early-return de erro. Sob `indeterminate` o app **renderiza normalmente** (graça
offline). A trava real (`revoked → blocked`) é reaplicada quando a rede volta — o listener de
`AppState 'active'` já chama `refresh()` e reavalia o gate. A decisão pura já dizia o certo; o
conserto é fazer o guard **obedecer** o `locked: false`.

## Farol

- Guard de UI que **contradiz** a decisão pura que consome (`locked: false` mas bloqueia mesmo
  assim). Se a função pura já classificou "não bloqueia", o guard não pode inventar um bloqueio.
- Estado de **carregamento/erro** (`indeterminate`, `null`, `loading`) tratado como estado de
  **negação** num app com promessa offline-first. "Não sei" ≠ "não pode".
- Gate de conformidade que barra **leitura de dado local** achando que protege — proteção de
  consentimento é sobre **escrita/tratamento**, não sobre o titular ver o próprio dado.
- Sinal de smoke: só testado online → o caminho offline (o valor de produto) nunca exercitado.
