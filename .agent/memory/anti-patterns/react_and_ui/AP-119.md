# [AP-119] Redundant Derived State Synchronization

## Context
When a UI state is strictly dependent on another state or external data (like an account link or a settings object), keeping a separate `useState` for it and trying to synchronize it via `useEffect` creates "dual source of truth" bugs.

## Pattern
Creating a `useState` for a value that should be derived directly from props, another state, or a memoized calculation.

## Anti-pattern Example
### ❌ Incorrect
```javascript
const [telegramEnabled, setTelegramEnabled] = useState(false);
const isConnected = !!settings.telegram_id;

useEffect(() => {
  setTelegramEnabled(isConnected); // Redundant synchronization
}, [isConnected]);
```

### ✅ Correct
```javascript
const isConnected = !!settings.telegram_id;
// Use isConnected directly in the UI
```

## Rationale
- Simplifies the component logic.
- Eliminates race conditions between state updates and effect synchronization.
- Ensures the UI always reflects the actual source of truth.
