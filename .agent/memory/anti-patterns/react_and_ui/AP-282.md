# AP-282 — Erro de validação em campo que a tela não renderiza ("verifique os campos destacados" sem destaque)

**Categoria**: react_and_ui
**Detectado em**: 2026-07-12 (smoke da 044 — passo 2 do onboarding mobile, travado)
**Severidade**: alta (bloqueia o fluxo, sem pista para o usuário nem para o suporte)

## O que aconteceu

O auto-fill da busca ANVISA no onboarding gravava `regulatory_category` com o valor **cru** da
base (`Biologico`, `Gases Medicinais`); o enum do schema é acentuado e fechado
(`REGULATORY_CATEGORIES`). O `safeParse` reprovava em `regulatory_category` — campo que a tela
do onboarding **não renderiza**.

O handler mostrava "Verifique os campos destacados" e `validate()` marcava o campo como
`touched`... num input que não existe. O usuário via um toast pedindo para corrigir campos e
**nenhum campo destacado**. Fluxo morto.

`normalizeRegulatoryCategory` já existia e já era aplicada no cadastro de medicamento (mobile) e
nos dois fluxos ANVISA da web. O onboarding era o único ponto que ficou de fora — a correção foi
feita nos outros lugares e não varreu todos os consumidores.

## Regra

1. **Toda entrada de dado externo (base ANVISA, import, API) que alimenta um enum fechado passa
   pelo normalizador do enum.** Ao criar o normalizador, `grep` por TODOS os pontos que consomem
   a fonte — a correção parcial é a que volta.
2. **Toast de validação genérico ("verifique os campos destacados") só é honesto se houver campo
   destacado.** Quando o erro cai fora dos campos renderizados, mostrar a **mensagem real**. Um
   form que valida um schema maior que a própria tela DEVE saber quais campos ele exibe.

Farol: usuário travado num form dizendo "não tem nada marcado em vermelho" → o erro está num
campo invisível; não confie no relato de que "todos os campos estão preenchidos".
