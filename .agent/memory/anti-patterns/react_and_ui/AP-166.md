# AP-166 — `useFormState.validate()` race com `handleChange` assíncrono

**Sintoma**: Submit com coerce de campo (string → number) imediatamente antes de `validate()` pode falhar/passar com base em estado errado. Form aceita `"0,5"` no UI mas valida `"0,5"` literal em vez de `0.5` coerced.

**Root cause**: `useFormState.validate` é `useCallback` com `[schema, values]` deps. Quando submit faz `coerceDose(form)` → `form.handleChange('dose', num)` → `form.validate()` imediatamente, validate ainda lê `values` da frame anterior (closure capturada pelo callback antes do re-render). `handleChange` é assíncrono (queue setState); só a próxima frame tem o valor novo.

**Por que perigoso**: behavior intermitente — funciona em testes (Jest atomicidade) mas falha em interação real onde coerce e validate são back-to-back na mesma frame.

**Fix aplicado**: `useFormState.validate` agora aceita `overrides` opcional. Submit passa o valor coercido explicitamente:

```js
// useFormState.js
const validate = useCallback(
  (overrides) => {
    const candidate = overrides ? { ...values, ...overrides } : values
    const result = schema.safeParse(candidate)
    // ...
  },
  [schema, values],
)

// submit handler
const currentDose = coerceDose(form)  // dispara handleChange (assíncrono)
const ok = form.validate({ dosage_per_intake: currentDose })  // override sincrono
```

Backwards compatible (default `undefined`).

**Regra preventiva**: nunca confiar em `form.values[X]` imediatamente após `form.handleChange(X, ...)` na mesma frame. Sempre passar `overrides` no `validate()` ou na construção do payload.
