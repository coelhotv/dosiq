# [AP-172] Recalcular status de estoque manualmente em vez de `resolveStockStatus`

## Description
Derivar o status do badge de estoque com thresholds manuais por dias dentro do componente (ex: `if (badgeDays < 7) return 'CRITICAL' ...`) em vez de chamar o helper canônico `resolveStockStatus(qty, dailyConsumption)` de `@dosiq/core`.

## Why it's harmful
- **Divergência em edge cases**: o cálculo manual por `dias = saldo/consumo` trata "sem consumo" como `Infinity` → cai no bucket mais alto (HIGH). Um item com **saldo 0 e sem consumo ativo** aparecia como HIGH (deveria ser CRITICAL). O helper trata o caso (qty<=0 → critico) e ainda considera vencimento.
- **Drift web↔mobile**: a listagem usa o helper; o detalhe duplicando a lógica diverge da listagem para o mesmo medicamento.

## Correct Approach
Importar e usar `resolveStockStatus`; mapear o enum lowercase (`critico/baixo/normal/alto/vencido`) para o contrato do badge (UPPERCASE) num `statusMap`.

## Example
### ❌ Wrong
```javascript
const badgeStatus = useMemo(() => {
  if (badgeDays < 7) return 'CRITICAL'
  if (badgeDays < 14) return 'LOW'
  if (badgeDays < 30) return 'NORMAL'
  return 'HIGH'
}, [badgeDays])
```

### ✅ Right
```javascript
const badgeStatus = useMemo(() => {
  const status = resolveStockStatus(saldo, dailyConsumption)
  const map = { critico: 'CRITICAL', baixo: 'LOW', normal: 'NORMAL', alto: 'HIGH', vencido: 'CRITICAL' }
  return map[status] || 'NORMAL'
}, [saldo, dailyConsumption])
```
