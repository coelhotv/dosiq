# AP-285 — Opção destrutiva renderizada como botão de ação: selecionar É executar

**Layer**: warm · **Pack**: design-ui · **Criado**: 2026-07-12 (044 F4a, review #739)
**Relacionado**: [[R-233]] (sheets) · [[AP-283]] (escrita no passo errado do wizard)

## Sintoma

Um sheet/modal de decisão oferece opções como `<button onClick={acaoDestrutiva}>`. O usuário
"escolhe" a opção e a ação já aconteceu — sem confirmação, sem chance de reler a alternativa.
Pior quando o mesmo sheet existe nas duas plataformas e só UMA tem confirmação: a mesma decisão
passa a ter semânticas diferentes conforme a superfície.

## Causa

Renderizar a opção como affordance de AÇÃO em vez de SELEÇÃO. O componente natural para "escolha
entre A e B, depois confirme" é um radiogroup + botão de confirmação; um `<button>` que dispara
no clique colapsa os dois atos em um.

O erro é fácil de cometer quando a lista de opções é curta e cada opção "parece" um comando —
especialmente ao portar de uma plataforma para a outra, onde o mobile já tinha rádio + confirmar
e a web foi escrita direto com botões.

## Regra

Ação irreversível ou destrutiva (zerar saldo, apagar, arquivar, migrar) exige **dois atos
deliberados**: escolher, depois confirmar. Concretamente:

- opções = `role="radio"` dentro de `role="radiogroup"` (+ `aria-checked`, roving tabindex,
  navegação por setas com o **foco acompanhando a seleção** — sem isso o leitor de tela não
  anuncia a troca);
- execução = botão de confirmação separado;
- **paridade entre plataformas**: a mesma decisão tem o mesmo número de atos em web e mobile.

O estado da escolha deve **resetar a cada abertura** — a opção destrutiva de uma tentativa
anterior nunca pode voltar pré-marcada. Preferir MONTAGEM CONDICIONAL do modal (desmontar reseta)
a repor o estado via `useEffect` (que ainda dispara `react-hooks/set-state-in-effect`).

## Caso real

044 F4a (PR #739): no sheet de reconciliação (gap ≥30d), a web executava `resumeAndZero()` — que
ZERA o saldo de todos os medicamentos — no clique da própria opção "Começar do zero", enquanto o
mobile pedia rádio + "Ativar estoque". Pego pelo revisor externo (Gemini, HIGH). O mesmo PR já
tinha corrigido o reset da escolha no mobile; a web nasceu com o furo maior.
