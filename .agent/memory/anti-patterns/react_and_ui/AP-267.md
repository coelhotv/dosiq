# AP-267 — Cast `as any` em call statement-position sem `;` cria ASI hazard invisível ao tsc

**Domínio**: react_and_ui · **Descoberto**: 2026-07-06 (040 F5 lote 6, PR #722) · **Severidade**: média (crash de runtime)

## Sintoma

Migração TS nível B casta `navigation.navigate(ROUTES.X)` → `(navigation.navigate as any)(ROUTES.X)` para destravar rotas não tipadas. Quando a linha castada **começa um statement** logo após outra linha sem `;` terminador, o `(` líder faz o ASI (Automatic Semicolon Insertion) fundir as duas linhas:

```js
setMedicine(form.values)
;(navigation.navigate as any)(ROUTES.ONBOARDING_TREATMENT)   // correto

setMedicine(form.values)
(navigation.navigate as any)(ROUTES.ONBOARDING_TREATMENT)    // BUG: vira setMedicine(form.values)(navigation.navigate as any)(ROUTES...)
```

`setMedicine(...)` retorna `void`/`undefined` → chamar o resultado = `TypeError: ... is not a function` em runtime. Ocorreu 3× no lote (ChatEntryButton, OnboardingMedicineStep, profileService.test).

## Por que escapou

O alvo do cast é `any` (`navigation.navigate as any`), então `f()(any)(...)` é **callable** para o compilador → **tsc não emite TS2349**. Quando o callee anterior também é `any` (ex.: `setMedicine` de contexto não tipado), zero diagnóstico. Só um teste que exercita o handler OU smoke no device pega. Casos onde o alvo NÃO era `any` (ChatEntryButton: `lightTap()` seguido do cast) chegaram a emitir TS2349 — esses o tsc pegou; os `any→any` não.

## Regra de prevenção

1. Ao castar uma call que **abre statement** (posição de statement, não dentro de `=>`/`return`/`{`/`,`), prefixar com `;`: `;(x.navigate as any)(...)`.
2. Após aplicar cast de navigate em massa (perl/sed), grep por casts statement-position e conferir a linha anterior: `grep -rnB1 "^\s*(navigation\(Ref\)\?\.navigate as any)("` — linha anterior terminando em `)`/`]`/identificador sem `;` = hazard.
3. Rodar os testes dos handlers tocados (não só tsc) — `any` mascara ASI; jest do escopo é o gate real.
