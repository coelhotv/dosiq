# AP-192 — View da SPA reseta no refresh de token (refocus da aba)

**Status:** active (bug aberto) · **Layer:** warm · **Domain:** react_and_ui
**Descoberto:** 2026-05-30 (smoke F3.2c — usuário no HealthHistory, troca de janela e volta → PWA "dá refresh" e cai no dashboard "hoje")

## Sintoma
Estando em qualquer view ≠ dashboard (ex: HealthHistory), ao trocar de janela
(IDE) e voltar ao browser, o app navega de volta pro dashboard. UX frustrante.

## Causa (App.jsx:92-124)
```js
useEffect(() => {
  if (!session) return
  const path = window.location.pathname   // '/' ou '/today' na maioria do tempo
  ...
  else if (path === '/today' || path === '/') setCurrentView('dashboard')
}, [session])   // ← depende de session
```
- A navegação interna é **state-based** (`setCurrentView`), a URL **não muda** (fica `/`).
- Ao refocar a aba, o Supabase **renova o access token** → `onAuthStateChange` →
  `setSession(novo objeto)` → o effect re-dispara → lê `path === '/'` →
  `setCurrentView('dashboard')` → reseta a view.
- O token refresh (mesmo usuário) NÃO deveria re-rotear.

## Regra / Fix
- Effects de roteamento inicial devem rodar por **identidade do usuário**
  (`session?.user?.id`) ou um guard `didInitRef`, não por toda mudança de `session`.
- Idealmente: sincronizar a URL com a view interna (history.pushState por view) p/
  refresh/deep-link consistentes — mas o mínimo é não re-rotear em token refresh.

## Fix planejado
Fatia própria (pós-F3.2c). Gatear o effect a `session?.user?.id` (ou didInit) →
token refresh não reseta a view. Avaliar sync URL↔view como melhoria maior.
