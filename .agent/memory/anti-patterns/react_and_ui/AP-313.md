# AP-313 — Navegação que também invalidava cache: remover o desvio leva junto um efeito que ninguém escreveu

**Camada**: warm · **Status**: active · **Detectado**: 2026-07-20 (smoke do PO, 052 Slice C)
**Pack**: `react_and_ui` · **trigger_count**: 1

## Sintoma

Confirmar a etapa da titulação pelo banner gravava tudo certo no banco — protocolo mutado, etapas
vinculadas, estados corretos — e **o banner continuava na tela**. Sair para a lista e reabrir o
tratamento corrigia sozinho.

## Mecanismo

A escada é estado do `TitrationTimeline`, via `useTitrationTimeline(protocolId)`. Esse hook só
recarrega em dois gatilhos: **focus** (`useFocusEffect`) ou **mudança de `protocolId`**. O
`refresh()` chamado pelo handler `onStartPendingStep` é o do **protocolo** — outro estado, outro
componente.

Antes do Slice C, confirmar um `medicine_switch` fazia
`navigation.replace(PROTOCOL_DETAIL, { id: protocolActivated })`. Como o executor novo tinha id
diferente, o `protocolId` mudava → a timeline remontava → escada fresca. A invalidação acontecia,
mas **de carona**: nenhuma linha de código dizia "recarregue a escada depois de confirmar".

O Slice C fez a RPC mutar o executor vigente. Não há mais protocolo novo, logo não há para onde
navegar, e o `navigation.replace` foi removido com justificativa correta (a armadilha da janela
de 24h deixou de existir). O efeito não-escrito foi embora junto — invisível na revisão, porque
não estava escrito em lugar nenhum para ser lido.

## Por que gate nenhum pegou

- `tsc`/lint: nada quebrou, o código está correto isoladamente.
- Testes: o `.test.sql` provou a RPC (que estava certa); os testes JS cobriam serviços, não o fio
  entre dois componentes com estados independentes.
- RC5: revisei o diff da REMOÇÃO e concluí, corretamente, que a navegação era desnecessária. A
  pergunta que faltou não era "esta linha ainda é necessária?" e sim **"o que mais esta linha
  fazia?"**.

## Regra

**Antes de remover uma navegação, um remount, uma troca de `key` ou um reset de rota, liste o que
mais aquilo causava.** Remount é um invalidador de cache universal e silencioso: todo estado local
abaixo dele é descartado. Procure especificamente por hooks que carregam dados com dependência em
algo que a navegação mudava (`protocolId`, `key`, params de rota).

**A invalidação tem de ser explícita e dona do próprio estado**: quem detém a cache é quem a
invalida depois da ação que a muta — nunca a navegação, que é consequência de UX e pode sair a
qualquer momento por decisão de produto.

```tsx
// ❌ o refresh depende de a navegação continuar existindo
onStart={() => onStartPendingStep?.(id)}

// ✅ quem é dono da escada recarrega a escada, sem depender de rota
const handleStartStep = useCallback(async (stepId: string) => {
  await onStartPendingStep?.(stepId)
  await refresh()          // `refresh` do PRÓPRIO hook, não o do pai
}, [onStartPendingStep, refresh])
```

## Sinal de alerta específico

Bug que **"se conserta sozinho quando saio e volto"** é quase sempre este: existe um refresh-on-focus
mascarando a ausência de invalidação na ação. O focus é uma rede de segurança que transforma o
defeito em intermitente — e intermitente não vira relato de usuário, vira "achei que era lentidão".

## Teste que trava

`apps/mobile/src/features/treatments/__tests__/titrationTimelineRefresh.test.tsx` — mocka
`useFocusEffect` como no-op **de propósito**: com a rede de segurança desligada, qualquer refresh
só pode vir da ação. Assere a ORDEM (`confirmou` → `recarregou`), não só que ambos ocorreram.
Verificado vermelho sem a correção ([[R-300]]).
