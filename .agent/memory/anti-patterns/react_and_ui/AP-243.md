# AP-243 — `Fragment` como filho direto de `AnimatePresence` quebra a animação de `exit`

**Domínio:** react_and_ui
**Detectado em:** spec 015 Onda 3 (PR #687, review Gemini)

## Sintoma
Para silenciar o warning "two children with the same key ``" do `AnimatePresence`, envolvemos os
filhos condicionais (`overlay` + `ChatWindowDrawer`) num `<Fragment key="...">`. O warning some,
mas a animação de **saída** (`exit`) do drawer/overlay para de funcionar — o componente desmonta
seco ao fechar.

## Causa
`AnimatePresence` precisa enxergar **cada filho animado como um elemento keyed direto** (motion
component ou componente cujo root é motion). Ele rastreia esses filhos por `key` para **adiar a
desmontagem** enquanto a animação de `exit` roda. Um `Fragment` agrupa os filhos num único nó sem
key própria utilizável → o AnimatePresence não consegue rastrear/adiar → sem exit.

## Fix
Renderizar cada filho como bloco condicional **separado e keyed** dentro do `AnimatePresence`
(não Fragment). Keys distintas resolvem o warning de chave E preservam o exit:

```jsx
<AnimatePresence>
  {isOpen && <motion.div key="chat-overlay" exit={{ opacity: 0 }} ... />}
  {isOpen && <ChatWindowDrawer key="chat-drawer" ... />}  // root é motion.div
</AnimatePresence>
```

Componentes não-animados (ex.: `ConfirmDialog`) ficam **fora** do `AnimatePresence`.

## Regra-mãe
O warning de key e a quebra de exit têm a MESMA raiz: filhos do AnimatePresence devem ser elementos
keyed diretos. Resolver o warning com Fragment troca um problema visível por um silencioso.
