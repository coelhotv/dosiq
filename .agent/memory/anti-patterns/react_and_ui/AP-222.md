# AP-222 — useState inicial não rastreia prop mutável

## Problema

`useState(prop)` ou `useState(prop || defaultValue)` inicializa o state **apenas no mount**.
Se o componente permanece no DOM e recebe nova prop (ex: modal reutilizado para criar/editar),
o state fica congelado com o valor do primeiro render — form parece vazio ou com dados de outro registro.

```jsx
// ❌ BUG: nudge muda, formData não
export default function NudgeFormModal({ nudge }) {
  const [formData, setFormData] = useState(nudge || { title: '', ... })
  // ...
}

// Caller reutiliza a instância — modal não desmonta entre aberturas:
<NudgeFormModal nudge={selectedNudge} isOpen={isModalOpen} ... />
```

## Sintoma

- Form de edição abre em branco (ao abrir pela 1ª vez com nudge `null`, depois com um nudge real)
- Form mostra dados do registro anterior (ao alternar entre registros diferentes)
- Sem erro no console — bug totalmente silencioso

## Fix — `key` prop para forçar remount

```jsx
// ✅ CORRETO: key diferente por registro → remount → useState reinicializa
<NudgeFormModal
  key={selectedNudge?.id || 'create'}
  nudge={selectedNudge}
  isOpen={isModalOpen}
  ...
/>
```

React desmonta e remonta o componente sempre que `key` muda.
`useState(nudge || defaultValue)` recebe o valor correto no novo mount.

## Por que NÃO usar `useEffect` + `setState`

```jsx
// ❌ Lint error: react-hooks/set-state-in-effect
useEffect(() => {
  setFormData(nudge || defaultValue)
  setErrors({})
}, [nudge])
```

`setState` síncrono dentro de `useEffect` dispara re-render extra e viola a regra
`react-hooks/set-state-in-effect` (configurada como **error** no projeto).

## Quando aplicar

Qualquer componente que:
1. Recebe uma prop que serve como **valor inicial** de um `useState`
2. É **reutilizado** (não desmonta) quando a prop muda — típico em modais, drawers, sidebars

**Why:** Bug silencioso em prod (028 admin nudges — formulário de edição vazio).

**How to apply:** Ao criar modal/form com prop de dados, sempre adicionar `key={entity?.id || 'create'}` no caller.
