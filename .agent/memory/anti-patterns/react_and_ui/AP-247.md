# AP-247 — Filtro de vigência incompleto em superfícies de seleção de dose [HIGH]

## Anti-Pattern

Usar apenas `active === true` ou `resolveTreatmentStatus() === 'ativo'` para filtrar tratamentos em modais/listas de registro de dose.

```js
// ❌ ERRADO — vaza prescrições encerradas e futuras do mesmo plano
const activeProtocols = protocols.filter(p => p.active)
```

## Por que é um problema

`resolveTreatmentStatus` não checa `start_date`. Um tratamento com `start_date > hoje` é classificado como ATIVO (porque active=true e end_date não passou). Da mesma forma, o `active` flag não é zerado automaticamente quando end_date passa — depende de GC assíncrono.

Resultado: prescrições encerradas e futuras do mesmo `treatment_plan` aparecem na modal de bulk dose (bug prod 039, TestFlight).

## Fix

Usar `isTreatmentSchedulableOn(protocol, today)` de `@dosiq/core` — predicado canônico que exige AMBOS: status ATIVO + hoje ∈ [start_date, end_date].

```js
// ✅ CORRETO
import { isTreatmentSchedulableOn } from '@dosiq/core'
const activeProtocols = protocols.filter(p => isTreatmentSchedulableOn(p))
```

## Callsites afetados (039)

- `apps/mobile/src/features/dose/hooks/usePlanProtocols.js` — mode==='plan' e mode==='active'
- `apps/web/src/shared/components/ui/GlobalDoseModal.jsx` — activeProtocols + activeTreatmentPlans
