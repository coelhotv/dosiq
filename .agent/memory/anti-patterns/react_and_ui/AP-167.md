# AP-167 — Eager parse string→number em input decimal apaga vírgula

**Sintoma**: input de dose com `keyboardType="decimal-pad"` não aceita `"0,5"` — usuário digita `0`, depois `,`, mas vírgula nunca aparece e dose fica em `0`.

**Root cause**: handler chamava `Number(raw.replace(',', '.'))` a cada keystroke. Estados intermediários como `"0,"`, `"0."`, `"."` resultam em `NaN` ou `0` quando coerced — substituem o valor da string com algo sem vírgula → próximo render mostra `"0"` (perdeu a vírgula). User não consegue completar a digitação do `5`.

**Por que perigoso**: parece bug de teclado/RN; user reporta "app não aceita decimais" sem clareza do mecanismo.

**Fix aplicado** (`handleDoseChange` em `ProtocolFormScreen.jsx`):

```js
const handleDoseChange = useCallback((name, raw) => {
  const str = String(raw ?? '')
  if (str === '') {
    form.handleChange(name, '')
    return
  }
  const normalized = str.replace(',', '.')
  const isIntermediate = normalized === '.' || normalized.endsWith('.')
  if (isIntermediate) {
    form.handleChange(name, str)  // mantém STRING preservando trailing
    return
  }
  const num = Number(normalized)
  form.handleChange(name, Number.isFinite(num) ? num : str)
}, [form])
```

Coerce final só no submit (via `coerceDose(form)` — ver [[AP-166]] sobre validate race).

**Regra preventiva**: input numérico que aceita decimal/vírgula deve preservar estados intermediários (`"0,"`, `"."`, vazio) como STRING. Conversão para number só no submit, nunca a cada keystroke.

**Display**: valor armazenado pode ser number OU string. Pra render, normalizar `String(v).replace('.', ',')` antes de passar pro input controlled.
