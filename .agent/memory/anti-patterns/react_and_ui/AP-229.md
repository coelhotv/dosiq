# AP-229 — Invalidação por evento wired em só UM de N hooks que leem a mesma fonte

**Categoria:** `react_and_ui`
**Detectado:** 012 Fase C PR 3b (review Gemini #666, web)
**Relaciona:** [[AP-192]] (refetch/identidade de hooks)

## Sintoma

Editar/excluir uma medida no card do dia atualizava a timeline e o dashboard, mas o
gráfico de tendência (`ScatterTrend` no `MeasuresHub`) ficava **stale** até um reload.
Salvar pela primeira vez funcionava; edições posteriores não refletiam no scatter.

## Causa-raiz

A invalidação é por evento de janela (`mr:measure-saved`, mesmo padrão de `mr:dose-saved`).
Dois hooks leem `biomarkers_log`: `useTodayMeasures` (dashboard) e `useMeasures` (scatter, por
tipo). O listener foi adicionado só ao `useTodayMeasures`. O `useMeasures` recarregava apenas
no mount → tendência não sincronizava com escritas feitas em outra superfície.

## Fix

Todo hook que lê uma fonte invalidável por evento DEVE registrar o mesmo listener:

```js
useEffect(() => {
  window.addEventListener('mr:measure-saved', load)
  return () => window.removeEventListener('mr:measure-saved', load)
}, [load])
```

## Regra geral

Ao introduzir um evento de invalidação (`mr:*-saved`), inventariar **todos** os hooks/consumidores
que leem a mesma tabela/fonte e wirar o listener em cada um — não só no que disparou a necessidade.
Checklist no PR: "quem mais lê esta fonte?". Padrão de evento já existe; o risco é cobertura
parcial, não o mecanismo. Smoke deve cobrir escrita em UMA superfície + verificação de atualização
nas DEMAIS (timeline, dashboard, tendência).
