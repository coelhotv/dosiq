# AP-122: Hardcoded Identifiers for Authorization

## Problem
Hardcoding specific UUIDs or email addresses in conditional logic to grant special permissions (e.g., admin access).

## Consequence
- Environment fragility: Dev and Prod IDs differ, breaking logic in one environment.
- Security debt: Hard to rotate or update authorized users without a code change.
- Lack of scalability: Adding a new admin requires a code commit and deployment.

## Solution
Use role-based metadata attached to the user session (Supabase Auth metadata) and check for a generic `'admin'` role.
