## Problema

No Hermes engine (Android), `Date.toLocaleString('pt-BR')` e `toLocaleTimeString('pt-BR', { hour: '2-digit', minute: '2-digit' })` retornam formato AM/PM em inglês (`"6/4/2026, 11:30 PM"`) em vez do formato 24h esperado (`"04/06/2026 23:30"`).

Não há erro — a função executa sem throw. O bug só aparece em device/emulador Android; simulador iOS e Node têm ICU completo e retornam o formato correto.

## Root Cause

O bundle Hermes do React Native não inclui ICU completo por padrão (redução de tamanho). O fallback do JS engine usa o locale do sistema operacional do device Android, que em muitos casos usa `en-US` independente do locale configurado.

## Fix

Nunca usar `toLocaleString` ou `toLocaleTimeString` para formatação de data/hora no mobile. Usar formatação manual com `padStart`:

```js
// Em vez de:
date.toLocaleTimeString('pt-BR', { hour: '2-digit', minute: '2-digit' })

// Usar:
const hh = String(date.getHours()).padStart(2, '0')
const min = String(date.getMinutes()).padStart(2, '0')
return `${hh}:${min}`

// Em vez de:
date.toLocaleString('pt-BR')

// Usar:
const dd = String(date.getDate()).padStart(2, '0')
const mm = String(date.getMonth() + 1).padStart(2, '0')
const yyyy = date.getFullYear()
const hh = String(date.getHours()).padStart(2, '0')
const min = String(date.getMinutes()).padStart(2, '0')
return `${dd}/${mm}/${yyyy} ${hh}:${min}`
```

Alternativa: usar `date-fns/format` com locale `pt-BR` (já dep do projeto via `@dosiq/core`).

## How to apply

Sempre que código mobile usar `toLocaleString`, `toLocaleTimeString`, `toLocaleDateString`:
- Substituir por formatação manual ou `date-fns/format`
- O try/catch de fallback em `DoseActionSheet.jsx` (Hermes fallback pattern) é o modelo correto
