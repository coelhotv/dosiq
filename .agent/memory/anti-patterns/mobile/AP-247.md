# AP-247 — Cold start trata só 1 canal de notificação

## Sintoma
App morto. Usuário toca ação ("Registrar") no card da **superfície** (canal
`dose-activity-v1`). App faz cold launch, mas a ação é **perdida** — a navegação p/ a
modal de registro nunca ocorre.

## Causa
`AlarmSchedulerBridge` tratava o cold start via `getInitialNotification().then(initial =>
openAlarmScreen(initial?.notification))`. `openAlarmScreen` ignora notificações que não
sejam de **alarme** (`isAlarmNotification` rejeita o canal da superfície). Então qualquer
ação de outra superfície que faça `launchActivity` cai no vazio no cold start (só o
foreground/background handler a tratava — e no cold start nenhum dos dois rodou ainda).

## Fix
No handler de `getInitialNotification`, **rotear por `pressAction.id`**: se for ação da
superfície (`SURFACE_ACTION.REGISTER`) → `handleAlarmAction({ detail: initial })`; senão →
`openAlarmScreen`. Guard `useRef` p/ rodar 1x por ciclo de vida.

## Regra
Handler de cold start (`getInitialNotification`) deve cobrir TODOS os canais/ações que
fazem `launchActivity`, não só o caminho default. Relacionado: [[CON-030]], [[AP-205]], [[AP-207]].
