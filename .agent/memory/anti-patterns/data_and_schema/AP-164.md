# AP-164 — Função com mesmo nome em arquivos diferentes do mesmo package

**Sintoma**: Listagem mobile filtrava silenciosamente tratamentos não-`diário` (DB tinha 5 active, mobile retornava 3). Detectado via MCP Supabase: server respondia 200 com count=5; client filtrava 3.

**Root cause**: `@dosiq/core` re-exportava `isProtocolActiveOnDate` de `adherenceLogic.js` (strict — frequency + weekdays + period). A versão simples em `dateUtils.js` (period-only) NÃO era exportada por nome distinto. Listagem usava a strict por engano (consumer importou pelo nome óbvio, não soube da existência da segunda).

**Por que perigoso**: bug semântico silencioso — nenhum lint, type check ou test pega. Linter passa, tests passam (mocks usam dados que casam com strict), prod silenciosamente esconde dados do user.

**Fix aplicado**:
- Barrel `@dosiq/core/index.js` agora re-exporta as duas funções com nomes distintos:
  - `isProtocolActiveOnDate` (strict, adherence) — para adherence/dashboard/stock
  - `isProtocolInPeriod` (period-only, dateUtils) — para listagem visível ao paciente
- Spec `EXEC_SPEC_FASE2_PROTOCOLOS.md` §6 documenta a distinção com tabela de uso.

**Regra preventiva**: ao auditar packages compartilhados antes de novo consumer, grep por `function X` cross-files. Se houver collision, renomear UM dos dois com prefixo semântico (`isProtocolInPeriod` vs `isProtocolActiveOnDate`). Nunca exportar dois com mesmo nome via `export *`.
