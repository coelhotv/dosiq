# AP-233 — Event ID prefixado do core (`inst:`/`log:`) usado como UUID bruto

**Status:** ✅RESOLVED (spec 033, PR #671, mobile 0.19.0) · **Layer:** warm · **Domain:** data_and_schema
**Descoberto:** 2026-06-16 (smoke 033: editar dose `missed`→`taken` consumia estoque mas não marcava `dose_instances.status`)

## Contexto

`createTimelineService` do core prefixa os IDs dos eventos para garantir unicidade na timeline
mesclada (doses + logs avulsos + biomarcadores):

```js
// packages/core — instanceToEvent / logToEvent
id: `inst:${inst.id}`   // evento de instância
id: `log:${log.id}`     // evento de log avulso
payload.instanceId: inst.id   // ← UUID bruto vive aqui
payload.logId: log.id         // ← UUID bruto vive aqui
```

O `mapToMobileShape` expõe os UUIDs brutos como `instance.instanceId` / `instance.logId`.
O campo `instance.id` continua sendo o **event ID prefixado** (`"inst:<uuid>"`).

## O anti-pattern

Passar `instance.id` (prefixado) onde a API espera UUID bruto:

```js
// ERRADO — "inst:<uuid>" não é UUID válido
onRegisterRetro?.(logData, instance.id)
onUndo?.(instance.id)

// CERTO
onRegisterRetro?.(logData, instance.instanceId)  // UUID bruto
onUndo?.(instance.instanceId)
```

## Por que é perigoso (falha silenciosa)

`_anchorLogToInstance` é **best-effort** — recebe o ID errado, não encontra a instância,
**falha em silêncio**. Resultado: `medicine_logs` inserido + estoque consumido (`consume_stock_fifo`),
mas `dose_instances.status` permanece `missed` e a âncora bidirecional não fecha. Desync
log↔instância↔estoque (parente do [[AP-193]]), sem erro no console.

## Fix / Regra

- Em qualquer consumidor de `TimelineEvent` mapeado: usar `instanceId`/`logId` (payload, UUID bruto)
  para FK, RPC e mutações. **NUNCA** `event.id` (prefixado, só p/ React key / dedup de lista).
- Ao desenhar anti-corruption layers (`mapToMobileShape`), expor explicitamente os UUIDs brutos
  e documentar que `id` é prefixado.
- Âncoras best-effort devem **logar** falha de match (não engolir) — falha silenciosa mascara desync.

Relacionado: [[AP-193]] (âncora log↔instância), [[AP-194]] (janela UTC no filtro de timeline).
