# AP-244 — Adapter cross-superfície passa shape local em vez do contrato do core

**Domínio:** data_and_schema
**Detectado em:** spec 015 Onda 3 (smoke web — adesão sumia do payload do chatbot)

## Sintoma
Na web, o assistente IA respondia "não tenho informações suficientes para calcular a sua adesão",
embora a adesão exista no app. No mobile e no Telegram funcionava. O dump (scratch) via fetcher
canônico também mostrava a adesão correta.

## Causa
A web **não usa o fetcher canônico** (`fetchChatbotContextData`) — reusa os dados já carregados no
`DashboardContext` e os passa direto ao builder `buildPatientContext` (otimização: evita 2º fetch).
Mas o shape do Dashboard expõe a adesão em `stats.rates.adherence` / `stats.adherenceRate`,
enquanto o contrato CON-028 do builder lê `stats.adherence` (0-1). O campo divergente chegava
`undefined` → o builder omitia a linha de adesão → o LLM não tinha o dado.

Os demais campos (medicines/protocols/logs/stockSummary/doseInstances) batiam por coincidência de
nome; só `stats` divergia.

## Fix
Conformar o adapter ao **contrato do core**, não ao shape local do consumidor:

```js
const normalizedStats = { ...stats, adherence: stats?.rates?.adherence ?? stats?.adherenceRate ?? null }
```

## Regra-mãe
Quando uma superfície alimenta um módulo do core por um caminho alternativo (sem o fetcher
canônico), o adapter É responsável por conformar ao contrato (CON-NNN) — o shape do consumidor
local não é autoridade. Vale testar o contrato no ponto de entrada de cada superfície.
