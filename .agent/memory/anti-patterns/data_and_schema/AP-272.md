# AP-272 — Tabela com `user_id` fora do pipeline de exclusão de conta → dado de saúde órfão

**Categoria:** data_and_schema · **Detectado:** 046 §T000 (2026-07-09) · **Severidade:** HIGH (compliance LGPD art. 16)

## Sintoma
Tabela nova com `user_id NOT NULL` mas **sem FK para `auth.users`** E **não incluída** na RPC
`delete_user_account()` (que deleta filhos→pais explicitamente). Excluir a conta deixa o dado do
titular órfão no banco — dado clínico sensível persiste após o titular sumir. Falha **latente e
silenciosa**: nenhum erro, órfãos só aparecem quando alguém exclui a conta (0 órfãos em prod até o dia
em que houver a 1ª exclusão real com essa tabela populada).

Caso real: `dose_instances`, `dose_critical_events`, `dose_adherence_monthly` — todas com `user_id`
solto. `dose_critical_events` não tinha FK alguma (nem via `protocol_id`) → nunca seria limpa. As
outras duas eram limpas *por acaso* via `protocol_id ON DELETE CASCADE` (protocols é deletado na RPC),
mas ficavam órfãs quando `protocol_id` fosse NULL.

## Causa raiz
Criar tabela com `user_id` como uuid solto (sem FK) e assumir que a limpeza "acontece". Dois modos:
(a) esquecer de anexar a tabela na RPC de exclusão; (b) mesmo anexando, **repete-se o erro na próxima
tabela nova** — a RPC é uma lista manual que sempre fica para trás.

## Fix
FK **`ON DELETE CASCADE` de `user_id` → `auth.users(id)`** (dado do titular deve sumir). À prova de
futuro: cobre a RPC `delete_user_account()` E o prune via Supabase **Admin API `deleteUser`** (que NÃO
reusa a RPC auth.uid()-based). Anexar na RPC sozinho é frágil; a FK é o mecanismo declarativo.

Exceção deliberada: **trilha que deve sobreviver ao titular** (ex.: `consent_log` de LGPD) usa
`ON DELETE SET NULL` + coluna de hash/e-mail — o oposto consciente, não o esquecimento.

## Guard
- CASCADE **bypassa RLS** e não dispara BEFORE DELETE triggers de bloqueio → não conflita com tabela
  append-only (ex.: ADR-077 `dose_critical_events`, cujo append-only é só ausência de DELETE policy).
- Testar com `BEGIN..ROLLBACK`: criar user fake → povoar → `DELETE FROM auth.users` → contar = 0 (AP-187:
  nunca aceitar auto-report; conferir no DB).
