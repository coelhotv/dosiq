# AP-228 — Prefill com `'' ` (string vazia) em campo `z.enum().nullable()` → update invisível-bloqueado

**Categoria:** `data_and_schema`
**Detectado:** 012 Fase C (smoke PO 2026-06-14, PR #665)
**Relaciona:** [[AP-225]] (`.partial()` mantém default), [[AP-214]] (`.partial()` stripa campo)

## Sintoma

Editar tratamento **não-líquido** (comprimido/cápsula) e clicar "Salvar alterações" falhava com
"Preencha o campo obrigatório para salvar" — **sem nenhum campo visível em erro** (o campo
`intake_unit` só renderiza para líquidos). Líquidos salvavam normal. Erro mudo, irreproduzível
por inspeção visual do form.

## Causa-raiz

`buildPrefill` (useProtocolFormState) montava `intake_unit: existing.intake_unit ?? ''` para
hidratar o form. Não-líquido tem `intake_unit = NULL` no banco → vira `''`. O schema é
`z.enum(INTAKE_UNITS).nullable().optional()` (`INTAKE_UNITS = ['gotas','ml','UI','mg']`). `''`
**não** é membro do enum **nem** `null` → falha o parse. Como a UI do campo só existe no ramo
líquido, a mensagem de erro não tinha onde ancorar → "campo obrigatório" fantasma.

```js
// '' não satisfaz enum nem nullable:
intakeUnitSchema.safeParse('')   // ❌ invalid_enum_value
intakeUnitSchema.safeParse(null) // ✅
```

## Fix

Prefill de campo nullable usa `?? null`, **nunca** `?? ''`:

```js
intake_unit: existing.intake_unit ?? null, // null (não ''): '' falha z.enum, NULL é válido
```

## Regra geral

Ao hidratar form a partir de registro existente, o fallback de um campo `z.enum().nullable()`
deve ser `null`, não `''`. String vazia é um "terceiro estado" que nem o enum nem o `.nullable()`
aceitam — e se o input do campo for condicional (renderiza só p/ alguns casos), o erro fica
invisível. Auditar todo `?? ''` em prefill cujo schema-alvo seja enum/nullable. Smoke deve cobrir
o **edit** de cada variante (líquido E sólido), não só o create.
