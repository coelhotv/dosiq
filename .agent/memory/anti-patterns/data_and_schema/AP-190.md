# AP-190 — Transição de status sem writer (a `missed` que nunca acontecia)

## Sintoma

Modelo materializado (`dose_instances`) com enum de status `pending|taken|missed|skipped_*`.
Geração criava `pending`; âncora setava `taken`; **`missed` só era setado pelo backfill
one-shot.** Nenhum job de regime fazia `pending → missed`. Resultado: toda dose esquecida
após o backfill ficava `pending` pra sempre → **adesão inflada** (`taken/(taken+missed)`
sem o missed real) e **streak que nunca quebra**. Latente, degrada silenciosamente.

## Causa

A máquina de estados precisa de um **writer por transição**. O spec do motor
(`EXEC_SPECS_PHASE_1_2` §cron) enumerou as responsabilidades do cron como só
`generate` + `cleanup` — a transição `pending→missed` **nunca virou sprint**. O enum
existir criou ilusão de cobertura; o backfill produziu 308 missed em prod, fabricando
confiança ("missed funciona ✅") sobre um **snapshot**, não um **processo**. A fase
consumidora (F3) confiou na semântica de `missed` sem auditar quem a produz —
mesmo erro caller-vs-definition do DEVFLOW C1, um nível acima (consumidor↔produtor).

## Correção (F2.5)

1. **Writer #3:** `markMissedDueInstances` (sweep `pending`→`missed` onde
   `scheduled_for + tolerance_minutes < now`) no cron diário (`api/generate-doses.js`).
   Paginado (AP-186), idempotente, guard `status='pending'` (AP-185).
2. **missed re-ancorável:** `findAnchorInstance`/`markTaken` aceitam `pending` E `missed`
   → registro retroativo dentro da tolerância faz self-heal `missed→taken` (corrige o
   sweep que terminalizou cedo). `missed` deixa de ser terminal.

## Regra preventiva

- **Todo status de um modelo materializado precisa de um writer de regime** (não one-shot)
  para CADA transição que o sistema assume. Listar as transições explicitamente no spec.
- **Backfill one-shot NÃO conta como writer recorrente** — só popula o passado.
- **Invariante de completude:** monitorar/testar que não existe estado "preso" —
  ex: `count(pending WHERE scheduled_for + tolerance < now) == 0` após o sweep. Uma
  invariante que falha alto se o writer sumir de novo.
- Fase consumidora DEVE auditar que existe produtor mantendo o dado que ela lê
  (não confiar no enum/na presença de linhas).
