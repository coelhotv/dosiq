# AP-341 — Consumidor novo assume que o select do caminho dele traz o campo

**Layer**: warm · **Categoria**: data_and_schema · **Criado**: 2026-08-26 · **trigger_count**: 1
**Origem**: bug de produção no registro em lote de injetáveis (mobile), achado em smoke do PO

## Sintoma

O seletor de sítio de injeção **nunca aparecia** no registro em lote aberto por bloco de horário,
plano ou notificação. Nenhum erro, nenhum log, nenhum teste vermelho: a tela simplesmente não
mostrava a seção. E o mesmo gate descartava o sítio no envio, então mesmo com a UI corrigida o dado
continuaria não sendo gravado.

## Mecanismo

`isInjectable(medicine)` decide por `medicine.presentation === 'injetavel'`. O caminho do lote carrega
os tratamentos por `getActiveTreatments` → embed `medicine:medicine_id(...)`, e **esse embed não pedia
`presentation`**. Campo ausente ⇒ `undefined` ⇒ predicado sempre `false` ⇒ o ramo inteiro da feature
some. A coluna existe no banco desde sempre; o defeito é do `select`, não do dado.

```
getMedicinesData (dashboard)  → pede presentation  → dose única e lote "hero" OK
getActiveTreatments (embed)   → NÃO pedia          → lote plan/misc/active MORTO
```

## Por que nenhum gate pegou

O `select` é **string**: `tsc` não valida, lint não valida, e os testes de comportamento mockam o
client — o mock devolve o shape que o teste inventou, não o que o PostgREST devolveria. Um predicado
que responde `false` por campo ausente é indistinguível de um predicado que responde `false` porque a
resposta é `false`. Diferente de [[AP-298]]/[[AP-340]] (coluna **inexistente** ⇒ `42703` ⇒ erro
barulhento), aqui a coluna existe e a query passa: **falha silenciosa, não erro**.

## A metade que a R-267 não cobria

[[R-267]] responde *"campo novo em `protocols` → varra todos os `.select()`"*. O caso inverso não
estava coberto: **consumidor novo** (a spec 031 introduziu `isInjectable`) sobre selects **antigos**.
Quem escreve o consumidor assume que "o medicamento vem completo" — e cada caminho traz um subconjunto
diferente.

## Prevenção

1. Ao introduzir um predicado sobre um campo de entidade embutida, **listar os caminhos** que produzem
   essa entidade (`grep` pelo embed / pelo service) e conferir o `select` de **cada um**.
2. Gate de saída da [[R-295]] vale igual: rodar o select alterado contra o PostgREST e **ver o campo
   na resposta**, não só o `200`.
3. Trava barata que nasceu com o fix: **teste de contrato do `select`** — captura a string e asserta
   os campos que a UI consome (`treatmentsService.select.test.ts`). Provado com poder de detecção:
   removendo `presentation` do embed, o teste falha.
4. Farol: predicado de feature (`isX(entidade)`) cujo campo **não aparece** no `select` do caminho —
   é feature morta esperando smoke manual para ser descoberta.
