# AP-225 — Zod v4 `.partial()` mantém `.default()` → update parcial corrompe dados

**Categoria:** `data_and_schema`
**Detectado:** 012 Fase B2 (smoke PO 2026-06-12, PR #660)
**Relaciona:** [[AP-223]] (`.partial()` + `.superRefine()`), [[AP-214]] (`.partial()` stripa campo ausente)

## Sintoma

Atualização parcial de `medicines` (ex.: gravar só `injection_container` via `medicineService.update`)
**flipava** `presentation: 'injetavel' → 'comprimido'` e `type → 'medicamento'` no banco — corrupção
clínica (líquido vira sólido, perde TTL/container/conversão). Reproduzido com Mounjaro e Lantus.
Invisível em lint/build; `validate:agent` passou (vitest/esbuild lenientes).

## Causa-raiz

`medicineUpdateSchema = medicineObject.partial()`. No **Zod v4**, `.partial()` torna o campo
opcional MAS **não remove o `.default()`** interno: ao parsear um objeto que omite o campo, o
`ZodDefault` ainda **materializa o valor padrão** na saída. Como o `update()` grava `validation.data`,
os defaults (`presentation: 'comprimido'`, `type: 'medicamento'`) eram escritos por cima do valor real.

```js
// prova
validateMedicineUpdate({ injection_container: 'caneta' })
// → { presentation: 'comprimido', type: 'medicamento', injection_container: 'caneta' }  ❌
```

## Fix

No schema de **update**, sobrescrever os campos com `.default()` para optional **sem** default;
defaults seguem só no **create**:

```js
export const medicineUpdateSchema = medicineObject.partial().extend({
  presentation: z.enum(PRESENTATIONS).optional(),
  type: z.enum(MEDICINE_TYPES).optional(),
})
```

## Regra geral

`.partial()` **não** neutraliza `.default()` nem `.superRefine()` (AP-223). Para schemas de update:
auditar TODO campo com `.default()` e removê-lo no path de update (`.extend({ campo: base.optional() })`),
OU pickar só as chaves presentes no input. Teste anti-regressão: `update({umCampo})` não deve trazer
nenhuma outra chave. Vitest passar **não** garante — Rollup/Vercel é mais estrito (caso irmão: build
quebrou em named import não re-exportado no mesmo PR).
