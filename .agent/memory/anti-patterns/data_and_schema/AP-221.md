# AP-221 — Drift de assinatura de RPC quebra callers silenciosamente

**Classe:** anti-pattern · **Layer:** warm · **Pack:** schema-data · **Status:** active

## Sintoma
`PGRST202` ("function not found") em runtime ao chamar RPC depois de alterar
sua assinatura numa migração anterior. Ex.: `consume_stock_fifo` ganhou
`p_user_id` na Fase A (#650); callers web (createStockRepository) e mobile
(doseService) continuaram chamando a assinatura antiga → erro só na tomada de
dose, não em teste de migração.

## Causa
Migração SQL e código que consome a RPC vivem em camadas diferentes. Mudar a
assinatura no DB não dispara erro de compilação no JS — PostgREST resolve por
nome+args em runtime. Fase A entregou DB; callers só foram tocados na Fase C.

## Correção
Ao mudar assinatura de RPC (add/rename/reorder de param):
1. `grep -rn "rpc('<nome>'" apps/ packages/ server/` — listar TODOS os callers.
2. Atualizar cada caller na MESMA fase/PR da migração (ou cravar contrato CON-NNN).
3. Atualizar os testes que mockam `.rpc()` (asserts de args).
4. Smoke do write-path real, não só do schema.
