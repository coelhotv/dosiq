# AP-194 — `getNow()`/`getSaoPauloTime().toISOString()` para consultar coluna UTC → janela deslocada 3h

**Status:** active · **Layer:** warm · **Domain:** data_and_schema
**Descoberto:** 2026-05-30 (Gemini PR #619 / S3.7 — janelas de adesão do bot)

## Sintoma
Janela de consulta (`gte`/`lte` em `scheduled_for`/`taken_at`, ambos timestamptz UTC)
fica **3h atrás** do UTC real → omite as doses das últimas 3h (justo as mais recentes:
relatório das 23h, streak logo após registrar uma dose). Adesão/streak subcontam.

## Causa
`getSaoPauloTime(date)` (e `getNow()` que a chama) retorna `new Date(spWallClockString)`:
constrói um Date a partir do **wall-clock de São Paulo** parseado como se fosse local do
servidor. Em servidor UTC (prod), `getNow().toISOString()` devolve o horário de SP **rotulado
como UTC** → 3h a menos que o instante real. Comparar isso com `scheduled_for` (UTC verdadeiro)
desloca a janela inteira.

```js
// ERRADO p/ limite de query em coluna UTC:
addDays(getNow(), -7).toISOString()   // 3h atrás do UTC real
getNow().toISOString()

// CERTO:
const nowIso = getServerTimestamp();  // = new Date().toISOString() → UTC real
addDays(nowIso, -7).toISOString();    // addDays faz new Date(iso) interno (exempt R-020)
```

## Regra
- Para **limites de query** em colunas timestamptz (UTC), usar **UTC real**:
  `getServerTimestamp()` para "agora"; `addDays(nowIso, -N)` para deslocamentos. **1 chamada**
  de timestamp por janela (evita instantes divergentes entre `from`/`to`).
- `getNow()`/`getSaoPauloTime()` servem para **wall-clock/exibição e fronteira de dia local**,
  NUNCA para `.toISOString()` comparado a coluna UTC.
- `new Date(epochMs)` (aritmética de epoch, ex.: `getTime()-1` p/ teto exclusivo) é legítimo e
  NÃO é o footgun do R-020 (que mira `new Date('YYYY-MM-DD')`) — `eslint-disable` pontual ok.
- Limites inclusivos (`gte`+`lte`, como `countByStatus`) em janelas adjacentes precisam de
  teto **exclusivo** num dos lados (ex.: ontem `lte = startOfDay - 1ms`) p/ não double-contar
  a instância exata do boundary.
