# AP-328 — Allowlist de visibilidade no core esconde um estado real e deixa o render das pontas virar código morto

**Classe**: dado real que existe no banco e não existe em nenhuma tela
**Origem**: spec 067 A1 (`fix/067-a1-skipped-user-visivel`) · incidente de prod 2026-08-14
**Família**: [[AP-305]] (capacidade declarada sem consumidor) · [[AP-307]] (render × gate) · [[AP-296]] (paridade web↔mobile) · [[AP-301]] (camadas mortas empilhadas)

## O que aconteceu

`dose_instances.status = 'skipped_user'` é escrito em produção (o "Pular" do alarme,
`quickDoseRegistration.ts:111,118`). Mas o adapter canônico de leitura filtrava por allowlist:

```ts
const VISIBLE_INSTANCE_STATUSES = new Set(['taken', 'missed', 'pending'])  // timelineService.ts:29
```

Resultado: a dose pulada **não existia em nenhuma superfície** — nem no mobile, nem na web, nem
como `missed`, nem como falha de aderência. Uma dose destruída às 09:47 por um alarme torto sumia
do registro do tratamento sem deixar rastro.

Pior: o mobile **já tinha o render pronto** (`DoseHistoryList.tsx:24`, `DoseActionSheet.tsx:31,37`
com label "Pulada" e `RedoDot`) — código morto há meses, porque o dado nunca chegava. A web não
tinha, e o fallback `STATUS_META[status] || STATUS_META.pending` (`DoseEventCard.tsx:50`)
transformaria a dose pulada em **"Pendente"** assim que o dado passasse a chegar: mentira sobre um
ato clínico, pior que o invisível (achado da RC2/D-1 — a spec original listava 3 arquivos e teria
entregue o bug).

## Por que nenhum gate pegou

- `tsc`/lint: `Set<string>` com 3 literais é código perfeitamente válido.
- Teste: existia um teste **verde** afirmando o comportamento errado — `'skipped_* são ocultos da
  timeline'`. O teste não estava quebrado; estava **codificando a premissa errada** (agrupar
  `skipped_paused` e `skipped_user` como se fossem a mesma coisa).
- Smoke: ninguém sente falta do que nunca apareceu. A ausência não gera erro, gera silêncio.

## Farol

1. **Toda allowlist de leitura é um gate invisível.** Ao ver `new Set([...])`/`.in('status',[...])`
   filtrando estados de uma máquina de estados, pergunte: *quais valores o banco produz que não
   estão nesta lista, e onde eles aparecem?* Se a resposta for "em lugar nenhum", é bug, não filtro.
2. **Agrupamento por prefixo (`skipped_*`) é onde a distinção morre.** `skipped_user` é ato da
   PACIENTE (fato clínico datado); `skipped_paused` é estado do TRATAMENTO. Tratá-los como um só
   por causa do nome apagou a diferença que importava.
3. **Neutro no CÁLCULO ≠ oculto na EXIBIÇÃO.** A justificativa da ocultação era "skipped é neutro
   na aderência" — verdade que vale para o numerador/denominador (R-248) e não vale para o
   histórico. Confusão de eixo.
4. **Estado novo no core = auditar TODOS os renderizadores das 2 plataformas antes de liberar.**
   Grep do valor em `apps/web` E `apps/mobile`, e conferir o *fallback* de cada mapa de status —
   um `|| STATUS_PADRAO` transforma estado desconhecido em afirmação falsa, em silêncio.
   Também as camadas de cor: o dot do calendário web precisou de CSS próprio
   (`Calendar.css`), fora da lista de arquivos da spec, senão o dia herdaria o verde default.
5. **Render pronto sem dado chegando é sinal, não conforto.** Código de exibição de um estado que
   nunca é exercido em nenhum teste de integração nem em prod está morto — e código morto esconde
   que a ponte está quebrada ANTES dele.

## Correção

`VISIBLE_INSTANCE_STATUSES` passa a incluir `skipped_user` (allowlist segue allowlist — teste novo
prova que status desconhecido continua fora); web ganha `STATUS_META.skipped_user`,
`STATUS_DOT_ORDER` e as duas famílias de CSS (card + dot); aderência intocada por construção.
