# AP-294 — Preferência de UX usada como permissão de acesso a dado do titular (LGPD)

**Domínio:** data_and_schema · **Origem:** spec 046 Slice D (smoke do hub) · **Data:** 2026-07-14
**Relacionadas:** [[R-291]] / [[AP-291]] (cobertura de export) · [[R-292]] · família art. 18 LGPD

## O anti-padrão

Uma flag de **preferência de interface** (o que o app *mostra*) foi usada para decidir o que entra no
**export de dados do titular** (o que ele tem *direito de levar*). São eixos diferentes: a preferência
governa telas; o direito de acesso/portabilidade (LGPD art. 18 II e V) governa dados. Confundi-los
faz o app **esconder do titular dados que são dele** — e nada falha, porque a omissão é silenciosa
(a seção some, não dá erro).

## O caso

O export (008) condicionava a seção de estoque a `stock_tracking_enabled` (044): dose-only → checkbox
some, fetch devolve `null`, formatter grava "não controlado". Mas **a 044 CONGELA o estoque, não
apaga** — quem teve estoque e desligou o controle mantém lotes e compras no banco. O export os
omitia em silêncio, nos três níveis (UI, fetch, formatter). Achado no smoke do hub de privacidade,
não por teste — os testes *codificavam* o comportamento errado ("dose-only não exporta estoque").

## Por que passou

O comportamento parecia uma decisão de produto legítima e tinha até uma US que o justificava (044/US3:
"não mostrar lista vazia de lotes"). A intenção era boa — não sugerir "acabou o estoque". O erro foi o
**mecanismo**: usar a preferência de controle como porteiro dos dados, em vez de decidir pela
**existência** deles.

## A distinção que corrige

- **Existe dado** (qualquer lote/compra) → exporta, sempre, independente da preferência.
- **Não existe** → seção honesta "sem dados", nunca a **ausência** da seção (ausência sugere que o
  dado nunca poderia existir; "sem dados" diz "você não tem, mas poderia").
- A preferência (`stock_tracking_enabled` / `stock_paused_at`) vira **metadado** no bundle
  (`control_enabled`), nunca um portão.

## Farol (como reconhecer no code review)

- No caminho de **export/portabilidade**, um `if (preferenciaDeUX)` ou `&& enabled` decidindo se a
  seção sai. Pergunta: *"esse dado existe no banco e é do titular?"* Se sim, a preferência de tela
  não pode escondê-lo.
- Teste que **afirma** que uma categoria de dado do titular "não é exportada" — quase sempre está
  petrificando o furo, não protegendo contra ele.
- Feature "desligável" cujo desligamento **preserva** os dados (congela, não apaga): os dados
  congelados continuam sendo do titular e continuam exportáveis.
