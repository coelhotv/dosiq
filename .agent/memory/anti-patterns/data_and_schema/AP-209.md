# AP-209 — Adicionar param a RPC = overload ambíguo + schema cache exige deploy ordering

**Layer:** warm · **Status:** active · **Pack:** data_and_schema / infra_and_deploy
**Detectado:** Spec 001 (Alarme Nativo) A2, RPC `upsert_notification_device`, 2026-06-03

## Sintoma A — função não-única

`CREATE OR REPLACE FUNCTION` com um param novo (mesmo com `DEFAULT`) **não
substitui** a função antiga — cria um **overload**. Com a de 7 args e a de 8-args-
com-default coexistindo, chamar com 7 args → `function ... is not unique`.

## Sintoma B — schema cache (PostgREST)

Após bumpar o app pra mandar o 8º param, mas **antes** de aplicar a migration:

```
Could not find the function public.upsert_notification_device(
  ...p_native_alarm_enabled...) in the schema cache
```

→ registro de device quebra (`[syncNotificationDevice] Upsert failed`).

## Causa

- **A:** Postgres resolve overloads por aridade; 7-arg + 8-arg-default = ambíguo.
- **B:** o PostgREST resolve a RPC por assinatura exata no schema cache; o app
  novo manda args que a função antiga (7 params) não tem → "not found".

## Fix

- **DROP** a assinatura antiga antes de recriar com o param novo (`DEFAULT` last
  p/ callers antigos seguirem válidos sem ambiguidade):

```sql
DROP FUNCTION IF EXISTS upsert_notification_device(text,text,text,text,text,text,text);
CREATE OR REPLACE FUNCTION upsert_notification_device(..., p_x boolean DEFAULT false) ...
```

- **Deploy ordering:** aplicar a migration **ANTES** de soltar o app que manda o
  param novo. App novo + função antiga = registro de device quebrado em prod.
