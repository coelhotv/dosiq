# AP-304 — `.partial()` + `.default()`: o update parcial que apaga o que você não tocou

## Sintoma

Pausar (desligar o `active`) um tratamento **semanal** fazia o **dia da semana sumir** — e ele
**não voltava** ao reativar. O usuário mandou uma edição de UM campo (`{ active: false }`) e o banco
perdeu OUTRO (`weekdays`).

## Causa raiz

```ts
export const protocolUpdateSchema = protocolSchema.partial()
// weekdays: z.array(...).optional().default([])
// titration_status: z...default('estável'); current_stage_index: z...default(0); etc.
```

`.partial()` torna cada campo **opcional** (aceita ausência), mas **não desfaz os `.default()`**.
Parsear um update parcial dispara os defaults dos campos ausentes:

```
validateProtocolUpdate({ active: false }).data
// => { active:false, weekdays:[], titration_status:'estável',
//      titration_schedule:[], current_stage_index:0, critical_alarm:false }
```

O repositório gravava `validation.data` **cru**:

```ts
const { _medicineIsLiquid, ...cleanUpdates } = validation.data
await client.from('protocols').update(cleanUpdates)...  // grava weekdays:[] e as N1
```

→ `weekdays` do tratamento semanal vira `[]` (o dia some), e as colunas N1 deprecadas
(`titration_status`/`titration_schedule`/`current_stage_index`) são reescritas em toda edição parcial.

## Por que passou por todos os gates

- **Teste do repo usava `toMatchObject`** (subset): valida que o payload CONTÉM `{name:...}`, mas
  **não vê chaves EXTRA** injetadas. `toEqual` teria pegado.
- O toggle manda só `{active}` — ninguém suspeita que pausar zera `weekdays`.
- `tsc`/lint não olham semântica de default; o client é mockado nos testes (não há escrita real).

Confirmado no banco por evidência (Supabase MCP), não por suposição: 1 linha `frequency='semanal'`
com `weekdays: []`.

## Fix

O `update` persiste **só as chaves que o chamador enviou**, com o valor já validado/transformado:

```ts
const sentKeys = new Set(Object.keys(updates))
const { _medicineIsLiquid: _omit, ...validated } = validation.data
const cleanUpdates = Object.fromEntries(
  Object.entries(validated).filter(([key]) => sentKeys.has(key)),
) as typeof validated
```

`updates` cru = a **intenção**; `validation.data` = a **validação de tipos**. A interseção é o que
de fato deve ir ao banco. Vale para web e mobile (write-path compartilhado em `@dosiq/core`).

## Farol (como reconhecer de novo)

- `schema.partial()` sobre um schema que tem `.default()` sendo usado para **UPDATE parcial**.
- Teste de payload de escrita com `toMatchObject`/`objectContaining` em vez de `toEqual` — não
  detecta chave a mais.
- "Mandei atualizar 1 campo e o banco perdeu outro" → suspeitar de default injetado no update.
