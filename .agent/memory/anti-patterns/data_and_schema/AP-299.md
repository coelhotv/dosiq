# AP-299 — Entidade nova materializa o valor que a tabela antiga representa por NULL (fronteira de domínio)

**Domínio**: data_and_schema · **Detectado**: 2026-07-16 (029 F3 / T013 — pego no preflight R-270,
ANTES de rodar em prod, pelo teste 17 da suíte live)

## O que aconteceu

O modelo N2 da titulação (`titration_steps`, spec 029) materializou a unidade de tomada
EXPLICITAMENTE, incluindo comprimido:

```sql
intake_unit text NOT NULL CHECK (intake_unit IN ('gotas','ml','UI','mg','cp'))   -- titration_steps (novo)
```

Mas a tabela que EXECUTA a dose representa comprimido por **ausência**:

```sql
intake_unit text CHECK (intake_unit IN ('gotas','ml','UI','mg'))   -- protocols (legado): sem 'cp'
-- dado real de prod: 62 de 70 protocolos com intake_unit NULL (= comprimido)
```

A RPC de transição copiava `step.intake_unit` para `protocols.intake_unit`. Para qualquer escada de
**comprimido** — o caso canônico do N1 (metoprolol) — isso é `23514 violates check constraint
protocols_intake_unit_check`, abortando a transação inteira.

**Só não explodiu em prod por sorte**: a única escada existente era `'mg'` (GLP-1 injetável).
O bug estava armado para a primeira titulação de comprimido criada pelo F4.

## Regra

Quando uma entidade nova convive com a antiga (strangler fig / adapter), **todo par
(coluna nova → coluna antiga) é uma FRONTEIRA DE DOMÍNIO, não uma cópia**. Antes de escrever de um
lado para o outro, comparar os CHECKs dos DOIS lados — o domínio novo costuma ser mais rico
justamente porque o antigo usava NULL/convenção implícita para o caso default:

```sql
intake_unit = NULLIF(v_step.intake_unit, 'cp')   -- 'cp' (N2, explícito) → NULL (N1, implícito)
```

Sinal de alerta: o modelo novo nasce com um valor de enum que **substitui uma convenção implícita**
do modelo velho (aqui, `'cp'` no lugar de NULL; no mesmo épico, `duration_days IS NULL` no lugar de
`requires_new_medicine`). Esse valor é exatamente o que NÃO pode atravessar a fronteira cru.

## Detecção

```sql
-- Comparar os domínios dos dois lados antes de escrever de um no outro:
SELECT conrelid::regclass, pg_get_constraintdef(oid) FROM pg_constraint
WHERE conname LIKE '%intake_unit%';
```

Teste obrigatório: um caso do valor NOVO atravessando para a tabela ANTIGA (caso 17 de
`docs/migrations/20260716_titration_switch_rpc.test.sql`).
