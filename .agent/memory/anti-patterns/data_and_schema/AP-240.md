# AP-240 — Janela de vigência/dias-restantes calculada por diff de ms em tempo real

**Categoria:** data_and_schema · **Detectado:** 038 Slice C (2026-06-23, PR #680 — bug HIGH Gemini)

## Sintoma
`derivePrescriptionStatus` (extraído de `Stock.jsx::deriveProtocolStatus`) calculava
`daysLeft = (end - now) / 86400000` com `now = getNow()` (horário ATUAL). Uma prescrição
que vence HOJE, avaliada ao meio-dia, dava `daysLeft ≈ -0.5` → caía em `< 0` → status falso
**'vencida'** ainda dentro do último dia válido de vigência. Transições de DST também
distorceriam a contagem (dia de 23h/25h).

## Causa
Comparar **instantes** (ms em tempo real) quando a regra é sobre **datas de calendário**.
A vigência é "válida até o fim do dia de término" — uma propriedade de data, não de relógio.
Diferença de ms entre meio-dia de hoje e meia-noite do fim introduz frações negativas que o
`< 0` interpreta como vencido.

## Fix / Prevenção
Comparar datas de calendário, normalizando `now` para **meia-noite local** + `Math.round`:
```js
const today = parseLocalDate(formatLocalDate(now)) // meia-noite local, sem new Date() (R-020)
const daysLeft = Math.round((end - today) / MS_PER_DAY)
```
- `end_date === hoje` → `daysLeft = 0` → 'vencendo' (válida), não 'vencida'.
- Extrair `MS_PER_DAY` como constante nomeada (evita número mágico).
- NÃO usar `new Date()` no core (R-020) — usar `formatLocalDate`+`parseLocalDate` do `@dosiq/core`.

**Regra geral:** alertas diários, cron jobs e janelas de N-dias comparam DATAS (meia-noite local),
nunca `Date.now()` sobre janelas de 24h. Família R-020/timezone, [[parseLocalDate]].
Detectado também latente: o código original em `Stock.jsx` carregava o mesmo bug — carve-out + teste o expôs.
