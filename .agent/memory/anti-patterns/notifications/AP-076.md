# AP-076 — Silent Mode Gate em L1 (Layer Boundary Violation)

Filtrar usuários `notification_mode='silent'` na query de L1 antes de invocar o dispatcher corta o pipeline inteiro — a notificação não chega ao inbox do app.

## Padrão incorreto

```js
// L1 — _reminderHelpers.js ou _adherenceHelpers.js
const eligibleUsers = users.filter(u => u.notification_mode !== 'silent') // ERRADO
// ou
.neq('notification_mode', 'silent')  // ERRADO
```

## Padrão correto

L1 passa todos os usuários (exceto `digest` quando o mecanismo substitui a notificação).
L3 (`checkGatePolicy` → `shouldSendNow`) suprime canais e loga `status='silenciada'`:

```js
// L1 — inclui silent users; exclui apenas digest quando aplicável
const eligibleUsers = users.filter(u => u.notification_mode !== 'digest')

// L3 — dispatcher/checkGatePolicy lida com silent:
// shouldSendNow({ mode: 'silent' }) → false → isSuppressed = true
// logNotificationEvent → status: 'silenciada' → aparece no inbox
```

**Why:** `silent` = "não dispara push/telegram, mas mostra no inbox". Cortar em L1 quebra o contrato de inbox. Apenas `digest` mode justifica exclusão em L1 porque tem mecanismo de entrega substituto.

**How to apply:** Sempre que adicionar query de usuários em L1 para qualquer tipo de notificação, verificar se o filtro é de TIMING (correto em L1) ou de CANAL/MODO (pertence ao L3). Relacionado a [[R-220]], [[AP-075]].
