## Anti-Pattern

Destruturar propriedades como `user` ou `session` diretamente de chamadas assíncronas do Supabase (`supabase.auth.getUser()`, `supabase.auth.getSession()`) assumindo que o objeto `data` sempre existe.

```javascript
// ❌ BUG: Se a chamada falhar ou não houver dados, lança TypeError: Cannot read properties of null (reading 'user')
const { data: { user } } = await supabase.auth.getUser();
```

Se a requisição falhar (por exemplo, erro de rede, token expirado, etc.), `supabase.auth.getUser()` ou `getSession()` pode retornar `{ data: null, error: ... }`. Nesse caso, a destruturação direta causa uma exceção em runtime no JavaScript/React, quebrando o fluxo da UI.

## Exemplo Real (sprint feedbacks 023)

No painel de admin e no formulário de feedback do mobile, a obtenção do usuário destruturava diretamente a propriedade `user` aninhada no `data`:

```javascript
// No código do admin:
const { data: { user } } = await supabase.auth.getUser();
```

Em casos de sessão nula ou expirada, isso causava falha catastrófica antes mesmo do tratamento adequado do erro do Supabase.

## Solução Correta

Sempre desestruture primeiro o nível de `data` e use encadeamento opcional (`data?.user` ou `data?.session`) para acessar o valor com segurança.

```javascript
// ✅ Correto: seguro contra data nulo ou erro
const { data, error } = await supabase.auth.getUser();
const user = data?.user;

if (error || !user) {
  // Tratar o caso de erro ou usuário não autenticado de forma amigável
}
```
