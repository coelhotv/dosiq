## Problema

Um pacote necessário em runtime (ex: `ws` para `realtime-js`) estava instalado apenas como dep transitiva. Em monorepos com hoisting (npm workspaces), deps transitivas podem ser removidas, rebaixadas de versão ou não resolvidas corretamente num `npm install` futuro — sem aviso. O ambiente local mascara o problema (Node 22+ tem WebSocket nativo; `ws` presente via hoisting do workspace mobile).

## Por que não é óbvio

- `npm install` bem-sucedido não garante que deps transitivas sejam mantidas em versão compatível
- Ambientes diferentes (local vs Vercel Node 20) resolvem hoisting diferente
- Não aparece em `npm audit` nem em type-check

## Fix

Qualquer pacote que seja pré-requisito de runtime de um módulo importado no servidor deve ser dep **direta**:

```json
// package.json (raiz ou workspace server)
"dependencies": {
  "ws": "^8.21.0"
}
```

## How to apply

Antes de fazer deploy de qualquer nova lib com sub-deps de runtime (WebSocket, fetch polyfill, crypto), verificar se os sub-deps estão em `dependencies` do workspace correto. Ver [[AP-210]] (o contexto específico de supabase+ws).
