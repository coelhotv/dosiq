# AP-217 — Reescrever função SQL existente a partir do spec, sem diff contra `pg_get_functiondef` ao vivo

**Layer**: warm · **Category**: infra_and_deploy · **Created**: 2026-06-07
**Trigger count**: 1 · **Pack**: infra-api, schema-data

## Sintoma
Plano de migração (022 Fase A) propôs o corpo de `consume_stock_fifo` escrito **a partir da intenção da spec**, não a partir da função real em produção. Diff contra `pg_get_functiondef` (C1/T001) expôs 3 regressões silenciosas que lint/testes web **não** pegariam:

1. **G1 — caller omitido / overload fantasma.** Plano assumiu 1 função; DB tinha **2 overloads** (3-arg `auth.uid()` + 4-arg `p_user_id`). Caller `conversational.js` usava a 3-arg, ausente da lista do plano (classe [[AP-215]] — read/caller path faltando).
2. **G2 — filtro perdido.** Corpo real filtra `entry_type != 'legacy_unrecoverable'` (SUM + loop); o reescrito omitia → consumiria estoque irrecuperável.
3. **G3 — guard de posse perdido.** Real valida `medicine_logs` (log↔user↔medicine) antes de consumir; reescrito omitia.

Também mudava FIFO `purchase_date`→`expiration_date` sem decisão explícita (afeta sólidos).

## Causa
Specs descrevem **comportamento desejado**, não o corpo vigente. Reescrever `CREATE OR REPLACE` de cor descarta invariantes acumuladas (filtros, guards, overloads, ordenação) que não estão na spec.

## Correção / Regra
Antes de `CREATE OR REPLACE` de função existente:
1. `SELECT pg_get_functiondef(oid)` de **todos** os overloads (`pg_proc WHERE proname=...`) — confirmar quantos existem.
2. Diff linha-a-linha real vs proposto; toda divergência é decisão consciente (filtro/guard/ordenação/grant) ou regressão.
3. Grep callers e confirmar **qual overload** cada um usa (args nomeados) — [[AP-215]].
4. Testar a migration completa em transação `BEGIN … ROLLBACK` no DB ao vivo (DDL + dados + função + cenário funcional) antes de aplicar — prod intocado, asserts reais.

## Evidência
022 Fase A, projeto kwqjtdsqkkbebfiaxubb. Resolvido em `analysis.md` (C1 Reality Check) + decisões D1 (DROP 3-arg + migrar caller) / D2 (manter FIFO). Teste transacional: líquido 15 gotas→0.75ml multilote, sólido linear, migração ml→0, overloads pós-DROP=1 — todos PASS.
