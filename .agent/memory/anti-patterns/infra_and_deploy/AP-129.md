# AP-129 — Node.js ESM Rejeita Imports Sem Extensão .js

Em ambientes Node.js ESM puro (como Vercel), imports relativos sem extensão `.js` falham com `ERR_MODULE_NOT_FOUND`.

## Sintoma

```
Error [ERR_MODULE_NOT_FOUND]: Cannot find module '/var/task/packages/core/src/schemas/medicineSchema'
imported from /var/task/packages/core/src/schemas/validationHelper.js
```

Ou mais genérico:
```
Cannot find module '/path/to/file'
```

## Causa

Node.js ESM (CommonJS não) requer extensão explícita em imports relativos. Funciona em:
- **Vite dev/build**: module resolution faz fallback automático
- **Jest/Vitest local**: extensões preenchidas por loader Node.js

Falha em:
- **Vercel runtime**: Node.js puro, sem loader ESM customizado
- **CI/CD que roda Node.js direto**: mesmo problema

## Padrão de Erro no Código

```javascript
// ❌ ERRADO — falha em Vercel
import { validateMedicineCreate } from './medicineSchema'
import { x } from '../utils/dateUtils'
import { y } from '@dosiq/core/schemas'  // sem /arquivo.js

// ✅ CORRETO — funciona em qualquer contexto ESM
import { validateMedicineCreate } from './medicineSchema.js'
import { x } from '../utils/dateUtils.js'
import { y } from '@dosiq/core/schemas'  // barrels (index.js) não precisam de extensão
```

## Fix

Adicionar `.js` a TODOS os imports relativos:

```diff
-import { validateMedicineCreate } from './medicineSchema'
+import { validateMedicineCreate } from './medicineSchema.js'

-import { validateProtocolCreate } from './protocolSchema'
+import { validateProtocolCreate } from './protocolSchema.js'
```

**Exceção**: Barrels (index.js) e imports de package exports não precisam (já resolvidos por package.json exports field).

## Como Detectar

```bash
# Grep por imports sem extensão em arquivos .js
grep -r "from '\./[^']*'" --include="*.js" | grep -v "\.js'" | head -20
```

## Por que Acontece

Node.js ESM implementa strict module resolution (WHATWG URL spec). Vite/Jest estendem isso com extensão automática; Node.js puro não. Vercel usa Node.js puro em runtime.

**W03**: Código roda localmente (dev com Vite), falha em Vercel (ESM Node.js).

## Incidentes Relacionados

- [AP-128] (wildcards em exports) — mesmo domínio, problema de resolução package-level vs file-level

## Lição

Sempre resolver `from '...'` com extensão explícita em arquivos .js ESM. Ferramentas locais escondem o erro; CI/Vercel expõe.
