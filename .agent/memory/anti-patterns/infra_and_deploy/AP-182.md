# AP-182 — `node-cron` em `server/` não dispara em produção

## Sintoma
Trabalho agendado registrado via `cron.schedule(...)` (node-cron) em
`server/index.js` / `server/bot/scheduler.js` **funciona em DEV local** (processo
Node persistente) mas **nunca dispara em produção**.

No PR-F2.2 o motor de geração de `dose_instances` foi cabeado assim
(`startDoseInstanceGeneration` → `cron.schedule('15 3 * * *', ...)`). Em prod, o
cron diário e a limpeza de pausados ficaram mortos — só o hook da factory
(create/edit de protocolo) e a rede lazy gerariam instâncias.

## Causa
Na Vercel, `server/` **não roda como processo persistente** — é importado como
módulos pelas funções `api/*`. Funções serverless são **efêmeras**: morrem após
cada request, então `cron.schedule` nunca chega a disparar. `server/index.js` não é
sequer uma função `api/` → nunca é invocado em prod.

O cron real de produção é **`api/notify.js`**, pingado a cada minuto pelo
**cron-job.org** (Bearer `CRON_SECRET`), com tarefas diárias **gated por hora**
dentro de `_executeCronJobs` (`if (currentHour === N && currentMinute === 0)`).
Está documentado em `api/CLAUDE.md` (seção "Cron Jobs").

## Como aplicar (regra)
Trabalho agendado novo DEVE ter um caminho de **produção serverless**, não só node-cron:
- **Opção piggyback:** adicionar ao `_executeCronJobs` de `api/notify.js`, gated por
  hora. ⚠️ compartilha o invoke de 60s com os reminders (caminho crítico) — só para
  trabalho leve e tolerante.
- **Opção isolada (preferida p/ trabalho pesado):** endpoint dedicado
  (`api/<job>.js`) com agendamento próprio no cron-job.org + `CRON_SECRET`. Isola o
  raio de impacto (não rouba tempo dos reminders). Ver [[ADR-051]].
- Manter o node-cron em `server/bot/scheduler.js` é OK **apenas** como paridade de
  DEV — nunca como o caminho de prod.
- Configurar o agendamento no cron-job.org é passo **humano** (externo ao repo) —
  documentar no PR.

## Detecção
Ao adicionar `cron.schedule`/`scheduleTask` em `server/`, perguntar: "isto tem uma
entrada correspondente em `api/` disparada por cron-job.org?". Se não, o job é
dev-only. Relacionado a R-090 (budget de funções) ao optar pelo endpoint dedicado.
