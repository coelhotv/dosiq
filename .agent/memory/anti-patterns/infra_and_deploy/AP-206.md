# AP-206 — Gate de push server-side não é smoke-testável on-device pré-deploy

**Layer:** warm · **Status:** active · **Pack:** infra_and_deploy / notifications
**Detectado:** Spec 001 (Alarme Nativo) A2, gate de duplicata, 2026-06-03

## Sintoma

Implementado o gate que suprime o push de dose pra devices com alarme nativo ON
(flag no DB + filtro no `expoPushChannel`). No device, a notificação **ainda
chega dobrada** (alarme local + push remoto). Parece bug do gate.

## Causa

O gate é **server-side** e o push de dose **nasce da prod** (`api/notify` cron
rodando em `main`). O filtro novo está na **branch**, não deployado. A prod roda
o código antigo → ignora o flag → o push do próprio device ainda sai → duplica.

A flag no DB estava **correta** (`native_alarm_enabled=true` confirmado via SQL);
o mobile sincroniza certo. Só o **consumidor** (canal de envio) está desatualizado.

## Lição

Supressão/roteamento de notificação cujo **disparo origina na prod** (cron/serverless)
**não tem como ser validada on-device antes do merge+deploy**. Não confundir
"ainda dobra no smoke" com bug de código.

- **Validar por unit test** (`expoPushChannel` filtra device flagged p/ kind de
  dose; não-dose passa; multi-device).
- A dedup on-device só aparece **pós-deploy** do canal.
- Checklist de smoke deve marcar isso como "verificável só pós-deploy", separando
  do que é testável localmente (flag no DB, sync mobile).
