# AP-274 — Island strict-A importando nível-B arrasta subárvore não-tipada pro compile strict

**Categoria**: infra_and_deploy
**Detectado**: 043 Slice A (2026-07-10)
**Relaciona**: R-283 (ratchet strict-island), R-284 (cross-program), R-279 (composição)

## Sintoma

`scripts/strict-island.sh` fica vermelho num commit que **só adicionou arquivos nível-A limpos**:

```
❌ CATRACA ESTOURADA — B server/*: 63 > teto 36
```

A "✅ fonte nível A strict-limpa" passa — o estouro é no bucket **B**, +27 erros
`TS7006` (implicit any) em arquivos que o autor **nem tocou** (`_adherenceHelpers.ts`,
`notificationHelpers.ts`, `notificationDeduplicator.ts`, `dateUtils.ts`).

## Causa

Um arquivo do island strict-A (`server/notifications/outbox/runOutboxCycle.ts`, incluído no
`tsconfig.strict.json`) **importou** um arquivo nível-B não-tipado
(`server/bot/_adherenceHelpers.ts`). O `tsc -p tsconfig.strict.json` type-checa
transitivamente todo import → a subárvore B inteira, que antes **não era compilada por nenhum
programa strict**, passa a ser contada no bucket `B server/*`. +27 erros de uma vez.

O erro não é "meu código A tem any" — é "meu import A→B revelou a dívida B pré-existente
dentro de um compile mais estrito".

## Fix — inverter a dependência (DI)

O island A **nunca importa B**. O consumidor nível-B (aqui `api/notify.ts`, programa api,
já cheio de `any`) monta o registry e **injeta** por parâmetro:

```ts
// api/notify.ts (nível B) — importa os builders B e injeta
const OUTBOX_CONTENT_BUILDERS = { daily_adherence: ({userId,settings}) => buildDailyAdherenceData(...) };
await runOutboxCycle({ ..., contentBuilders: OUTBOX_CONTENT_BUILDERS });

// server/notifications/outbox/runOutboxCycle.ts (nível A) — recebe, não importa
export async function runOutboxCycle({ contentBuilders, ... }: { contentBuilders: Partial<Record<string, ContentBuilder>>; ... })
```

Resultado: `B server/*` volta a 36, island A segue limpo.

## Guard

- Arquivo em `server/notifications/` (ou qualquer dir do `A_SRC` do strict-island) importa
  **apenas** outros A ou tipos puros. Dependência lógica A→B vira **injeção** a partir do caller B.
- Ao adicionar arquivo A que precisa de lógica que vive em B: parametrize, não importe.
- Regra de bolso: se `strict-island.sh` estoura o bucket B logo após adicionar arquivo A,
  procure um import A→B antes de tentar tipar a dívida B (esta seria queima de dívida fora de escopo).
