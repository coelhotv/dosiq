# AP-275 — Tabela server-internal nasce com grants anon/authenticated (default privileges legados)

**Categoria**: infra_and_deploy
**Detectado**: 043 Slice A (2026-07-10, verificado em prod via MCP)
**Relaciona**: AP-183 (least-privilege fail-closed), R-090

## Sintoma

Migração cria tabela server-internal, comentário diz "nenhum grant a anon/authenticated
(novas tabelas pós-30/10 não recebem grants — CLAUDE.md)". Verificação LIVE após aplicar:

```sql
SELECT grantee, string_agg(privilege_type, ',')
  FROM information_schema.role_table_grants
 WHERE table_schema='public' AND table_name='notification_outbox' GROUP BY grantee;
-- anon          | TRIGGER,INSERT,SELECT,UPDATE,DELETE,TRUNCATE,REFERENCES
-- authenticated | INSERT,SELECT,UPDATE,DELETE,TRUNCATE,REFERENCES,TRIGGER
-- postgres | ...  service_role | ...
```

anon E authenticated receberam grants completos — o oposto do que a migração assumiu.

## Causa

O projeto dosiq (prod) tem **default privileges legados** (`ALTER DEFAULT PRIVILEGES ... GRANT
... TO anon, authenticated`) que se aplicam a TODA tabela nova do schema `public`. A nota da
CLAUDE.md ("a partir de 30/10/2026 novas tabelas não recebem grants automáticos") **NÃO reflete
o estado real deste banco** — os defaults continuam concedendo.

RLS habilitada SEM policy nega as linhas para anon/authenticated (o dado fica seguro na prática),
mas o grant existir é um furo de defense-in-depth e reprova PO-SEC-2 na letra ("zero grant").

## Fix

Em toda tabela server-internal, **REVOKE explícito** logo após o CREATE — não confiar na premissa:

```sql
ALTER TABLE public.<tabela> ENABLE ROW LEVEL SECURITY;
GRANT SELECT, INSERT, UPDATE, DELETE ON public.<tabela> TO service_role;
REVOKE ALL ON public.<tabela> FROM anon;
REVOKE ALL ON public.<tabela> FROM authenticated;
```

E **verificar LIVE** (`role_table_grants`) depois de aplicar — a única prova é a query, não o SQL escrito.

## Guard

- Toda migração de tabela server-internal: par `GRANT service_role` + `REVOKE ALL FROM anon/authenticated`.
- Fechar PO de grants SEMPRE por query live `information_schema.role_table_grants`, nunca por leitura do SQL.
- Suspeitar de qualquer comentário "não recebe grant automático" — validar contra o banco real.
