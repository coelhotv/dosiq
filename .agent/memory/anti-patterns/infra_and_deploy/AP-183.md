# AP-183 — Auth de cron sem guarda de presença do segredo (bypass via "Bearer undefined")

**Categoria:** infra_and_deploy
**Severidade:** High (security)
**Detectado:** 2026-05-29 (Gemini Code Assist, PR #604)
**Status:** corrigido

## Sintoma

Validador de cron compara o header de Authorization diretamente contra uma env var via template literal:

```javascript
const authHeader = req.headers['authorization']
if (authHeader !== `Bearer ${process.env.CRON_SECRET}`) {
  return res.status(401).json({ error: 'Unauthorized' })
}
```

Se `process.env.CRON_SECRET` **não estiver configurado** (`undefined`), a comparação vira:

```
authHeader !== "Bearer undefined"
```

Qualquer requisição enviando o header literal `Authorization: Bearer undefined` passa na validação → **bypass total da autenticação**. O endpoint roda com `service_role` (ignora RLS), então o blast radius é o motor inteiro.

## Causa raiz

Falha-aberto: a ausência do segredo deveria negar acesso (fail-closed), mas a coerção `${undefined}` → `"undefined"` transforma o segredo ausente numa senha previsível e pública.

## Correção

Verificar presença do segredo **antes** de comparar (falha-fechado):

```javascript
const authHeader = req.headers['authorization']
const cronSecret = process.env.CRON_SECRET
if (!cronSecret || authHeader !== `Bearer ${cronSecret}`) {
  return res.status(401).json({ error: 'Unauthorized' })
}
```

Aplicado em `api/generate-doses.js` (PR #604) e `api/notify.js` (mesma classe latente, endurecido no mesmo commit `ce4892d2`).

## Regra geral

Qualquer validador que compare entrada do usuário contra uma env var deve **falhar-fechado** quando a env var está ausente. Padrão: `if (!secret || input !== secret)`. Vale para Bearer tokens, webhook secrets, API keys.

Varredura de detecção: `grep -rn 'Bearer \${' api/ server/`. Distinguir **validadores** (comparam header de entrada — vulneráveis) de **headers outgoing** (setam Authorization pra chamar serviço externo — não vulneráveis).
