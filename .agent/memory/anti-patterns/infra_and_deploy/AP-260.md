# AP-260 — Script de migração reescreve imports fora do domínio e a sessão commita

**Domínio**: infra_and_deploy · **Descoberto**: 2026-07-03 (040 F2, commit 434144e) · **Severidade**: alta

## Sintoma

Durante a migração TS (040 F2), o `migrate-domain.sh` reescreveu specifiers de import em ~30 arquivos **fora do domínio da sessão** (api/, server/, apps/web) por colisão de basename (`dateUtils.js` existe em dois lugares). A sessão 2.6 commitou essas mudanças "porque já estavam feitas" (434144e), removendo a extensão `.js` de imports relativos em código Node ESM puro.

## Consequência

`ERR_MODULE_NOT_FOUND` em runtime em 32 arquivos de api/ e server/ (bot Telegram, cron notify, DLQ) — **invisível pro vitest**, porque Vite resolve import extensionless e Node ESM não. Detectado só no gate F2 (review Fable) via smoke `node --input-type=module -e "import(...)"`. Corrigido em 4808b6ca.

## Regra de prevenção

1. Pós-script, `git diff --name-only` filtrado pelo path do domínio: qualquer arquivo fora → `git checkout --` neles, **nunca commitar**; anotar no PR que o domínio X precisa de sessão própria.
2. Sessão que tocar server/ ou api/ (mesmo indiretamente): smoke Node ESM obrigatório antes do commit (ver [[R-282]]).

## Emenda (078 Slice 2, 2026-09-04) — a 2ª instância, e o que ela acrescenta

Mesma classe, outro escritor: o modo `--lifecycle` do `migrate-memory-frontmatter.mjs` tinha
mandato para 2 linhas (`incident_count`/`last_referenced`) em 611 arquivos de memória, e a via DRY
— reserializar o frontmatter com `js-yaml` — **reformatava 18 arquivos** de brinde (`summary`
escalar longo aspeado virava bloco dobrado `>-` em R-295, AP-300, AP-345/346…). Nada quebrava, o
diff era cosmético, e é exatamente por isso que passaria: num PR de 611 arquivos ninguém lê 18
reformatações.

O que a 2ª instância acrescenta à regra de prevenção: **`git diff` pós-script é tarde demais quando
o lote é grande** — a checagem tem de estar DENTRO do escritor, comparando antes/depois com as
linhas do mandato removidas dos dois lados, e o arquivo divergente é **pulado**, não corrigido "de
brinde". E a escolha de mecanismo segue disso: escrita de mandato estreito **patcha o TEXTO**
(substituição no lugar), não reserializa a estrutura — reserializar devolve o arquivo inteiro
reescrito e transforma qualquer diferença do serializador em mudança sua. Medido: com o patch de
texto, 611/611 escritos e **0 linhas** fora de `incident_count`/`last_referenced`.

**Farol:** escritor em lote que faz `parse → mutar → serializar` sobre arquivo que **humano
formatou**. O round-trip só é seguro quando o formato do arquivo já é saída do próprio
serializador — e num acervo com histórico, nunca é para todos.
