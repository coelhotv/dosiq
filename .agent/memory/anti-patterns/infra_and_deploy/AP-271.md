# AP-271 — Glob sem âncora em ignore file exclui diretórios homônimos aninhados

**Domínio**: infra_and_deploy · **Descoberto**: 2026-07-08 (040 F6 fechamento, PR #731 — deploy quebrado) · **Severidade**: alta (deploy down, erro só aparece no ambiente remoto)

## Sintoma

`.vercelignore` tinha `scripts/` (sem âncora). A intenção era excluir só o `scripts/` da raiz, mas a semântica gitignore-like casa o padrão em QUALQUER nível — `packages/core/scripts/` foi removido do upload. O `prepare` do core (`npm run build` → `node scripts/fix-dts-extensions.mjs`) quebrou o `npm install` na Vercel com `MODULE_NOT_FOUND`, num arquivo que existia no commit e funcionava em qualquer ambiente local/CI que clona o repo inteiro.

## Por que escapou

Ignore file só age no upload da Vercel — nenhum gate local (build, testes, strict-island, CI GitHub) exercita essa exclusão. O primeiro sinal foi o deploy FAILURE do preview.

## Regra de prevenção

1. Em `.vercelignore`/`.dockerignore`/etc., padrão de diretório que deve valer só na raiz SEMPRE com âncora: `/scripts/`, não `scripts/`.
2. Ao criar arquivo novo dentro de um diretório com nome "comum" (scripts, dist, data, docs) que participa de build remoto, grep o nome do dir nos ignore files do repo antes do push.
3. Diagnóstico rápido: arquivo existe no commit mas `MODULE_NOT_FOUND` só na Vercel → suspeitar de ignore de upload, não de git.
