# AP-238 — Path alias vive em 2 configs (vite + eslint), atualizar só um quebra lint

**Categoria:** infra_and_deploy · **Detectado:** 038 Slice A (2026-06-22)

## Sintoma
Após `git mv` de uma pasta com path alias (`@settings` → `views/redesign/settings`), atualizar só o `vite.config.js` deixou 7 `import-x/no-unresolved` no lint. O resolver do ESLint tem seu **próprio** mapa de aliases em `eslint.config.js`, independente do vite.

## Causa
Aliases de path no dosiq são declarados em DOIS lugares:
- `apps/web/vite.config.js` (runtime/build)
- `eslint.config.js` (resolver `import-x/no-unresolved`, ~linha 50-71)

Mover/renomear o destino de um alias exige atualizar AMBOS. Lint passa a ser o único gate que pega — build e testes resolvem pelo vite e ficam verdes, mascarando.

## Fix / Prevenção
Ao mover qualquer pasta apontada por alias (`@settings`, `@medications`, etc.):
1. `grep -rn "<old-path>" vite.config.js eslint.config.js` — atualizar os dois.
2. Rodar `rtk lint` (não só build/test) como gate — é o único que valida o resolver eslint.

Relacionado: AP-H27 (git mv quebra import relativo), R-117 (manualChunks paths).
