## Sintoma

Após adicionar um entitlement no `app.config.js` (ex.: `ios.associatedDomains`),
`npx expo run:ios --device` falha com:

```
❌ Provisioning Profile "iOS Team Provisioning Profile: com.coelhotv.dosiq"
   does not support the Associated Domains capability.
❌ Entitlements file defines the value "com.apple.developer.associated-domains"
   which is not registered for profile ...
CommandError: Failed to build iOS project. "xcodebuild" exited with error code 65.
```

## Causa

O provisioning profile é um **snapshot** das capabilities do App ID no momento em
que foi gerado. O profile automático ("iOS Team Provisioning Profile") em cache no
Mac é **anterior** ao entitlement → não o inclui. Habilitar a capability no App ID
(Apple Developer portal) **não** atualiza retroativamente o profile já em cache;
o build local reusa o stale.

> EAS builds não sofrem disso: o EAS chama a API da Apple e **regenera** o profile
> com as capabilities a cada build. O problema é específico do build local
> (`expo run:ios` / Xcode com profile cacheado).

## Correção

```bash
# apaga profiles cacheados → Xcode/expo regeneram um novo já com a capability
rm -rf ~/Library/MobileDevice/Provisioning\ Profiles/
npx expo run:ios --device
```

Se o CLI não re-assinar, forçar via Xcode (mais confiável):
`ios/Dosiq.xcworkspace` → target → **Signing & Capabilities** → desmarcar e
remarcar **"Automatically manage signing"** (descarta o profile velho, gera fresco).

Pré-condição: a capability precisa estar habilitada no App ID
(Apple Developer → Identifiers → `com.coelhotv.dosiq`).

## Onde apareceu

PR #585 (UL-S1) adicionou `associatedDomains: ['applinks:dosiq.app']`. O UL tinha
sido validado via build EAS/TestFlight (que registra a capability), mas o primeiro
`expo run:ios` local depois disso falhou com erro 65 — profile local stale.
Resolvido apagando a pasta de profiles + regerando no Xcode.
