# AP-264 — Dependência de workspace em package standalone quebra `npm ci --prefix` isolado

**Domínio**: infra_and_deploy · **Descoberto**: 2026-07-04 (040 F3, CI smoke) · **Severidade**: média

## Sintoma

Sessão 3.3 adicionou `@dosiq/core` e `@dosiq/shared-data` às `dependencies` de `server/package.json` (formalizando os imports do código). Mas `server/` NÃO é workspace npm — o CI roda `npm ci --prefix server` isolado, e o npm foi buscar o pacote privado no registry: `404 Not Found - @dosiq/core@*`.

## Consequência

Job de smoke do CI vermelho no PR. Segundo efeito em cascata: `scripts/smoke-server.mjs` (Node puro) importava fontes `.js` do server que viraram `.ts` — Node não importa `.ts`.

## Regra de prevenção

1. Package standalone (fora de `workspaces` do root) NÃO declara deps de pacote privado do monorepo — em runtime resolve via `node_modules` do root por lookup ancestral de diretórios.
2. Antes de mexer em `dependencies` de um package: conferir se ele é workspace (`npm ls --workspaces`) e se algum job de CI o instala isolado (`--prefix`/`working-directory`).
3. Smoke de código `.ts` roda sob o runtime real do serviço (tsx pro server) — mas ver AP-263: tsx não valida extensão.
