# AP-261 — Exports órfãos em package.json mascaram o type-checking ("verde ilusório")

**Domínio**: infra_and_deploy · **Descoberto**: 2026-07-03 (040 F2, gate Fable) · **Severidade**: alta

## Sintoma

Ao migrar um package pra TS (rename `.js`→`.ts`), os `exports` do `package.json` seguem apontando pro `.js` inexistente. Duas falhas mascaradas, com sintomas TARDIOS e distantes da causa:

1. **tsc**: imports de `@dosiq/<pkg>` resolvem como `any` silencioso → strict island "verde" que não checa nada. Quando os exports foram corrigidos (b9086ec), 949 erros reais apareceram de uma vez — o verde das sessões 2.3-2.5 era ilusório.
2. **eslint**: `import-x/no-cycle` estoura `Cannot find module` no CI (aconteceu 3× na fase: config na 2.2, shared-data na 2.3, config/design-tokens/storage no CI do PR #703 — fix e13a500).

## Regra de prevenção

Migrou package → **no MESMO commit** atualizar `main`/`exports` do `package.json` pra `.ts` e validar com um import real: `npx tsc --noEmit` num arquivo que importe o package via specifier `@dosiq/<pkg>` (não relativo). Gate por sessão: `./scripts/strict-island.sh` (contagem de dívida despencar/zerar = red flag de resolução `any`).
