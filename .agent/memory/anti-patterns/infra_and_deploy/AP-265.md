# AP-265 — Rename em massa não varre globs de configs de teste/CI

**Domínio**: infra_and_deploy · **Descoberto**: 2026-07-05 (040 F4, CI smoke) · **Severidade**: média

## Sintoma

F4 renomeou todo `apps/web/src` para `.ts/.tsx`, mas 4 configs vitest mantinham `include: ['src/**/*.test.{js,jsx}']` (smoke/ci/lowram + exclude de coverage). CI remoto: `No test files found, exiting with code 1`.

## Por que escapou

`validate:agent` (gate da fase) usa a config default, cujos globs pros testes rodados já estavam corretos — passou verde. Configs alternativas (smoke, ci com coverage, lowram) só rodam em jobs remotos específicos; nenhum gate local as exercita. Mesma classe de furo: refs literais `src/main.jsx`/`src/App.jsx` em excludes de coverage.

## Regra de prevenção

1. Rename em massa de extensão → grep obrigatório por padrões da extensão antiga em TODAS as configs de tooling: `grep -rn "{js,jsx}\|\.jsx'" *.config.* vitest* .github/workflows/` (análogo ao passo vercel.json da F3).
2. "No test files found" com exit 1 é o sintoma bom; pior seria glob parcial rodando subset silencioso — ao mexer em globs, conferir contagem com `npx vitest list --config X | wc -l` contra a config default.
3. Checklist de fase de migração deve incluir configs consumidoras (vitest*, playwright, lint-staged, workflows), não só código.
