## Descrição

Chamar `Notifications.getLastNotificationResponseAsync()` diretamente dentro de um `useEffect` que tem `session` como dependência provoca re-execução do handler de cold start toda vez que o usuário faz logout + login sem fechar o app. Resultado: navegação espúria para a tela da última notificação mesmo que o app já esteja aberto há minutos.

## Incidente

Sprint N1.4 — identificado pelo Gemini Code Assist na revisão do PR #499. A implementação inicial processava `getLastNotificationResponseAsync` a cada re-execução do `useEffect([supabase, session])`.

## Correção

Usar `useRef` como flag one-shot para garantir que o processamento ocorra apenas uma vez por ciclo de vida do app:

```js
const coldStartProcessed = useRef(false)

// Dentro do useEffect:
if (!coldStartProcessed.current) {
  coldStartProcessed.current = true
  const lastResponse = await Notifications.getLastNotificationResponseAsync()
  if (lastResponse && isMounted) {
    navigateFromPush(lastResponse.notification.request.content.data?.navigation)
  }
}
```

O `useRef` persiste entre re-renders e re-execuções do `useEffect` enquanto o componente estiver montado.

## Como evitar

Qualquer operação que deve ocorrer **apenas uma vez por ciclo de vida do app** (não por render/sessão) deve usar `useRef` como flag de controle, especialmente se estiver dentro de um `useEffect` com dependências que mudam em fluxos normais de uso (autenticação, sessão, configurações).
