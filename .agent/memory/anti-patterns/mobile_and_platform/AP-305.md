# AP-305 — Campo de contrato existe e valida, mas UM canal não o consome → feature "pronta" que não faz nada

**Detectado:** spec 029 F5 (T025), C2 gate 2026-07-18
**Relaciona:** [[AP-300]] · [[R-267]] · [[CON-030]]

## O padrão

`notificationPayloadSchema` tem `actions: z.array(actionSchema).default([])` desde o "Gate 4
preliminar". O schema valida, os builders preenchem, os testes de payload passam, e o campo
aparece no objeto de saída. **Só o canal Telegram (`channels/telegramChannel.ts:68`) lê esse
campo.** O `expoPushChannel` nunca emitiu `categoryId` nem ações — logo, para o mobile, `actions`
sempre foi um campo decorativo.

O F3 entregou o push do `medicine_switch` "com o payload certo" e o escopo herdado descrevia o
trabalho restante como "estender o `actionSchema` + o builder + a policy". Seguir essa descrição
ao pé da letra produziria: schema válido, builder correto, testes verdes — e **push sem botão
nenhum no aparelho**. O bug só apareceria no smoke em device real.

## Por que passa por todos os gates

Igual ao AP-300, mas do lado da SAÍDA: o contrato descreve uma capacidade que **nenhuma camada
downstream implementa**. `tsc` valida a forma do objeto; o teste do builder afirma que o campo
foi preenchido; o teste do canal não assertava ausência (não havia o que assertar). Nada no
pipeline pergunta *"quem consome isso?"*.

## Regra

**Campo de contrato que representa uma CAPACIDADE (ação, botão, deep link, anexo) só está
entregue quando existe um consumidor por canal/plataforma — e um teste que prova a emissão no
formato que a plataforma exige.**

Checklist ao adicionar/estender um campo desses:
1. `grep` o nome do campo nos consumidores (`channels/`, handlers de plataforma). Zero hits fora
   do schema = campo decorativo.
2. Para push: o par é sempre **`categoryId` (servidor) + registro da categoria (app)**. Um sem o
   outro entrega notificação sem botões, em silêncio — mesmo furo que o T015 fechou para o alarme
   (`ensureAlarmCategories`).
3. O teste do CANAL (não só o do builder) asserta o campo na mensagem final.
4. Se a capacidade nasce parcial de propósito, anotar no schema **qual canal ainda não consome** —
   senão o próximo slice a lê como pronta (foi o que aconteceu aqui, do F3 para o F5).

## Farol

Um campo de payload que nunca aparece em nenhuma assertion de teste de canal, e cuja feature
"já está no schema há slices", é candidato forte a decorativo.
