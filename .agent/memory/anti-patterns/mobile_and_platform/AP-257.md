# AP-257 — Supor que a iOS Live Activity transiciona/encerra sozinha sem app rodando JS

- **Domínio:** mobile
- **Detectado:** 2026-07-02 (spec 041 fix-up — bug prod v0.23.3: countdown congelado, `late` preso até swipe, registro não virava `done`)
- **Severidade:** alta (superfície de dose crítica mostra estado errado / não encerra)
- **Relacionado:** ADR-076 (emendada), CON-030, CON-029, AP-256

## Sintoma

Live Activity iniciada (foreground ou push-to-start) NÃO transiciona `upcoming→now→late` nem
encerra ao registrar a dose quando o app não está rodando JS. Countdown congela no zero; `late` fica
preso na lock screen até swipe manual; dose registrada não vira `Tomada ✓`.

## Causa-raiz

O widget recomputa o estado (`displayState`) **só em re-render**. `Text(timerInterval:)` anima os
dígitos mas NÃO re-renderiza a view → o estado derivado congela. Re-render em background depende de
**um único** `staleDate` (`ActivityContent`); depois que passa, nada mais transita. iOS **não roda
JS em background** → `deriveAndDrive`/`onDoseActivityRefresh` (que fariam update/end) não executam.

A premissa "transições degradam bem como na 039 (staleDate/foreground)" é **falsa**: a 039 nunca
entregou transição/encerramento sem o app vivo. Android não sofre — tem scheduler local encadeado
(Notifee `TimestampTrigger`) que roda sem JS.

## Fix

O servidor DEVE dirigir o ciclo de vida via push APNs (ActivityKit):
- **update** (`event:'update'`, token per-Activity) ao cruzar cada boundary de estado;
- **end** (`event:'end'`) quando a dose é resolvida (`taken`/`skipped`/`missed`).

Token per-Activity via `Activity.pushTokenUpdates` (≠ pushToStartToken), persistido efêmero em
`dose_instances.la_push_token`. Idempotência do update por `la_push_state`.

**Pegadinha (descoberta em prod 2026-07-02):** o token per-Activity só é emitido para o app EM
EXECUÇÃO e só existe APÓS a Activity ser criada. Logo, LA iniciada por **push-to-start com app
fechado** NÃO captura o token → server não consegue update/end → presa no estado inicial. O
"servidor dirige o ciclo" só vale quando o app abriu na janela e capturou o token (start local =
fluxo canônico do AK). App 100% fechado: só a transição única via `staleDate=próximo boundary`
(sem token). NÃO existe pré-geração de token para dose futura. Ver ADR-076 §Limitação.

## Guard

- Qualquer superfície contínua iOS (Live Activity) que precise transicionar/encerrar com app fechado
  DEVE ter um driver server-side (push) OU um mecanismo nativo agendado — nunca só `staleDate`+foreground.
- `staleDate` serve p/ 1 re-render pontual, não p/ máquina de estados multi-hop.

## Lição

"Degrada bem" não é análise — é suposição. iOS LA sem push é uma foto que re-renderiza no máximo 1×
por staleDate; qualquer transição/encerramento em background exige push (ou o app aberto). Validar o
ciclo de vida completo (não só o start) antes de declarar paridade com Android.
