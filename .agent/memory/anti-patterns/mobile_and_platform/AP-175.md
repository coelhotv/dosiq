# AP-175 — Autocomplete RN: foco dessincronizado mata a 2ª busca

**Classe:** mobile_and_platform · **Status:** warm · **Trigger count:** 1

## Sintoma
No FormAutocomplete: primeira busca OK, usuário seleciona um item, depois limpa
e digita de novo — o autocomplete **não carrega mais** sugestões.

## Causa
`handleSelect` faz `setFocused(false)`, mas o TextInput nativo **mantém o foco**
(`keyboardShouldPersistTaps="handled"` impede blur ao tocar a sugestão). Estado
`focused=false` enquanto o nativo segue focado. Usuário digita a 2ª busca direto
(teclado já aberto) → `onChangeText` dispara → effect de busca roda mas aborta em
`if (!focused) return`. `onFocus` não re-dispara porque o input nunca perdeu foco.

## Correção
Soltar o foco nativo no select via ref:
```js
const inputRef = useRef(null)
// <TextInput ref={inputRef} ... />
function handleSelect(item) {
  // ...
  setFocused(false)
  inputRef.current?.blur() // re-sincroniza: próximo tap re-dispara onFocus
}
```

## Onde aplicar
Qualquer input controlado que gate efeitos em estado `focused` próprio +
`keyboardShouldPersistTaps`.
