# AP-251 — smallIcon sem drawable regenerado crasha a notificação no device [HIGH]

## Anti-Pattern

```js
// ❌ ERRADO — ic_dosiq_mark referenciado mas nunca adicionado ao res/ do Android
await notifee.displayNotification({
  android: { smallIcon: 'ic_dosiq_mark', channelId, ... }
})
```

## Por que é um problema

Android EXIGE um small icon válido. Se o nome não resolve em `res/drawable`, o SO lança:

```
java.lang.IllegalArgumentException: Invalid notification (no valid small icon)
```

`notifee.displayNotification` rejeita. Em managed Expo o crash é DUPLO-silencioso:
1. `android/` é gitignored/efêmero — `expo prebuild` regenera do zero. Um drawable colocado à mão some no próximo prebuild/EAS se NENHUM config plugin o reescrever.
2. O callsite costuma estar dentro de `try/catch` com `if (__DEV__) console.warn(...)` → em build de produção (`__DEV__=false`) o erro é engolido. A feature inteira (superfície/card) NUNCA aparece, sem nenhum sinal.

Resultado (039/F2): a ongoing notification da superfície de estado contínuo nunca renderizava no device real (Xiaomi/HyperOS). O alarme funcionava por OMITIR `smallIcon` (cai no `ic_launcher` default). Diferença mascarava a causa.

## Fix

Versionar a geração do drawable via config plugin (`withDangerousMod` android), igual ao padrão iOS (`withDoseActivityBridge`/`withDoseLiveActivity` que sobrevivem ao `ios/` efêmero):

```js
// withDoseActivityAndroidIcon.js
const { withDangerousMod } = require('@expo/config-plugins')
module.exports = (config) => withDangerousMod(config, ['android', (cfg) => {
  const resDir = path.join(cfg.modRequest.platformProjectRoot, 'app/src/main/res/drawable')
  fs.mkdirSync(resDir, { recursive: true })
  fs.writeFileSync(path.join(resDir, 'ic_dosiq_mark.xml'), ICON_XML) // vector drawable mono
  return cfg
}])
```

Notas:
- Small icon Android é máscara alpha-only → drawable BRANCO (`#FFFFFFFF`); o SO tinge com o `color` da notificação (por-estado). Não embutir cor no drawable.
- Registrar o plugin em `app.config.js plugins[]` (RE-001: app.config.js é canônico).

## Diagnóstico (reproduzível)

```
adb -s <serial> logcat -d | grep -iE "no valid small icon|Invalid notification|DoseActivity"
# → "(NotificationAndroidModel): Notification small icon 'ic_dosiq_mark' could not be found"
```

`adb shell dumpsys notification --noredact | grep <surface>` confirma se a notif foi postada.
