# [AP-171] `Intl.NumberFormat` (moeda) não confiável no Hermes — usar formatação manual

## Description
Usar `Intl.NumberFormat('pt-BR', { style: 'currency', currency: 'BRL' })` em helper compartilhado web↔mobile (`@dosiq/core/utils/stock.formatBRL`). O Hermes (engine RN) não garante suporte completo a ICU, então a formatação de moeda pode renderizar incorretamente em dispositivo (símbolo, separadores ou casas erradas) — sem lançar erro, apenas saída errada.

## Why it's harmful
- **Falha silenciosa em device**: passa nos testes (Node/V8 tem ICU completo) mas renderiza errado no app — não é pego por CI.
- **Família AP-155 / R-199**: mesma raiz que `Intl.DateTimeFormat` no Hermes; aqui o sintoma é saída incorreta em vez de crash.

## Correct Approach
Formatação manual determinística (idêntica web↔mobile). Tratar o sinal **antes** do símbolo para preservar contrato (`-R$ 50,00`, não `R$ -50,00`).

## Example
### ❌ Wrong
```javascript
return new Intl.NumberFormat('pt-BR', { style: 'currency', currency: 'BRL' }).format(n)
```

### ✅ Right
```javascript
const sign = n < 0 ? '-' : ''
const [intPart, decPart] = Math.abs(n).toFixed(2).split('.')
const groupedInt = intPart.replace(/\B(?=(\d{3})+(?!\d))/g, '.')
return `${sign}R$ ${groupedInt},${decPart}`
```
