# [AP-141] Fragmentação de Resolução de IDs em Notificações Cross-Platform

## Sintoma
Notificações enviadas pelo backend (L1/L2) chegam ao Inbox (Web/Mobile) com chaves inconsistentes (`protocol_id` vs `protocolId`). Isso faz com que o CTA abra a modal correta mas não pré-selecione os medicamentos, ou falhe silenciosamente na navegação.

## Causa Raiz
Mismatch de convenção entre o banco de dados (snake_case: `protocol_id`) e o dispatcher de notificações (camelCase: `protocolId`). Sem um helper de normalização no consumidor, a interface falha ao tentar acessar a propriedade errada.

## Como Evitar (Fix)
Implementar um helper de resolução resiliente em todos os pontos de consumo de notificações.

```javascript
// Exemplo de helper resiliente (NotificationInboxScreen.jsx)
const _resolveProtocolIds = (data) => {
  const singleId = data?.protocol_id || data?.protocolId;
  const multiIds = data?.protocol_ids || data?.protocolIds;
  return { singleId, multiIds };
};
```
