# AP-248 — iOS nested Modal swallows DateTimePicker gestures [HIGH]

## Anti-Pattern

```jsx
// ❌ ERRADO — picker dentro de Modal secundário no iOS
<Modal visible={showPicker}>
  <DateTimePicker onChange={handleChange} mode="spinner" />
</Modal>
```

## Por que é um problema

No iOS, um `<Modal>` secundário renderizado dentro de outro `<Modal>` não recebe eventos de toque/gesto corretamente. O `onChange` do `DateTimePicker` nunca dispara — o usuário seleciona horário no spinner mas o valor não atualiza. Resultado: `taken_at` salvo como `now` em vez do horário escolhido (bug prod 039).

## Fix

Renderizar o picker como overlay absoluto **dentro** do mesmo Modal externo, sem segundo `<Modal>`:

```jsx
// ✅ CORRETO — overlay absoluto no mesmo Modal
const IOSDateTimePickerOverlay = ({ visible, value, onChange, onClose }) => {
  if (!visible) return null
  return (
    <View style={styles.pickerOverlay}>
      <DateTimePicker value={value} mode="datetime" onChange={onChange} display="spinner" />
      <TouchableOpacity onPress={onClose}><Text>OK</Text></TouchableOpacity>
    </View>
  )
}

// styles
pickerOverlay: {
  ...StyleSheet.absoluteFillObject,
  justifyContent: 'flex-end',
  zIndex: 10,
  elevation: 10,
}
```

Renderizado dentro do outer `<Modal>`, após o conteúdo principal.

## Incidente

PR #693, 2026-06-30. Doses bulk registradas com `taken_at = now` em vez do horário selecionado pelo usuário no spinner (23:47 → gravado como 01:05 do dia seguinte). 7 logs corrigidos no DB via Supabase MCP.
