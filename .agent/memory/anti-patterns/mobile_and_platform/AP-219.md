## Problema

`PanResponder` criado com `onStartShouldSetPanResponder: () => true` captura TODOS os eventos de toque, incluindo os destinados a `TouchableOpacity` e `Pressable` filhos. Resultado: cliques nos filhos são silenciosamente engolidos — sem feedback visual, sem disparo do `onPress`. Scroll vertical também é bloqueado se o `PanResponder` estiver num componente scrollável.

## Root Cause

`onStartShouldSetPanResponder: true` captura o evento no início do toque (`onStart`), antes que qualquer filho tenha chance de responder. O sistema de gestos do React Native resolve conflitos no sentido pai→filho: quem captura no `onStart` vence.

## Fix

```js
// ERRADO — bloqueia filhos:
const panResponder = PanResponder.create({
  onStartShouldSetPanResponder: () => true,
  onMoveShouldSetPanResponder: () => true,
  ...
})

// CORRETO — só captura swipe horizontal puro:
const panResponder = PanResponder.create({
  onStartShouldSetPanResponder: () => false,
  onMoveShouldSetPanResponder: (_evt, gestureState) => (
    Math.abs(gestureState.dx) > 10 && Math.abs(gestureState.dy) < 5
  ),
  onPanResponderRelease: (_evt, gestureState) => {
    if (gestureState.dx > 40) handleSwipeLeft()
    else if (gestureState.dx < -40) handleSwipeRight()
  },
})
```

`onStart=false` + `onMove` com threshold `dx>10 && dy<5` garante:
- Cliques normais passam para os filhos (dx pequeno, sem movimento)
- Swipes horizontais são capturados pelo PanResponder
- Scroll vertical não é interrompido (dy não é pequeno em scroll)

## How to apply

Sempre que adicionar `PanResponder` a um View que contém elementos interativos ou está dentro de um ScrollView: usar o padrão acima. Nunca usar `onStart=true` em componentes com filhos tapeáveis.
