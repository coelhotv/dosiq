## Sintoma

Usuário com push **negado** no SO toca em "Ativar", abre `Linking.openSettings()`,
concede a permissão nas Configurações do sistema e volta ao app. O toggle/estado
de permissão na tela continua **desatualizado** (segue "off"/"bloqueado") até
navegar para fora e voltar.

## Causa

`useFocusEffect` (React Navigation) dispara **apenas** em foco de navegação — ou
seja, quando a tela entra em foco dentro do stack/tab. Voltar do **background do
app** (retorno das Configs do SO, app switcher) é um evento de **foreground do
sistema**, não de navegação. A tela já estava focada; nenhum re-foco ocorre, logo
`useFocusEffect` não re-executa a checagem de permissão.

## Correção

Combinar **dois** gatilhos para re-checar permissão:

```js
// 1. foco de navegação (entrar na tela)
useFocusEffect(useCallback(() => { checkPermission() }, [checkPermission]))

// 2. foreground do app (voltar do background — ex.: Configs do SO)
useEffect(() => {
  const sub = AppState.addEventListener('change', (next) => {
    if (next === 'active') checkPermission()
  })
  return () => sub.remove()
}, [checkPermission])
```

Em `checkPermission`, detectar a transição negado→concedido (`getPermissionsAsync`,
nunca `requestPermissionsAsync` na checagem) e, ao detectar concessão, registrar o
token + ligar o canal (ver [[R-239]]).

## Onde apareceu

`apps/mobile/src/features/profile/screens/NotificationPreferencesScreen.jsx`
(PR #584, Fase 4). `wasGrantedRef` inicializado em `null` (não `false`) para que a
primeira checagem no mount não conte como transição e sobrescreva um OFF deliberado.
