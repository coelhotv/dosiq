# [AP-202] View do dia reusa fetch de janela larga sem filtrar ao dia local

**Status:** active · **Layer:** warm · **Domain:** mobile_and_platform
**Criado:** 2026-06-01 (PR-F4.3b) · **trigger_count:** 1

## Sintoma
A timeline do "Hoje" mobile renderizou ~5x as doses de cada tratamento (4 dias passados já marcados + 1 do dia). Pego no smoke PO antes do commit.

## Causa
`useTodayData` busca `getDoseInstancesForPeriod(user.id, 14)` — janela de 14 dias necessária para a **tendência de adesão** (curWindow vs prevWindow de 7d). Ao migrar a timeline para consumir essas instâncias (`buildDoseItemsFromInstances`), iterei `data.doseInstances` **inteiro** → a lista do dia passou a incluir as ocorrências dos 13 dias anteriores. O web não sofreu porque o dashboard busca janela só de hoje; o mobile **reusa** o fetch largo.

## Correção
Filtrar pelas fronteiras do **dia local** (tz) ANTES de montar a lista:
```js
const dayStart = parseISO(getStartOfDayISO(todayStr, tz)).getTime()
const dayEnd   = parseISO(getEndOfDayISO(todayStr, tz)).getTime()
const todayInstances = instances.filter((i) => {
  const t = parseISO(i.scheduled_for).getTime()
  return t >= dayStart && t <= dayEnd
})
buildDoseItemsFromInstances(todayInstances, protocols, tz)
```
As estatísticas seguem operando na janela larga (14d) — só a lista do dia é filtrada.

## Regra
Quando uma view **day-scoped** reusa um fetch de janela larga (feito para outro fim — agregação/tendência), filtrar explicitamente ao dia local antes de renderizar. Não assumir que "instâncias do contexto" == "instâncias de hoje".
