# AP-205 — Import pesado no entrypoint (pré-AppRegistry) crasha o cold start

**Layer:** warm · **Status:** active · **Pack:** mobile_and_platform
**Detectado:** Spec 001 (alarme nativo), emulador Android API 30, 2026-06-02

## Sintoma

App crasha no launch (erro rápido + crash), antes de qualquer tela. Visto no
emulador Android 11 (API 30) após registrar `notifee.onBackgroundEvent` no
`index.js`.

## Causa

`index.js` roda no **top-level do entrypoint, ANTES do `AppRegistry`** e antes
dos módulos nativos inicializarem. O handler de background importava
`quickDoseRegistration` no topo, que puxava a cadeia pesada
`doseService → supabase client + @react-native-firebase/analytics`. Esses
módulos, ao serem avaliados no cold start (pré-init nativo), crasham.

```js
// ERRADO — import pesado avaliado no entrypoint
import { handleAlarmAction } from './quickDoseRegistration' // → supabase + firebase
notifee.onBackgroundEvent(async (e) => { await handleAlarmAction(e) })
```

## Fix

No entrypoint, manter o topo **leve** (só notifee). **Lazy-require** a cadeia
pesada dentro do callback — só roda quando o SO entrega o evento, com o runtime
já pronto.

```js
import notifee, { EventType } from '@notifee/react-native'
notifee.onBackgroundEvent(async (event) => {
  if (event.type === EventType.ACTION_PRESS || event.type === EventType.DISMISSED) {
    const { handleAlarmAction } = require('./quickDoseRegistration') // lazy
    await handleAlarmAction(event)
  }
})
```

## Regra geral

Qualquer código importado pelo `index.js`/entrypoint (antes do `AppRegistry`)
deve ter grafo de import **mínimo**. Nada de supabase client, firebase, ou
services que tocam módulos nativos no top-level. Diferir via lazy `require` /
mover para dentro da árvore React (carrega após o AppRegistry montar).
