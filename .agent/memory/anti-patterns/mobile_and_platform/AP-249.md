## Sintoma

Superfície nativa nova (notificação ongoing Android F2; widget/Live Activity iOS F3)
renderiza um ícone **genérico "semântico"** — `Image(systemName: "drop.fill")` (gota =
medicação) — em vez da **marca dosiq** que o mock canvas especifica explicitamente.
PO pega no smoke ("mesma coisa que aconteceu com o Android").

## Causa raiz

Atalho mental: "medicação → gota → SF Symbol `drop.fill`". O ícone é escolhido **sem abrir
o mock** (`plans/mocks_app_mobile/.../Dosiq_Spec_039-Dose_State_Machine.html` →
`dosiq-mocks/dose-state-machine-screens.jsx`, componente `DosiqMark`). O mock é a fonte de
verdade de branding e usa a marca dosiq (arco "q" + check + dot) em TODAS as superfícies
(ilha minimal/compact/expanded + lock screen). O default só é descoberto no smoke porque o
build compila igual com qualquer ícone.

Recorrente no mesmo épico (Android F2 + iOS F3) → não é deslize pontual, é viés de processo.

## Fix

- Marca portada do **SVG canônico** `apps/web/public/dosiq-logo-mono.svg`
  (viewBox `130 103 600 600`, path único M/L/C/Z absolutos):
  - **RN**: `apps/mobile/src/shared/components/branding/DosiqLogo.jsx` (react-native-svg).
  - **Widget Swift** (não pode importar react-native-svg): `DosiqMark` como SwiftUI `Shape`
    com parser mínimo dos comandos M/L/C/Z do mesmo path
    (`apps/mobile/targets/dose-activity/DosiqMark.swift`). `DosiqMarkView` = fill + stroke
    leve (espelha `stroke-width:18` do SVG p/ legibilidade em tamanhos pequenos).

## Regra

Qualquer superfície que exiba branding (notificação, widget, Live Activity, splash, ícone
de canal) → **abrir o mock ANTES de escolher o ícone** e **reusar o path canônico**, nunca
um SF Symbol/asset genérico "semântico". Branding tem fonte única (`dosiq-logo-mono.svg`);
divergência é defeito, não estilo.

## Generalização (mesma raiz bateu 2x na sessão F3)

A falha NÃO é só do ícone — é **re-derivar a superfície da 2ª plataforma do zero em vez de
espelhar a 1ª já refinada**. No mesmo smoke F3 a apresentação re-derivada perdeu ajustes que
a F2 (Android, `doseActivitySurfaceService`) já tinha: título = **nome + dose** (não só nome),
**HH:mm agendado** junto do countdown, frases com "crítica", **cap CL-3** do count-up. Quando
uma feature ganha um gêmeo de plataforma (Android↔iOS), a superfície anterior + seu mock são a
**spec viva** — espelhar decisão por decisão (formatação, copy, janelas, caps), não reinventar.
Antes de codar a superfície gêmea: ler o service/UI da plataforma irmã E o mock, e listar os
ajustes a portar.
