# AP-138: Promise não-awaited em Linking event handler → crash via TurboModule

**Categoria:** mobile_and_platform  
**Severidade:** CRÍTICO — crash em produção (EXC_CRASH SIGABRT)  
**Detectado em:** TestFlight v0.3.3 build 303, 2026-05-10  
**Fix aplicado em:** fix/mobile-recovery-crash-web-forgot-password

## Descrição

Chamar `supabase.auth.setSession()` ou qualquer outro método assíncrono dentro de `Linking.addEventListener('url', handler)` ou `.getInitialURL().then(cb)` sem `await` e sem `try/catch` causa crash na app.

O problema: a Promise rejeitada (token expirado, URL malformada, SecureStore write failure) propaga pelo bridge TurboModule do React Native, onde C++ captura e relança a exceção via `ObjCTurboModule::performVoidMethodInvocation` → `abort()`.

## Sintoma

```
Exception Type: EXC_CRASH (SIGABRT)
Termination: SIGNAL 6 Abort trap
Thread 12: facebook::react::ObjCTurboModule::performVoidMethodInvocation (RCTTurboModule.mm:444)
```

Feedback TestFlight: "fechou o app apos clicar no link de recuperar senha"

## Causa Raiz

```javascript
// ❌ ERRADO — Promise não awaited, erro não capturado
function handleDeepLink({ url }) {
  supabase.auth.setSession({ access_token, refresh_token }) // fire-and-forget
}
```

## Fix

```javascript
// ✅ CORRETO — async handler com try/catch
async function handleDeepLink({ url }) {
  try {
    const { error } = await supabase.auth.setSession({ access_token, refresh_token })
    if (error) debugLog('Navigation', 'setSession falhou', error.message)
  } catch (e) {
    debugLog('Navigation', 'Exceção em setSession', e?.message)
  }
}
Linking.getInitialURL()
  .then((url) => { if (url) handleDeepLink({ url }) })
  .catch((err) => debugLog('Navigation', 'getInitialURL falhou', err?.message))
```

## Invariante

**Toda operação async dentro de Linking callbacks DEVE ter `await` + `try/catch`. Erros NUNCA relançados — apenas consumidos em JS via `debugLog`.**

Ver também: R-224 (regra de safe deep link handlers)
