## Sintoma

Console Expo / Metro spam de `WARN  Unsupported dashed / dotted border style` toda vez que o componente é renderizado/animado. Especialmente ruidoso quando o componente vive dentro de container animado via `LayoutAnimation` ou similar — RN re-avalia o style por frame, multiplicando o warning.

## Causa-raiz

React Native NÃO suporta `borderStyle: 'dashed'` ou `borderStyle: 'dotted'` em iOS/Android (apenas `'solid'`). Web aceita via CSS — daí o engano comum quando se traduz mock visual ou se copia código web.

## Detecção

```bash
grep -rn "borderStyle.*['\"]\(dashed\|dotted\)['\"]" apps/mobile/src
```

## Correção

Trocar `borderStyle: 'dashed'` por uma das alternativas:
- `borderStyle: 'solid'` + cor mais suave (ex: `primary[100]`) — mantém indicação visual
- Remover borda e usar gap/padding/divisor
- SVG inline desenhando dashes (custo: complexidade)

## Caso real

Fase 2 T1.5 — `TreatmentsScreen.addToGroup` (link "+ Adicionar tratamento ao grupo") usava `borderTopWidth: 1, borderTopColor: primary[100], borderStyle: 'dashed'`. Dentro do `protocolsList` que é animado por `LayoutAnimation.configureNext` no toggle de accordion. Cada expand/collapse disparava dezenas de warnings.

Por que não foi detectado antes da Fase 2: nenhum componente Fase 1 usava dashed dentro de bloco animado. Combinação `dashed + LayoutAnimation` é o que torna o problema visível em vez de apenas chato.
