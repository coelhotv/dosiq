# AP-318 — Bundle JS novo + binário native velho + init fail-silent

## O que aconteceu
Smoke do PR 1.3b (Firebase → Sentry/PostHog). iOS mandava crash pro Sentry, **Android não**. O
palpite natural — "limitação do SDK Android / do emulador" — estava errado. O `android/` no device
era um **prebuild anterior ao swap**: `app/build.gradle` ainda aplicava `com.google.gms.google-services`
+ `com.google.firebase.crashlytics` (linhas 184-185) e o autolinking tinha **zero** ocorrência de
sentry. O Metro serve o bundle JS **novo** (chama `Sentry.captureException`) para um **APK velho**
que não tem o módulo native do Sentry compilado.

## Por que passou despercebido
O `Sentry.init` e o `captureException` estão em `try/catch` fail-silent **de propósito** (ADR-090:
observabilidade nunca pode impedir o app de subir). Consequência: a ausência do módulo native **não
vira erro** — vira **silêncio**. Silêncio é indistinguível de "funcionou" no smoke. iOS parecia OK
só porque ali eu tinha rodado `prebuild --clean -p ios` + `run:ios` durante o gate; Android nunca
foi reconstruído nesta branch.

## A raiz mental
Modelo herdado da **web** (recarregar o bundle basta — browser baixa o JS novo) aplicado a mobile.
No mobile, **JS e native são dois artefatos separados**: `expo start` / reload troca só o JS; um
módulo native novo (ou removido) só entra com **rebuild** (`prebuild` + `run:ios/android`). Reload
sobre binário velho = bundle novo falando com native que não existe mais / ainda não existe.
Irmão de [[AP-316]] (gate mecânico não cobre `xcodebuild`) e de [[AP-314]] (código velho JÁ rodando
é a superfície que quebra) — aqui é o binário velho no **próprio** device de smoke.

## Regra / Farol
- Trocou/removeu/adicionou **dependência native** (pod, gradle plugin, config plugin)? O smoke SÓ
  vale sobre um **rebuild** (`expo run:ios` E `run:android`), NUNCA sobre reload de JS num binário
  anterior. "Funciona num, no outro não" pós-swap native = suspeitar de binário desatualizado ANTES
  de suspeitar do SDK/emulador.
- `init` fail-silent de observabilidade **esconde** módulo native ausente. Ao validar pipeline de
  crash/analytics, confirmar no binário: `grep` no `android/app/build.gradle` + autolinking pelo
  nome do pod. Ausência de erro ≠ presença do módulo.
- Prova barata de binário obsoleto: resíduo do provedor ANTIGO no projeto gerado (`firebase`/
  `google-services` no gradle depois de removê-los do config) = o `android/`/`ios/` é de um prebuild
  velho, reconstruir.
