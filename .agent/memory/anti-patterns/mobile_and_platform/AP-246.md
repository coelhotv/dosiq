# AP-246 — ActivityKit: encerrar+recriar Live Activity sem serializar mata a recém-criada

**Domínio:** mobile_and_platform
**Origem:** Spec 039 F0 (spike iOS), review Gemini PR #689 (2026-06-27)
**Severidade:** High

## Sintoma

Live Activity criada e encerrada quase imediatamente. Pílula da Dynamic Island
pisca e some. Sem erro no console.

## Causa

Padrão "1 superfície ativa": antes de `Activity.request`, encerram-se as
Activities anteriores. Se o encerramento roda em `Task` **separada** e o
`Activity.request` roda fora dela (síncrono), os dois são concorrentes:

```swift
// ERRADO — request compete com o end()
Task { for a in Activity<Attrs>.activities { await a.end(...) } }
let activity = try Activity.request(...)   // cria a nova JÁ
// quando a Task acima finalmente roda, lista TODAS (inclui a nova) e encerra a nova
```

A Task de cleanup, ao executar, lista `Activity.activities` — que agora já inclui
a recém-criada — e chama `.end()` nela.

## Fix

Serializar: encerramento + request na **mesma** Task, com `await` antes do request.

```swift
Task {
    for activity in Activity<DoseActivityAttributes>.activities {
        await activity.end(nil, dismissalPolicy: .immediate)
    }
    do {
        let activity = try Activity.request(attributes: attributes, content: content, pushType: nil)
        resolve(activity.id)
    } catch {
        reject("request_failed", error.localizedDescription, error)
    }
}
```

## Por que o smoke não pegou

Spike testado com 1 disparo por vez (sem activity anterior viva) → loop vazio,
sem corrida. Race só aparece com Activity pré-existente ao recriar.

## Aplicar no MVP (F3)

T030-T034 implementam o bridge real — herdar o padrão serializado desde o início.
