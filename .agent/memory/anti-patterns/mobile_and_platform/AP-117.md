# AP-117 — Params de navegação sem contrato tipado entre emissor e receptor

## Problema

Emissor (`NotificationInboxScreen`) envia `params.bulkMode = 'plan'` mas receptor (`TodayScreen`) verifica `params.screen === 'bulk-plan'`. O mismatch silencioso faz a modal nunca abrir — o usuário cai no Dashboard sem feedback de erro.

## Por que acontece

Params de navegação React Navigation são objetos dinâmicos sem tipagem em tempo de compilação. Cada lado evolui independentemente (inbox adiciona param, dashboard muda o nome) sem que o outro quebre o build.

## Exemplo problemático

```js
// NotificationInboxScreen.jsx — ERRADO
params.bulkMode = 'plan'
params.planId = item.treatment_plan_id

// TodayScreen.jsx — nunca satisfeito
if (params.screen === 'bulk-plan') { ... }
```

## Solução

Definir as chaves de params em um contrato centralizado (constante ou comentário JSDoc explícito) e validar no receptor com `if (params.screen)` antes de processar:

```js
// NotificationInboxScreen.jsx — CORRETO
params.screen = 'bulk-plan'
params.planId = item.treatment_plan_id
params.at = hhmm
```

## Como detectar

Grep por `params\.` nas duas pontas da navegação e conferir se as chaves coincidem exatamente.

**Why:** Incident confirmado em N1.8: push tap de plano abria o Dashboard sem modal de registro.
**How to apply:** Sempre que adicionar um novo deeplink de notificação, verificar as chaves lidas pelo receptor (`TodayScreen.jsx`) antes de definir as chaves no emissor.
