## Anti-Pattern

`AsyncStorage` no React Native é escopado por **app**, não por usuário.
`supabase.auth.signOut({ scope: 'local' })` limpa apenas a sessão Supabase —
**não toca nenhuma chave do AsyncStorage**.

Resultado: ao trocar de conta no mesmo device/simulador, o próximo usuário herda:
- flags de feature do usuário anterior (`@dosiq/alarm-enabled`, `@dosiq/alarm-nudge-seen`)
- caches de dados do usuário anterior (`@dosiq/protocols-snapshot`, `@dosiq/today-snapshot`, etc.)

**Sintoma real:** usuário B (que nunca ativou alertas críticos) via `AlarmToggleSection`
porque `@dosiq/alarm-enabled = 'true'` estava no storage do usuário A.

## Exemplo do problema

```js
// signOut NÃO limpa AsyncStorage
await supabase.auth.signOut({ scope: 'local' })
// storage anterior persiste → próximo login lê dados do user anterior
```

## Fix

`logoutUser` em `profileService.js` deve chamar `AsyncStorage.multiRemove` com
todas as chaves user-scoped antes de retornar:

```js
await AsyncStorage.multiRemove([
  ALARM_ENABLED_KEY,          // '@dosiq/alarm-enabled'
  ALARM_NUDGE_SEEN_KEY,       // '@dosiq/alarm-nudge-seen'
  '@dosiq/medicines-snapshot',
  '@dosiq/protocols-snapshot',
  '@dosiq/purchases-snapshot',
  '@dosiq/stock-snapshot',
  '@dosiq/today-snapshot',
  '@dosiq/treatments-snapshot',
  '@dosiq/recovery-flow',
]).catch(() => {})
```

**Não limpar:** chaves device-scoped (`@dosiq/expo-push-token`,
`@dosiq/alarm-perms-guide-shown`) — pertencem ao device, não ao usuário.

## Regra

Toda nova chave AsyncStorage introduzida deve ser classificada como
**user-scoped** ou **device-scoped** e adicionada à lista de `multiRemove`
no `logoutUser` se for user-scoped.
