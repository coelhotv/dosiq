> ⚠️ **SUPERSEDED em 2026-07-19 pela spec 052.** `dose_instances.medicine_id` **existe** desde o
> Slice A (#761, migração aplicada em prod) e é `NOT NULL` desde o Slice B (#762). A identidade do
> medicamento de uma dose **é** a coluna — resolver pelo protocolo (o "fix" abaixo) é justamente o
> bug que a 052 existe para matar: o protocolo evolui e reescreve o passado. Leitura correta hoje:
> `resolveInstanceMedicine` (`@dosiq/core`).

## Problema

`dose_instances` não tem coluna `medicine_id`. A tabela só armazena `protocol_id`.

Qualquer código mobile que tente ler `instance.medicine_id` diretamente obtém `undefined`.
`registerDose` exige `medicine_id` via Zod → falha silenciosa com erro "Este campo é obrigatório".

## Root Cause

Schema de `dose_instances` foi projetado com ligação indireta: instância → protocol → medicine.
O campo `medicine_id` só existe na tabela `protocols`.

## Fix

Em `enrichInstancesWithProtocol` (useHistoryData.js), incluir `medicine_id` no select do protocol
e mapear explicitamente no return:

```js
.select('id, name, medicine_id, dosage_per_intake, medicine:medicines(...), ...')
// ...
return { ...inst, medicine_id: p.medicine_id, ... }
```

**Why:** `...inst` preserva campos da instância mas `medicine_id` nunca estava lá — precisava ser
injetado pelo enrich.

## How to apply

Sempre que código mobile precisar de `medicine_id` a partir de uma `dose_instance`:
1. Verificar se o enrich do hook expõe o campo
2. Se não: adicionar ao select + map do `enrichInstancesWithProtocol`
3. Nunca assumir que `instance.medicine_id` existe sem verificar o schema da tabela
