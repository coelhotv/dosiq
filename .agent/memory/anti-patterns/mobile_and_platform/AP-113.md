# AP-113 — Server Clock Timezone Leak in Notification Formatters

## Sintoma

Emojis de saudação incorretos (ex: 🌙 "madrugada" quando é 08:00 no Brasil),
títulos com horário de período errado, `getTimeOfDayGreeting()` retorna texto
inconsistente com o horário local do usuário.

## Causa

Uso de `new Date().getHours()` como valor default ou fallback em formatters
de notificação — o servidor pode estar em UTC ou outro timezone.

```js
// ERRADO — depende do relógio do servidor
export function formatDoseGroupedByPlanMessage(planName, doses, scheduledTime, hour = new Date().getHours())

// ERRADO — fallback timezone-dependente
const hour = data.hour ?? new Date().getHours();
```

## Correção

```js
// CORRETO — fallback neutro (madrugada genérica, não depende de relógio)
export function formatDoseGroupedByPlanMessage(planName, doses, scheduledTime, hour = 0)

// CORRETO — confiar que o chamador sempre fornece hour calculado corretamente
const hour = data.hour ?? 0;
```

O chamador (tasks.js / dispatcher) SEMPRE deve calcular `hour` a partir do timezone
do usuário usando `getCurrentTimeInTimezone(timezone)`.

## Regra relacionada

**R-020** — ALWAYS use parseLocalDate() / timezone utilities. NEVER use new Date() for local time.

**Why:** O servidor (Vercel, Node.js) pode estar em UTC. `new Date().getHours()` retorna
a hora UTC, não a hora local do usuário. Para o Brasil (GMT-3), isso causa erro de 3h.
