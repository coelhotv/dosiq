# [K-090] Lightweight Notification Badge Pattern

## Context
When a screen only needs to display a numeric badge for unread notifications (e.g., a Profile or Settings tab), using a full notification log hook that fetches content, performs enrichment (joins), and sets up AppState listeners is an anti-pattern (Over-fetching).

## Pattern
Use a specialized lightweight hook that performs a `count` query with `head: true` instead of fetching full rows.

### Key Optimization
Using `{ count: 'exact', head: true }` in Supabase JS client translates to a `HEAD` request or a `SELECT COUNT(*)` on the server, returning only the count in the headers/metadata without transferring the body.

### Example
```js
const { count } = await supabase
  .from('notification_log')
  .select('id', { count: 'exact', head: true })
  .eq('user_id', userId)
  .gt('sent_at', lastSeenTimestamp)
```

## Benefits
- **Network Payload**: Reduces from KBs to practically zero (headers only).
- **Client Performance**: Avoids complex JS enrichment logic and large state updates.
- **Battery/CPU**: Fewer listeners and less processing on the main thread.
