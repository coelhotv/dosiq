- **[ADR-091]** *(accepted — spec 051-A Planning, PO 2026-07-25)* **Superfície de config remota do kill switch de versão mínima**. Origem: o ADR-088 consolidou o kill switch na 051, mas o FR-018 dizia só "config remota" — sem tabela/coluna/grant/endpoint/tela; medido no banco: **nenhuma** tabela de config/flags existe e o boot do mobile não faz **nenhuma** leitura remota hoje. Decisões: (1) tabela dedicada `public.app_version_gate` (1 linha/plataforma, `is_active NOT NULL DEFAULT false`, `updated_by` FK→`auth.users` SET NULL — R-287); rejeitado estender `in_app_nudges` (filtro de conteúdo, policy só `authenticated`); (2) decisão **pura** em `@dosiq/core` + tabela-verdade normativa como teste, UI **obedece** (antídoto do AP-303: *"guard de UI que contradiz a decisão pura que consome"*); (3) 🔴 `compareSemver` obrigatório e **`satisfiesSemver` PROIBIDA** — ela é **fail-closed** (`semver.ts:45`, nasceu p/ filtrar nudges) e inverteria a semântica no boot: config corrompida viraria bloqueio universal; (4) fail-open explícito + **proibido cachear** o estado de bloqueio (cache de gate ativo bricka o offline p/ sempre) + inspecionar `error` do supabase-js explicitamente (não lança); (5) escrita em **duas camadas independentes** (AP-278): `REVOKE INSERT,UPDATE,DELETE,TRUNCATE FROM anon, authenticated` **+** RLS com policy só de `SELECT` p/ **`anon` E `authenticated`** — `REVOKE FROM PUBLIC` sozinho NÃO basta neste projeto (`ALTER DEFAULT PRIVILEGES` nomeia os roles), e copiar a policy dos nudges deixaria o gate mudo sem sessão; (6) conteúdo remoto é não-confiável: allowlist de `store_url` (apple/play) + `message` como `<Text>` puro com cap; (7) saída honesta p/ `https://dosiq.app` como **constante compilada** (nunca da linha do gate — 2º vetor + saída removível pela config que bloqueia); (8) guarda de raio de impacto **no handler**, não na UI (`acknowledge_affected_devices` conferido server-side); (9) invariante: o kill switch nunca gateia a superfície que o desativa; (10) 🔴 admin passa a derivar do **uid autenticado** (`ADMIN_USER_ID` vs `getUser().user.id`), eliminando o lookup em `user_settings` — o modelo antigo (`telegram_chat_id == ADMIN_CHAT_ID`) era **auto-atribuível** por qualquer das 48 contas (policy de UPDATE sem restrição de coluna, sem UNIQUE); `auth.users` tem zero grants p/ anon/authenticated/service_role. Guards: manter `getUser()` (nunca decode local de JWT), env ausente ⇒ **negar**, corrigir AP-216, 401/403 uniforme. Dívidas: admin único por env var (migrar p/ `admin_users` ao escalar); policies `Pilot_*` de `user_settings` (S-13); NC6 web fora de escopo -> [`decisions/mobile_and_platform/ADR-091.md`](./decisions/mobile_and_platform/ADR-091.md)
- **[ADR-090]** *(accepted — spec 055 PR 1.3b, 2026-07-24)* **Drop `@react-native-firebase` → Sentry (crash) + PostHog (analytics de produto)**.
