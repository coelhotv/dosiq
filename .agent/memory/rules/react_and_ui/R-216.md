# R-216: Null-Safe Form Initialization

**Contexto**: Componentes de formulário que recebem `initialValues` de parâmetros de URL ou estados de modal.

## Regra
SEMPRE trate `initialValues` como potencialmente `null` ou `undefined` no ponto de entrada do formulário ou no hook de estado.

## Por que?
Default parameters do Javascript (`const fn = (arg = {}) => ...`) NÃO protegem contra `null`, apenas contra `undefined`. Se um parâmetro de URL ou prop for passado como `null`, o acesso a propriedades (`arg.id`) resultará em `TypeError`.

## Exemplo Correto
```javascript
// No Hook
export function useForm({ initialValues }) {
  const [formData, setFormData] = useState(() => getInitialFormData(initialValues))
}

// Na Utilitária
export const getInitialFormData = (initialValues) => {
  const values = initialValues || {} // Hard fallback
  return {
    id: values.id || '',
    name: values.name || ''
  }
}
```

## Exemplo Incorreto (CRASH)
```javascript
// Se initialValues vier como null, isso quebra
export const getInitialFormData = (initialValues = {}) => ({
  id: initialValues.id || ''
})
```
