## Regra

Para resetar estado quando uma dependência (prop/valor externo) muda, usar
**derived state during render** em vez de `useEffect` com `setState` síncrono.

O lint rule `react-hooks/set-state-in-effect` bloqueia `setState` síncrono
dentro de `useEffect` porque causa render extra desnecessário.

## Padrão correto

```jsx
// Guarda o valor anterior em estado; quando difere, atualiza ambos no mesmo render.
// React executa o setState durante render, descarta o output atual e re-renderiza
// com os novos valores — sem render extra (diferente de useEffect).

const [myState, setMyState] = useState(initialValue)
const [prevDep, setPrevDep] = useState(dep)

if (prevDep !== dep) {
  setPrevDep(dep)
  setMyState(computeNewState(dep))  // reset derivado da nova dep
}
```

## Exemplo real (AlarmSchedulerBridge)

```jsx
const [loaded, setLoaded] = useState(!user?.id)
const [prevUserId, setPrevUserId] = useState(user?.id ?? null)
const userId = user?.id ?? null

// Reset no mesmo render quando userId muda
if (prevUserId !== userId) {
  setPrevUserId(userId)
  setLoaded(!userId) // novo user → false (aguarda load); logout → true
}
```

## Alternativas

- **`key` prop**: se o componente inteiro deve ser remontado ao mudar a dep,
  renderizar com `key={dep}` no pai — mais simples quando remount é aceitável.
- **`useRef` + derivação**: quando não precisa causar re-render (raro).

## Anti-pattern evitado

```jsx
// ❌ useEffect + setState síncrono — causa render extra + falha no lint
useEffect(() => {
  setLoaded(false)  // react-hooks/set-state-in-effect
}, [userId])
```

**Why:** `useEffect` roda APÓS o render; `setState` dentro dele agenda outro render.
Derived state during render é síncrono ao render atual — mais eficiente e idiomático.
