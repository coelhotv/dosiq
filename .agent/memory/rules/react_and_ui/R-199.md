# [R-199] Intl.DateTimeFormat Module-Level Memoization (React Native)

## Context
In React Native, `Intl.DateTimeFormat` instantiation and execution can be expensive and potentially inconsistent depending on the JS engine (JSC vs Hermes). Executing it inside high-frequency render loops or helper functions called during render causes UI thread lag.

## Rule
ALWAYS move `Intl.DateTimeFormat` detection or instantiation to the module level (outside the component) or wrap it in a global constant if the configuration is static.

## Example
### ❌ Incorrect
```javascript
function formatTime(str) {
  const is24h = !new Intl.DateTimeFormat(undefined, { hour: 'numeric' }).format(...).match(/am|pm/i)
  // ... logic
}
```

### ✅ Correct
```javascript
const IS_24H = !new Intl.DateTimeFormat(undefined, { hour: 'numeric' }).format(...).match(/am|pm/i)

function formatTime(str) {
  if (IS_24H) { // ... }
}
```

## Impact
- Better frame rates on mid-tier Android devices.
- Prevents redundant object creation on every render.
