# R-285 — Default `= undefined` em props destructuradas não-anotadas controla a opcionalidade inferida

**Domínio**: react_and_ui · **Criada**: 2026-07-06 (040 F5 lotes 3/4/6 + review PR #725) · **Status**: ativa

## Regra

Em componente TS **sem anotação explícita de props** (nível B da migração 040), a opcionalidade de cada prop é inferida do destructuring: **prop sem default = required** (TS2739/2741/2740 em todo caller que a omite).

1. Prop opcional em componente shared/reutilizado → dar default no destructure: `secondaryLabel = undefined` (ou o default de negócio: `= false`, `= null`).
2. **NUNCA** dar default truthy a prop de render condicional (`{secondaryLabel && <Btn/>}`) — muda UI; `= undefined` preserva o comportamento exato.
3. **NUNCA remover** um `= undefined` "aparentemente redundante" sem rodar tsc full-project: a remoção reintroduz required-ness e quebra callers distantes silenciosamente (sugestão de IA nesse sentido no lote 3 — declinada).
4. Remendo no call-site (`prop={undefined}`) é proibido como fix permanente — resolve 1 caller e espalha ruído; o fix de 1 linha no componente mata a classe (lote 6 acumulou 5+ remendos que o review do PR #725 removeu).

## Origem

040 F5: `FormActions`/`FormSection`/`FormSelect`/`EmptyState`/`BulkDoseRegisterModal` migrados sem defaults → cascata TS2739 nos lotes seguintes; corrigidos em 481f0d6, e081391e e ~9 componentes no lote 3. Fix definitivo dos restantes (`FormAutocomplete`, `FormInput`) no backlog F6.
