# [R-210] Conditional Hook Execution (Enabled Flag)

## Context
Custom hooks that perform side effects like network requests, setting up timers, or adding event listeners (e.g., `AppState`) can cause performance degradation and redundant resource usage if they execute in backgrounds or in inactive views.

## Rule
All custom hooks with side effects MUST accept an optional `enabled` (boolean) parameter in their options object. This flag must be used to:
1. Guard network request logic (e.g., in a `load` callback).
2. Guard the setup and cleanup of effects (e.g., `useEffect`).
3. Be included in dependency arrays.

## Rationale
- **Performance**: Reduces the number of concurrent network requests.
- **Resource Management**: Prevents the accumulation of stale listeners and timers.
- **Consistency**: Follows standard patterns established by libraries like `useSWR` and `TanStack Query`.

## Examples
### ✅ CORRECT
```jsx
export function useFeature(options = {}) {
  const { enabled = true } = options
  
  useEffect(() => {
    if (!enabled) return
    // ... side effect logic
  }, [enabled])
}
```

### ❌ WRONG
```jsx
export function useFeature() {
  useEffect(() => {
    // ... always executes
  }, [])
}
```
