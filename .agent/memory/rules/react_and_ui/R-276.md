# R-276 — Inputs decimais na web: `type=text inputMode=decimal` + `coerceDecimal`, nunca `type=number`

**Categoria:** `react_and_ui`
**Origem:** 012 Fase B2 (smoke PO 2026-06-12, PR #660)
**Relaciona:** AP-167 (coerceDecimal mobile), R-270 (decimal PT-BR no write-path)

## Regra

Todo input numérico **decimal** nos forms web DEVE ser `type="text" inputMode="decimal"` e a camada
de persist/validação DEVE normalizar com `coerceDecimal` (`@dosiq/core` — vírgula OU ponto → Number).

**Proibido `type="number"` para decimais:** o HTML bloqueia a vírgula no browser (PT-BR usa `,` como
separador) e `Number('2,5') = NaN` quebra silenciosamente persist e validação.

Campos **inteiros** (nº de frascos, duração em dias, validade) podem manter `type="number"`.

## Cuidado de validação (corolário — Gemini #660)

Ao trocar para `type="text"`, a validação nativa do browser some: `'abc'` passa a ser digitável.
Comparações ingênuas falham — `"abc" <= 0` é `false`. SEMPRE validar `Number.isNaN(coerceDecimal(v))`
antes de comparar magnitude:

```js
const qty = coerceDecimal(formData.quantity)
if (Number.isNaN(qty) || qty <= 0) errors.quantity = '...'
```

## Fonte única

`coerceDecimal` vive em `packages/core/src/utils/formUtils.js` (R-129 — lógica pura no core),
exportado por `@dosiq/core`. Não recriar helper local por feature (havia ~10 `.replace(',','.')`
inline antes do sweep). Mobile já seguia o padrão via seu próprio `coerceDecimal` (AP-167).

## Cobertura

Forms varridos: medicamento, compra/estoque, tratamento (edição), wizard passos 1/2/3. Persist +
validação em `_medicineFormUtils`, `_stockFormUtils`, `protocolFormUtils`, `_treatmentWizardSubmit`,
`useTreatmentWizardState`.
