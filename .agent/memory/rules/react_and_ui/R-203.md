# R-203: Semantic Versioning in Footers

## Context
Displaying the current application version in the UI (e.g., in Settings or Profile footers).

## Rule
Always use `import.meta.env.VITE_APP_VERSION` to dynamically inject the version from the build environment.

The Web/PWA product version source of truth is `apps/web/package.json` `version`. Build-time `VITE_APP_VERSION` must be generated from or kept aligned with that value. Hardcoded UI fallbacks are allowed only as resilience fallback and must be updated when the web package version changes.

For release governance, use R-221/R-242 before changing Web/PWA behavior:
- classify release impact;
- bump `apps/web/package.json` when impact is `patch`, `minor`, or `major`;
- add a Portuguese `CHANGELOG.md` entry under `[Unreleased]`.

## Example
```javascript
// ✅ CORRECT
const APP_VERSION = import.meta.env.VITE_APP_VERSION || "3.3.0";

// ❌ WRONG
const APP_VERSION = "3.2.1"; // Hardcoded and out of sync
```
