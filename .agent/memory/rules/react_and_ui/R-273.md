# R-273 — Modal/Form com entidade como prop: obrigatório `key` no caller

## Regra

Todo componente modal ou form que recebe uma entidade como prop de dados iniciais
(`nudge`, `medicine`, `protocol`, etc.) **DEVE** ter `key` correspondente no caller.

```jsx
// ✅ OBRIGATÓRIO
<EntityFormModal
  key={selectedEntity?.id || 'create'}
  entity={selectedEntity}
  isOpen={isOpen}
  ...
/>
```

## Por quê

`useState(prop || default)` inicializa **apenas no mount**. Se o modal permanece
no DOM (pattern comum — montado uma vez, controlado por `isOpen`), trocar a prop
não reinicializa o state. Resultado: form abre com dados do registro anterior ou
vazio, sem nenhum erro no console (AP-222).

`key` diferente força React a desmontar + remontar → `useState` recebe valor correto.

## Verificação no C1

Ao criar ou revisar qualquer componente que:
- Recebe prop de entidade (`nudge`, `medicine`, `protocol`, `stock`, etc.)
- Usa essa prop como valor inicial de `useState`
- É renderizado via `isOpen` (permanece no DOM)

→ Confirmar que o caller passa `key={entity?.id || 'create'}`.

## Anti-pattern relacionado

[[AP-222]] — `useEffect + setState` **não** é alternativa válida: viola
`react-hooks/set-state-in-effect` (configurado como **error** no projeto).
