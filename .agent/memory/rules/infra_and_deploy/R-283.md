# R-283 — Ratchet strict TS: `scripts/strict-island.sh` em toda sessão de migração

**Domínio**: infra_and_deploy · **Criada**: 2026-07-03 (040 F2, redesenho do gate)

## Regra

Durante o épico 040 (e qualquer migração incremental com gate de qualidade):

1. O gate strict é **`./scripts/strict-island.sh`**, não `tsc -p tsconfig.strict.json` cru. Semântica: erros em **fonte** dos domínios nível A = bloqueante; nível B transitivo + testes A = dívida contada (TODO 040-strict, queima na F6).
2. Rodar em **TODA sessão antes do commit**, não só no gate da fase. Gate medido só no fim ≠ ratchet: b9086ec passou 5 sessões "verdes" e revelou 949 erros na última.
3. Promover domínio a nível A = adicionar dir ao `include` do `tsconfig.strict.json` **E** ao filtro `A_SRC` do script (lista só cresce).
4. Queda abrupta na contagem de dívida sem trabalho correspondente = red flag de resolução `any` (ver AP-261), não vitória.

## Por quê

Com o core 100% TS, o programa strict engole dependências nível B via imports — tsc cru nunca mais fica verde até strict global. O script separa sinal (regressão em fonte A) de ruído (dívida B conhecida).
