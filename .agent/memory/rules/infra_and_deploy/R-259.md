# R-259 — EAS capability sync lê o `.entitlements` nativo, não o `app.config`

**Layer:** warm · **Status:** active · **Pack:** infra_and_deploy
**Origem:** Spec 001 (Alarme Nativo) A2 iOS, PR feat/alarme-nativo, 2026-06-03

## Regra

Em projeto com `ios/` **prebuildado e commitado** (workflow bare), o `eas
credentials`/`eas build` sincroniza as capabilities do Apple Developer Portal a
partir do **`ios/<App>/<App>.entitlements` nativo** — **não** do
`app.config.js → ios.entitlements`. Capability ligada no portal mas ausente do
arquivo nativo é **desativada** pelo EAS ("Disabled: <capability>").

Declarar o entitlement nos **DOIS** lugares:

1. `ios/<App>/<App>.entitlements` — fonte que o EAS lê **agora**.
2. `app.config.js` `ios.entitlements` — garante que um futuro `prebuild --clean`
   regere o arquivo já com a chave (senão sobrescreve e reintroduz o bug).

```xml
<!-- Dosiq.entitlements -->
<key>com.apple.developer.usernotifications.time-sensitive</key>
<true/>
```

## Detalhes

- Sintoma: ligar a capability no portal, rodar `eas credentials`, e ver
  "✔ Synced capabilities: Disabled: Time Sensitive Notifications" — o EAS reverte
  a cada execução porque reconcilia o portal contra o arquivo local.
- **Não** declarar entitlement ainda **não aprovado** pela Apple (ex.: Critical
  Alerts em avaliação) — o provisioning profile falha (entitlement não autorizado).
- `uncommitted` no git **não** afeta o build (`prebuild`/build lê o working tree).
