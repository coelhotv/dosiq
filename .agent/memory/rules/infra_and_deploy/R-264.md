## Regra

Antes de bumpar `@supabase/supabase-js` (ou qualquer lib com client constructor que bundla sub-deps com requisitos de runtime), verificar changelog do sub-dep embutido (`realtime-js`, `postgrest-js`, etc.) para mudanças de requisitos de ambiente (WebSocket, fetch, crypto).

O checklist SQP (R-221) para bumps de deps server-side deve incluir:

- [ ] Lib bundla sub-deps com requisito de runtime (WebSocket, fetch, crypto)?
- [ ] Sub-dep foi bumped no release? Ver changelog de cada sub-dep listado no release notes
- [ ] `ws` (ou polyfill equivalente) está em `dependencies` diretas do workspace server?
- [ ] Smoke test de cold start passou em Node 22 local antes do PR?

## Por que

`supabase-js` 2.91 bundla `realtime-js` que passou a verificar WebSocket no construtor (silent breaking change — não explicitado no major/minor do supabase-js). O bump foi feito como parte de outro feature (`feat(mobile): alarme nativo A2`) sem checklist de runtime, chegando a prod sem gate.

## Como aplicar

Ao fazer `npm install @supabase/supabase-js@latest` (ou qualquer update via Dependabot/manual):
1. Ler `CHANGELOG.md` do `@supabase/realtime-js` para a faixa de versão embutida
2. Rodar `node scripts/smoke-server.mjs` em Node 22 localmente
3. Só então abrir PR
