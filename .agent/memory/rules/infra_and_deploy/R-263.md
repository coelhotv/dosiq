## Regra

Declarar `"engines": { "node": "22.x" }` no `package.json` raiz **e** `NODE_VERSION=22` nas env vars da Vercel. Sem essa âncora, bumps silenciosos de runtime da Vercel mudam o ambiente de execução sem sinal visível no código ou no CI.

## Por que

Vercel atualiza o runtime padrão periodicamente. Uma função que funcionava em Node 20 pode quebrar silenciosamente ao mover para Node 22 (ou vice-versa) — especialmente em checagens de globals nativos (WebSocket, fetch). A âncora garante que o ambiente local, o CI e a Vercel usem exatamente a mesma versão.

## Como aplicar

```json
// package.json raiz
"engines": { "node": "22.x" }
```

```
// Vercel Dashboard → Settings → General → Node.js Version
NODE_VERSION=22
```

Ao decidir subir para Node 24 (LTS subsequente): atualizar ambos juntos e testar o smoke ([[R-262]]) antes.
