# R-284 — Mudança em pacote compartilhado exige compilar os programas consumidores (cross-program)

**Domínio**: infra_and_deploy · **Criada**: 2026-07-04 (040 gate F3)

## Regra

"Strict-limpo" ≠ "limpo em todo programa que inclui o código". Um pacote compartilhado (ex.: `@dosiq/core`) é compilado por N programas TS com flags diferentes — a inferência muda entre eles (caso real: opcionalidade Zod com/sem `strictNullChecks`; erro latente da F2 só observável quando `api/` virou TS).

1. `scripts/strict-island.sh` roda **cross-program**: além do island strict, compila cada tsconfig consumidor (`api/`, `server/`; F4/F5 adicionam web/mobile ao `CONSUMERS`). Erro de FONTE em consumidor = bloqueante; testes = dívida contada.
2. Ao criar tsconfig novo que inclua `packages/*`: adicionar ao `CONSUMERS` na 1ª sessão da fase.
3. Erro que só aparece num regime de flags NÃO é "erro do consumidor" — é erro latente do pacote compartilhado; corrigir na fonte.

## Por quê

Gate F2 fechou verde legitimamente e mesmo assim a F3 herdou um erro do core: nenhum gate compilava o core sob non-strict até `api/` virar TS. Sem o check, F4/F5 repetiriam o padrão a cada tsconfig novo (erro "de ninguém").
