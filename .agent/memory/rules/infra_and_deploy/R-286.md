# R-286 — União discriminada em código do core: estreitar com `=== false`, não com `!x.success`

**Domínio**: infra_and_deploy (regime de flags cross-program) · **Criada**: 2026-07-07 (040 F6 lote 6.5)

## Regra

Em código de `packages/core` (ou qualquer fonte consumida por MAIS de um programa tsc), narrowing de união discriminada booleana usa comparação explícita:

```ts
// ✅ estreita em qualquer regime de flags
if (result.success === false) { return result.error }

// ❌ NÃO estreita sob consumer com strict:false (mobile herda da base)
if (!result.success) { return result.error }
```

## Por quê

`!x.success` só estreita com `strictNullChecks` ligado. O core compila strict-limpo no island, mas TAMBÉM é typechecked dentro dos programas consumidores (R-284) — mobile/api herdam `strict: false` da base, e lá o `!` não discrimina a união: o branch enxerga o tipo largo e o erro aparece como "erro do consumer" longe da causa. `=== false` estreita nos dois regimes.

Vale até `strict: true` global (meta pós-040); depois disso a regra vira estilo, não correção.
