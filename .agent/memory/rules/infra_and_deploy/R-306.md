# R-306 — Smoke de endpoint serverless em dev exige apontar o proxy pro deploy CERTO (branch preview + bypass de SSO)

`api/*` nunca roda localmente neste projeto — `vite.config.js` faz `/api` → proxy pra um deploy
Vercel real quando `EXPO_PUBLIC_API_BASE_URL` está setado (dev sempre bate em backend remoto, nunca
emulado). Duas armadilhas descobertas no smoke da PR 1.5c (kill switch admin panel):

1. **Branch errada por trás do proxy é indistinguível de "endpoint não existe".** O `.env.local`
   trazia `EXPO_PUBLIC_API_BASE_URL=https://dosiq.app/` (produção = branch `main`). Testar um
   resource novo (`versionGate`) que só existe numa branch de integração ainda não mergeada em main
   devolve o fallback genérico do router (`405 Method or action not allowed`) — sintoma idêntico ao
   de "serverless não funciona em dev". Fix: apontar pro **alias estável da branch**
   (`https://dosiq-git-<branch>-<org>-projects.vercel.app`, atualiza a cada push) via
   `mcp__plugin_vercel_vercel__list_deployments` pra achar a URL certa — não assumir prod.

2. **Deployments de branch/preview (não-produção) têm SSO por padrão (Deployment Protection).** O
   proxy do Vite roda no processo Node e não tem sessão de browser Vercel — a resposta é um
   redirect pra `vercel.com/sso-api` que o browser bloqueia por CORS (`ERR_FAILED`, sem
   `Access-Control-Allow-Origin`). Prod (`dosiq.app`) não tem essa proteção, por isso o proxy
   "sempre funcionou" até então — mascarou o problema #1 por meses. Fix: gerar o **Protection
   Bypass for Automation** secret (Vercel dashboard → Project → Settings → Deployment Protection),
   colar em `.env.local` como `VERCEL_AUTOMATION_BYPASS_SECRET`, e o proxy manda
   `x-vercel-protection-bypass` + `x-vercel-set-bypass-cookie` nos headers — só o processo Node vê
   o secret, nunca chega ao browser.

**Gate:** antes de declarar "não dá pra testar serverless em dev", conferir (a) qual branch está
atrás de `EXPO_PUBLIC_API_BASE_URL` e se ela tem o código em teste, (b) se a resposta é o fallback
genérico do router (sintoma de #1) vs CORS/SSO redirect (sintoma de #2) — são causas raiz
diferentes, com fixes diferentes.

⚠️ **Lembrar de reverter** `EXPO_PUBLIC_API_BASE_URL` pra `https://dosiq.app/` depois do smoke —
senão dev fica preso apontando pra uma branch de integração indefinidamente, e outros fluxos
(chat IA, etc.) rodam contra o deploy errado sem aviso.
