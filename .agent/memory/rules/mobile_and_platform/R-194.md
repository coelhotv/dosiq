## Regra

Para refs de `NavigationContainer` que precisam ser importadas fora do componente (deeplink, push notifications, analytics), usar `createNavigationContainerRef()` de `@react-navigation/native` — **não** `createRef()` do React.

```js
// ✅ CORRETO
import { createNavigationContainerRef } from '@react-navigation/native'
export const navigationRef = createNavigationContainerRef()

// Uso externo — sem .current, sem verificação de isReady
navigationRef.navigate('Hoje', params)

// ❌ ERRADO
import { createRef } from 'react'
export const navigationRef = createRef()
navigationRef.current?.navigate('Hoje', params) // isReady check manual necessário
```

## Por que

`createNavigationContainerRef` retorna um objeto com `navigate()` diretamente (não via `.current`) e **enfileira ações automaticamente** se o navigator ainda não estiver montado — eliminando a necessidade de:
- verificar `isReady()` antes de navegar
- adicionar listener `addListener('state', ...)` como fallback de timing
- gerenciar `unsubscribe` manualmente (risco de vazamento)

## Origem

N1.4 (Sprint 2026-W17) — sugestão do Gemini Code Assist na revisão de PR #499. A implementação inicial usou `createRef` que exigiu `addListener` manual como fallback, com risco de vazamento de listener se `unsubscribe` não fosse chamado.
