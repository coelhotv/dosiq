## Regra

**NUNCA** solicitar permissão de push no primeiro carregamento do app. O prompt
do SO só dispara em **pontos de intenção** explícitos do usuário.

### Setup global = register-only

`usePushNotifications` no boot **não pede** permissão. Apenas:
1. registra handlers (`setNotificationHandler`) + listener de tap;
2. se `getPushPermissionStatus()` já for `granted`, registra o token
   (`registerPushToken`). Caso contrário, retorna sem prompt.

### Pontos de intenção (onde pedir)

- **Onboarding** — usuário LIGA o toggle "Me avise a hora de tomar" →
  `enablePushAtIntent`. Negado no SO → toast informativo, sem nag.
- **1º tratamento criado** fora do onboarding — se status `undetermined`,
  `enablePushAtIntent` após o create bem-sucedido (não no edit).
- **Configs de notificações** — usuário ativa o canal "Celular".

### Princípios

- `getPermissionsAsync` para CHECAR (puro, sem prompt);
  `requestPermissionsAsync` só quando `canAskAgain` em ponto de intenção.
- Negado no SO nunca bloqueia o fluxo — a dona Maria reativa depois em Configs.
- Lembretes existem no app independentemente do push (ver [[ADR-047]]); push é
  só entrega.

## Onde nasceu

PR #584 (Fase 4): redesenho da permissão de push após o deeplink de confirmação
abrir o app já logado e disparar o prompt no passo 2 — antes de qualquer intenção.
Ver [[AP-178]] para re-checagem ao voltar das Configs do SO.
