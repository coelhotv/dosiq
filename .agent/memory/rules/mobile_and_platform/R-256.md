# R-256 — SecureStore de sessão/auth com `AFTER_FIRST_UNLOCK` p/ background

**Layer:** warm · **Status:** active · **Pack:** mobile_and_platform
**Origem:** Spec 001 (Alarme Nativo) A2 iOS, PR feat/alarme-nativo, 2026-06-03

## Regra

Itens do Keychain (expo-secure-store) que precisam ser lidos por **handlers em
background ou com a tela bloqueada** — sessão Supabase lida por ações do alarme
(Notifee `onBackgroundEvent`, Apple Watch, lock screen) — DEVEM ser gravados com:

```js
SecureStore.setItemAsync(key, value, {
  keychainAccessible: SecureStore.AFTER_FIRST_UNLOCK,
})
```

O default (`WHEN_UNLOCKED`) torna o item **ilegível com o device travado** →
`getValueWithKeyAsync ... User interaction is not allowed` → `useAuth`/restauração
de sessão falha → o "Tomei" travado não consegue chamar `registerDose` (sem auth).

## Detalhes

- `AFTER_FIRST_UNLOCK`: legível após o 1º unlock pós-reboot, inclusive em
  background/locked. **Não** sincroniza com iCloud (token fica local ao device) —
  postura de segurança adequada (não usar `ALWAYS`).
- Aplicar **só na escrita**; itens já gravados migram no próximo refresh/login.
  Forçar migração = logout+login ou esperar o auto-refresh do Supabase reescrever.
- No-op no Android (usa Keystore, ignora `keychainAccessible`).
- Vale p/ chunked storage: aplicar a opção em **todos** os `setItemAsync`
  (chunks + contador), não só na chave direta.
