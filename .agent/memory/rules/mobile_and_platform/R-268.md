## Regra

Qualquer operação Supabase que faça UPDATE de status em uma única linha específica (ex: `revertToUnregistered`, `markTaken`) DEVE ter seu retorno verificado antes de prosseguir com operações dependentes.

## Por quê

O PostgREST/Supabase não retorna erro quando um UPDATE não afeta nenhuma linha (0 rows affected). A operação retorna `{ data: [], error: null }` — sucesso silencioso. Se a linha já foi alterada por outra operação concorrente (race condition, duplo-clique, outro device), o caller não sabe que o update foi um no-op e segue executando lógica que assume que o estado mudou.

## Como aplicar

```js
// ERRADO — assume que o revert funcionou:
await doseInstanceRepo.revertToUnregistered(instanceId, newStatus)
await logEvent(...)
return { success: true }

// CORRETO — checa retorno booleano antes de prosseguir:
const reverted = await doseInstanceRepo.revertToUnregistered(instanceId, newStatus)
if (!reverted) {
  return { success: false, error: 'Não foi possível reverter o status da dose. O registro pode já ter sido alterado.' }
}
await logEvent(...)
return { success: true }
```

O repositório `createDoseInstanceRepository` retorna `boolean` em `revertToUnregistered` e `markTaken` — verificar sempre.

Padrão geral: se o método do repositório retorna `boolean`, tratar `false` como falha de concorrência antes de continuar.
