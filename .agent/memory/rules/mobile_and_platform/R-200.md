# R-200 — Centralized Notification Gate (ADR-030)

## Regra

Desde a implementação da **ADR-030**, o `NotificationDispatcher` é a única autoridade para decidir se uma notificação deve ou não ser entregue ao usuário final.

**Invariantes de Fluxo:**
1. **Orquestradores (Bot, Cron, API):** Devem focar apenas na detecção de eventos e construção de payloads. Eles NÃO devem consultar preferências de supressão (ex: `quiet_hours`) ou estado de silêncio.
2. **Gate Único:** A verificação de `shouldSuppressNotification()` e `resolveChannelsForUser()` deve ocorrer exclusivamente dentro do `dispatchNotification.js`.
3. **Log de Supressão:** Notificações suprimidas pelo gate central DEVEM ser registradas na `notification_log` com o estado `silenciada` para fins de auditoria e transparência.

## Por que?

A fragmentação da lógica de supressão entre o Bot do Telegram e o Servidor de Push gerava inconsistências onde um usuário recebia alertas no celular mas não no Telegram durante "Quiet Hours", ou vice-versa. Centralizar no Dispatcher garante que a experiência do usuário seja uniforme, independentemente do canal de entrega.

## Exemplos

**CERTO (Delegar ao Dispatcher):**
```javascript
// server/bot/tasks.js
const payload = buildPayload(user, item);
await notificationDispatcher.dispatch(payload); // O gate está aqui dentro
```

**ERRADO (Gate Manual no Orquestrador):**
```javascript
// server/bot/tasks.js
const settings = await getSettings(user.id);
if (settings.silent_mode) return; // VIOLAÇÃO R-200: Gate manual duplicado
await notificationDispatcher.dispatch(payload);
```
