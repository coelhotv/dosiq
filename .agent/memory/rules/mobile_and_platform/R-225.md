# [R-225] Resilient ID Resolution for Notification Payloads

## Definição
Todo componente de UI ou hook que consome dados de notificações (Inbox, Push Listeners, Linking Handlers) DEVE utilizar um helper de resolução resiliente para lidar com variações de chaves de ID entre plataformas e camadas.

## Detalhes
As notificações no Dosiq podem originar-se de diferentes fontes:
- **Banco de Dados (L1):** Usa `snake_case` (`protocol_id`).
- **Dispatcher/TS (L2):** Pode usar `camelCase` (`protocolId`).
- **Antigos payloads:** Podem ter chaves legadas.

Para garantir que CTAs e Deep Links funcionem corretamente (ex: abrir a modal com o medicamento correto pré-selecionado), o código deve ser resiliente:

```javascript
// ✅ Correto: Resolver com fallbacks
const protocolId = data?.protocol_id || data?.protocolId;
const protocolIds = data?.protocol_ids || data?.protocolIds;
```

## Aplicação
- Mobile: `NotificationInboxScreen.jsx`, `useNotificationLinking.js`
- Web: `NotificationActions.jsx`
- Server: `NotificationDispatcher.js`
