## Regra

Quando um componente (A) carrega dados async e alimenta um hook (B) com side
effect destrutivo (ex: `cancelAll`, limpar cache, desregistrar listeners), o
hook B **não deve executar antes do primeiro load() bem-sucedido**.

Extrai o hook para sub-componente `C` e renderiza condicionalmente com `loaded`.

## Padrão

```jsx
// Componente orquestrador
export default function Bridge() {
  const [data, setData] = useState([])
  const [loaded, setLoaded] = useState(!userId)  // R-265 para reset em mudança de userId
  const [prevUserId, setPrevUserId] = useState(userId)
  if (prevUserId !== userId) { setPrevUserId(userId); setLoaded(!userId) }

  const load = useCallback(async () => {
    const result = await fetchData()
    setData(result)
    setLoaded(true)  // ← marca como carregado após sucesso
  }, [userId])

  useEffect(() => { load() }, [load])

  // Gate: sub-componente só monta após loaded=true
  return loaded ? <HookWrapper data={data} /> : null
}

// Sub-componente isolado para o hook com side effect
function HookWrapper({ data }) {
  useDestructiveHook({ data })  // cancelAll, etc. — só roda após dados reais
  return null
}
```

## Por que sub-componente?

React proíbe hooks condicionais (`if (loaded) useHook()` é inválido).
Sub-componente renderizado condicionalmente contorna a regra corretamente:
quando `loaded=false`, o sub-componente não existe na árvore React e o hook
não é chamado.

## Contexto real (AlarmSchedulerBridge)

- `AlarmSchedulerBridge` carrega `protocols` async
- `useAlarmScheduler({ isAlarmEnabled: hasCriticalProtocol })` chama `cancelAll`
  quando `isAlarmEnabled=false`
- `hasCriticalProtocol = protocols.some(...)` é `false` enquanto `protocols=[]`
- Sem gate → `cancelAll` no mount → alarmes cancelados antes de load() terminar
- Com gate → `AlarmScheduler` sub-componente só monta após `load()` setar `loaded=true`

## Relação com AP-215

Este padrão é a solução direta para AP-215 (cancelAll prematuro no mount).
