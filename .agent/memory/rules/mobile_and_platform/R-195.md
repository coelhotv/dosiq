# R-195 — Enrichment relacional no hook em vez de duplicar dados em notification_log

## Regra

Dados que existem em tabelas relacionais (nomes de medicamentos, listas de doses de um protocolo) **nunca devem ser duplicados/persistidos em `notification_log`**. Em vez disso, o hook de leitura (`useNotificationLog`) deve enriquecê-los em memória após o fetch, fazendo queries relacionais paralelas.

## Implementação canônica

```js
async function enrichWithDoses(logs) {
  // Separar por tipo que precisa de enriquecimento
  const planLogs  = logs.filter(l => l.notification_type === 'dose_reminder_by_plan')
  const miscLogs  = logs.filter(l => l.notification_type === 'dose_reminder_misc')

  // Queries paralelas — nunca sequenciais
  const [planProtos, miscProtos] = await Promise.all([
    fetchByPlanIds(planLogs.map(l => l.treatment_plan_id)),
    fetchByProtocolIds(miscLogs.flatMap(l => l.provider_metadata?.protocol_ids ?? [])),
  ])

  // Filtrar por janela de tempo (±2h) antes de montar a lista de doses
  return logs.map(log => ({
    ...log,
    doses: buildDoseList(log, planProtos, miscProtos),
  }))
}
```

## Por que

- **Evita drift de dados**: nomes de medicamentos mudam (o usuário pode renomear). Duplicar cria versões desatualizadas em notification_log.
- **Evita schema bloat**: `notification_log` não precisa de colunas `doses JSONB[]` que crescem indefinidamente.
- **Separação de responsabilidades**: o dispatcher registra *o evento*; o hook de leitura resolve *o contexto atual*.

## Quando aplicar

- Sempre que a UI da inbox precisar de dados além do que está em `notification_log` (nomes de medicamentos, dosagens, listas de protocolos).
- Queries de enriquecimento devem ser paralelas (`Promise.all`) e filtradas em memória por janela de tempo.

**Why:** Decisão tomada em N1.8 após o usuário corretamente rejeitar a proposta de persistir `doses[]` em `notification_log`. Relational join é mais limpo e evita duplicação.
**How to apply:** Ao implementar nova feature de inbox que precise de dados extras, adicionar branch em `enrichWithDoses()` no `useNotificationLog` — nunca adicionar campos a `notification_log` para armazenar snapshots de dados relacionais.
