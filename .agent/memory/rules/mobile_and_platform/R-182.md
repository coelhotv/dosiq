# [R-182] Cross-Platform Build Version Synchronization

## Context
Google Play uses `versionCode` (integer) and App Store uses `buildNumber` (string) to identify binary versions. Manual management leads to drift and confusion.

## Rule
Maintain absolute mobile build version consistency by deriving both platform-specific identifiers from the semantic `APP_VERSION` in `apps/mobile/app.config.js`.
- Use the formula: `major * 10000 + minor * 100 + patch`.
- Apply to `android.versionCode` as a number.
- Apply to `ios.buildNumber` as a string.
- Treat `APP_VERSION` as the canonical mobile product version.
- Do not infer mobile release version from root `package.json` or `apps/mobile/package.json`.

For release governance, use R-221/R-242 before changing mobile behavior:
- classify release impact;
- bump `APP_VERSION` when impact is `patch`, `minor`, or `major`;
- add a Portuguese `CHANGELOG.md` entry under `[Unreleased]`.

## Rationale
Ensures that a single mobile source of truth (`APP_VERSION`) updates iOS and Android build identifiers simultaneously, simplifying support, store submissions, and release tracking.
