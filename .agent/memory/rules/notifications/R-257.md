# R-257 — Botões de ação em notificação iOS exigem categoria registrada

**Layer:** warm · **Status:** active · **Pack:** notifications / mobile_and_platform
**Origem:** Spec 001 (Alarme Nativo) A2 iOS, PR feat/alarme-nativo, 2026-06-03

## Regra

No iOS, os botões de ação de uma notificação (Tomei/Soneca/Pular) **não** vêm do
array `actions` do payload (isso é Android). Exigem **registrar uma categoria** e
referenciá-la:

```js
// 1. Registrar a categoria (idempotente, no setup):
await notifee.setNotificationCategories([
  { id: ALARM_CHANNEL_ID, actions: [
    { id: ALARM_ACTION.TAKEN, title: 'Tomei', foreground: false },
    { id: ALARM_ACTION.SNOOZE, title: 'Soneca', foreground: false },
    { id: ALARM_ACTION.SKIP, title: 'Pular', foreground: false, destructive: true },
  ]},
])
// 2. Apontar no payload:
ios: { categoryId: ALARM_CHANNEL_ID, ... }
```

Sem `setNotificationCategories`, `categoryId` referencia uma categoria inexistente
→ a notif iOS sai **sem botões**.

## Detalhes

- `foreground: false` → ação tratada pelo background handler (igual Android), sem
  abrir o app; só o tap no corpo abre.
- `foregroundPresentationOptions: { sound: true, banner: true, list: true }` no
  bloco `ios` → toca/aparece **com o app aberto** (iOS suprime por padrão em
  foreground). Sem isso, o alarme em foreground fica mudo.
- O `id` da ação iOS chega em `event.detail.pressAction.id` — mesmo handler
  cross-platform do Android.
- iOS **não** tem full-screen takeover na lock screen; o tap abre o app → tela
  cheia. Ver [[K-091]].
