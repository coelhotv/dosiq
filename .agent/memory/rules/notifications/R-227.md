# R-227 — Kind Uniqueness por Tipo de Relatório

Relatórios com contextos distintos (período, dados, título) DEVEM ter kinds separados. Compartilhar `kind` entre relatórios diferentes impede títulos distintos, schemas específicos, builders próprios e comportamentos de gate diferenciados.

## Violação descoberta

`weekly_adherence` e `adherence_report` usavam o mesmo `kind: 'adherence_report'` → relatório semanal recebia título "Relatório Diário", schema sem campo `period`, sem nudge motivacional.

## Contrato

Cada kind DEVE ter:
1. Entrada no `kindSchema` (`z.enum`)
2. Schema Zod de dados próprio (`xxxDataSchema`)
3. Builder próprio em `_payloadBuilders.js` (`buildXxxPayload`)
4. Case no switch de `buildNotificationPayload.js`
5. Rota em `getNavigationMetadata` e `resolveDeeplink`

## Kinds ativos (2026-05)

| Kind | Relatório | Horário |
|------|-----------|---------|
| `daily_digest` | Resumo diário de doses pendentes | digest_time do usuário |
| `adherence_report` | Relatório de adesão (com comparação período anterior) | 23h por TZ |
| `weekly_adherence` | Resumo semanal simples | domingo 23h por TZ |
| `monthly_report` | Resumo mensal | dia 1 10h por TZ |

**How to apply:** Antes de reutilizar um `kind` existente para novo contexto, verificar se os dados, título e comportamento são diferentes. Se sim, criar novo kind. Relacionado a [[R-220]].
