# [R-222] Notification Schema Hardening

**Context:** Notification 3-Layer Architecture (L1, L2, L3).
**Domain:** `server/notifications`

## Rule
Always use strict enums (`z.enum`) for action IDs and parameters in notification schemas to prevent runtime injection, invalid UI states, or silent failures in the dispatcher.

## Reasoning
- Generic `z.string()` allows invalid action types to pass validation but fail at the channel level (Telegram/Push).
- Hardening the schema at L2 ensures that any structural deviation is caught during the payload construction phase.
- Improves IDE autocompletion and developer experience when working with notification builders.

## Examples

### ✅ Correct
```javascript
const actionSchema = z.object({
  id: z.enum(['take', 'snooze', 'skip', 'open_app']),
  label: z.string(),
  params: z.object({
    medicineId: z.string().uuid(),
    dosage: z.string().nullish()
  })
});
```

### ❌ Incorrect
```javascript
const actionSchema = z.object({
  id: z.string(), // Too generic
  label: z.string(),
  params: z.record(z.any()) // Unsafe
});
```
