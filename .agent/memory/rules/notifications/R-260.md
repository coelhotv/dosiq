# R-260 — Som em loop do Notifee + cancelar a notif EXIBIDA p/ parar

**Layer:** warm · **Status:** active · **Pack:** notifications
**Origem:** Spec 001 (Alarme Nativo), PR feat/alarme-nativo, 2026-06-03

## Regra

Para um alarme tocar em **loop até o usuário agir** (Android), combinar no payload:

```js
android: {
  loopSound: true,     // repete o som
  ongoing: true,       // notif não some por swipe
  autoCancel: false,   // não auto-dismiss ao tocar
  // ...
}
```

E, **crucial**, ao tomar a ação (Tomei/Pular/Soneca) o `cancelAlarm` DEVE cancelar
a **notificação JÁ EXIBIDA** — não só o trigger:

```js
await notifee.cancelNotification(doseInstanceId)        // displayed → PARA o som
await notifee.cancelTriggerNotification(doseInstanceId) // trigger pendente
```

`cancelTriggerNotification` sozinho **não para o som** de uma notif já disparada
(o trigger virou notificação exibida). Sem `cancelNotification`, o loop segue
tocando após o usuário escolher.

## Detalhes

- A soneca reusa esse cancelar-primeiro: cancela a atual (mata o som) e re-agenda.
- `loopSound`/`ongoing` são **Android-only** — no-op no iOS (loop contínuo no iOS
  só com Critical Alerts). Ver [[K-091]].
- Registro deve **cancelar antes de gravar no DB** (silencia já, mesmo que o
  registro falhe): `registerTaken/Skip` chamam `cancelAlarm` antes de `registerDose`.

Relacionado: [[R-255]], [[R-261]] (imutabilidade do canal), [[K-091]].
