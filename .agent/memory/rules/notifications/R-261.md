# R-261 — Canal Android é imutável: bumpar o id p/ trocar o som

**Layer:** warm · **Status:** active · **Pack:** notifications
**Origem:** Spec 001 (Alarme Nativo), PR feat/alarme-nativo, smoke Xiaomi, 2026-06-03

## Regra

Um Android Notification Channel é **imutável após criado**. Mudar `sound`,
`importance`, `bypassDnd` etc. de um canal existente **não tem efeito** — o SO
ignora a re-criação com o mesmo id. Para aplicar um som novo, **bumpar o id do
canal**:

```js
export const ALARM_CHANNEL_ID = 'dose-alarm-v3' // v1→v2→v3 a cada troca de som
```

## Por quê

Sintoma real (smoke Xiaomi/HyperOS): o alarme tocava o som **padrão** (gota
d'água) em vez do `alarm_dose.wav`, mesmo com o `.wav` no bundle. Causas
combinadas:
1. Canal criado num build anterior ao plugin de sons (res/raw sem o arquivo) →
   nasceu com som padrão e, por ser imutável, não corrigia nem reinstalando.
2. Re-criar com o mesmo id não atualiza.

Fix: garantir o `.wav` em `res/raw` (plugin `expo-notifications` `sounds`) **e**
bumpar o channel id → canal limpo, recriado com o som certo.

## Detalhes

- Confirmar no device: `adb shell dumpsys notification` → procurar
  `mSound=android.resource://<pkg>/raw/alarm_dose` no bloco do canal.
- Canais antigos (v1/v2) ficam órfãos no device — inofensivos (o app posta só no
  id atual); opcional limpar via `notifee.deleteChannel`.
- iOS não tem esse problema (som é por-notificação, não por-canal).
