# R-315 — PDF/impressão: o texto atravessa uma fronteira de CODIFICAÇÃO, e ela não é UTF-8

**Categoria:** process_and_testing · **Origem:** 073 PR 1 (F-23 + smoke do PO), 2026-08-22

## O fato

As fontes padrão do jsPDF (Helvetica & cia.) codificam em **WinAnsi/cp1252**, não em UTF-8. Isso
significa que:

- **todo acento do português passa** — `ã é ç ú â õ` estão em Latin-1. A crença de que "PDF precisa
  de fonte embutida para escrever português" é falsa e custou uma tarefa inteira de planejamento
  (embutir fonte = ~300KB de bundle) que se revelou desnecessária;
- **sinais tipográficos fora do cp1252 saem como lixo, silenciosamente.** O `≈` (U+2248) que os
  formatadores de dose do core usam saía como `("H` **no meio da dose** — na informação mais crítica
  de um documento clínico. Sem erro, sem warning: o PDF é gerado com sucesso.

## A regra

1. **Não decida por memória.** Antes de embutir fonte ou de "tirar os acentos por segurança",
   MEÇA: gere um PDF de uma linha e extraia com `pdftotext`. Custa 30 segundos.
   ```bash
   node -e "const {jsPDF}=require('jspdf');const d=new jsPDF();d.text('Adesão Período ≈ 0,1 mL',10,20);require('fs').writeFileSync('/tmp/t.pdf',Buffer.from(d.output('arraybuffer')))"
   pdftotext /tmp/t.pdf -
   ```
2. **Sanitize na fronteira, nunca na origem.** O core está certo: na tela o `≈` renderiza. Quem tem
   a limitação é o renderizador — então a tradução (`≈` → `~`, resto fora do conjunto descartado)
   mora no serviço de PDF, num único helper por onde passa todo texto dinâmico (células de tabela e
   `doc.text` interpolado). Mudar o core para agradar o PDF degrada as outras plataformas.
3. **Melhor a ausência que a sujeira** (decisão do PO): caractere não representável é removido, não
   substituído por um placeholder que o leitor interpretará como dado.
4. **Cuidado com o que devolve array.** `doc.splitTextToSize` devolve `string[]`; sanitizar o array
   o transforma numa string com vírgulas. Sanitize ANTES do split.

## O irmão do problema: largura

A mesma classe de falha silenciosa aparece no layout. Quando as colunas de uma tabela somam
exatamente a largura útil da página, o `jspdf-autotable` **estica o texto caractere a caractere**
(`2 , 4  m g`) e apenas registra `Of the table content, N units width could not fit page` no stdout.
Deixe folga e trate esse aviso como falha: ele aparece no console e não em nenhum gate.

**Gate de saída de qualquer mudança em PDF:** gerar o documento com dados REAIS (não fixture
inventado) e extrair com `pdftotext -layout`. Suíte verde não vê glifo trocado nem coluna esticada.
