# R-234 — Smoke PO ANTES de abrir PR (push OK, HOLD `gh pr create`)

**Regra**: ao concluir implementação de feature mobile com smoke obrigatório, fazer `git push` (necessário pra EAS worktree do PO sincronizar) mas **NÃO** abrir PR com `gh pr create`. Aguardar PO validar smoke local primeiro. Só abrir PR depois de "tudo OK" explícito.

**Why**: PRs abertos com bugs UI/UX vivos forçam um ciclo extra de fixes + replies pro reviewer LLM (Gemini) que pode interpretar diff intermediário como "estado final". Ciclos de churn perdidos. Adotado a partir do PR-A Fase 2 (#561) após PO sinalizar "o ideal seria eu ter validado as telas antes de publicar o pr".

**How to apply**:
1. Implementar + lint + jest verde
2. `git push` (branch fica disponível no GitHub + worktree EAS pega via pull no PO)
3. **HOLD** — reportar pro PO: "Pronto pra smoke. Branch `feat/foo-bar` no worktree."
4. PO valida (iOS + Android API 24 + iPhone físico se aplicável)
5. Se bug → fix → push → re-smoke (loop)
6. PO autoriza explicitamente: "tudo validado, pode publicar o pr"
7. ENTÃO `gh pr create`

**Não aplicar quando**:
- PR só toca docs/specs (sem código rodável)
- PR só toca tests/lint (zero impacto user-visible)
- PR é hotfix urgente com smoke já validado em prod
