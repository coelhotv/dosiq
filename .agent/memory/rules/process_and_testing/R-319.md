# R-319 — Memória DEVFLOW mora em `.agent/memory/`, nunca em `plans/`

## Rule

**Todo artefato de memória do DEVFLOW — `CON-NNN`, `ADR-NNN`, `R-NNN`, `AP-NNN` — nasce em
`.agent/memory/<tipo>/<domínio>/` e é registrado no índice correspondente no mesmo C5.**

`plans/` é **gitignored** (purga de 2026-06-23). O que é escrito lá:

- não viaja no `git clone` — nenhum outro agente, máquina ou sessão futura consegue ler;
- não aparece em PR, logo **nunca passa por review**;
- some com a máquina, sem rastro no histórico;
- e — o modo de falha mais traiçoeiro — **o índice versionado pode apontar para ele**, produzindo
  uma entrada que parece registrada e resolve num link morto para quem não é o autor.

`plans/specs/NNN/` continua sendo o lugar certo de `spec.md`, `plan.md`, `tasks.md`,
`design-brief.md` e afins: são artefatos **de trabalho**, efêmeros, cujo valor acaba quando o épico
fecha. A distinção é essa:

| Pergunta | Vive em |
|---|---|
| "como vamos construir isso?" (efêmero, morre com a entrega) | `plans/specs/NNN/` |
| "o que ficou decidido/contratado?" (permanente, sobrevive ao épico) | `.agent/memory/` |

**Teste de decisão:** *se a spec fosse apagada amanhã, este arquivo ainda precisaria existir?*
Se sim, é memória — vai versionado.

### O que é local-only DE PROPÓSITO (não "consertar")

O `.gitignore:76` declara a intenção: *"keep rules/anti-patterns/decisions/contracts/knowledge
shared, ignore only local runtime/journals"*.

| Caminho | Estado | Por quê |
|---|---|---|
| `.agent/memory/{rules,anti-patterns,decisions,contracts,knowledge}/` | **versionado** | é a memória compartilhada — o alvo desta regra |
| `.agent/memory/journal/` · `.agent/state.json` · `.agent/sessions/` | **ignorado de propósito** | runtime local, alto churn, específico da máquina |
| `plans/specs/README.md` | **versionado** (única exceção rastreada em `plans/`) | é o índice canônico de status — precisa viajar |
| resto de `plans/**` | **ignorado** | `/plans/` na linha 137; a negação `!/plans/specs/` **não** re-inclui os arquivos, porque o git não desce em diretório pai excluído |

⚠️ O último item é a pegadinha que criou o incidente: `!/plans/specs/` **parece** re-incluir a
pasta e não re-inclui. Quem escreveu o CON-033 lá dentro tinha motivo razoável para achar que
seria versionado.

## Gate

No C5 que aceita um contrato/ADR/regra/AP:

```bash
# 1. o arquivo está sob controle de versão?
git ls-files --error-unmatch .agent/memory/contracts/<domínio>/CON-NNN.md

# 2. nenhum índice aponta para plans/
rtk grep -rn "plans/specs" .agent/memory/*_INDEX.md
```

`git mv` que falha com **`fatal: not under version control`** é o sintoma exato desta regra: o
artefato nunca esteve versionado.

## Origem

**CON-033** (kill switch de versão mínima, spec 051-A PR 1.5b) foi escrito em
`plans/specs/051-expo-updates/contracts/CON-033-version-gate.md` e registrado no
`CONTRACTS_INDEX.md` — versionado — com link relativo para o caminho gitignored. Ficou assim de
2026-07-26 a 2026-08-15, quando a conciliação do backlog o encontrou.

O contrato descreve o resolver que decide **bloqueio de boot de toda a base instalada**
(`resolveVersionGate`, tabela-verdade fail-open). Ou seja: a interface mais destrutiva do app tinha
seu contrato normativo existindo em uma única máquina, enquanto o índice do repo anunciava que
estava registrado.

Nenhum gate pegou porque todos os gates olham código — `tsc`, lint, testes, `strict-island.sh`.
Nenhum deles lê o `.gitignore` contra a árvore de memória.
