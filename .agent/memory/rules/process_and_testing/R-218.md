# R-218: Sub-agentes Sempre Branch + PR + Aprovação Humana

## Context
Sub-agentes spawned pelo agente principal para refatoração em lote (lint waves, cleanup, etc.) têm acesso a ferramentas de escrita e git. Sem restrição explícita, commitam direto na branch ativa.

## Rule
Todo prompt de sub-agente para refatoração DEVE conter:

```
⚠️ REGRA CRÍTICA DE GIT:
1. Crie branch: git checkout -b refactor/<wave>/<nome>
2. Implemente as mudanças
3. Rode o gate de validação
4. Reporte resultado ao agente principal
5. PARE — não abra PR, não faça merge, não commite na main
Aguarde aprovação humana explícita antes de qualquer ação git adicional.
```

## Fluxo Correto
```
Sub-agente → branch feature → implementa → gate → reporta
Agente principal → verifica gate → abre PR
Usuário → revisa PR → aprova textualmente
Agente principal → aguarda Gemini review → aplica sugestões
Usuário → aprovação final → merge
```

## Nunca
- Sub-agente commitar direto na `main`
- Sub-agente abrir PR sem instrução do agente principal
- Agente principal fazer merge sem aprovação humana (R-060)
- Pular review do Gemini após push

## Consequência de Violação
Regressões de produção silenciosas: layout quebrado, features inacessíveis, bugs de auth — detectáveis apenas em uso real, difíceis de reverter.
