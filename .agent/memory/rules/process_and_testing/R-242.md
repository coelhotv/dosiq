# R-242 — Release Impact Classification and Version Bumps

## Rule
Every code-changing PR must classify its release impact before commit and PR creation.

Required classification:
- `patch`: bug fix, safe technical correction, copy fix, internal behavior correction with no new user-facing capability.
- `minor`: new user-facing feature, meaningful UX addition, additive API/data behavior, store-visible improvement.
- `major`: breaking migration, incompatible user behavior, destructive data model transition, or required user/operator migration.
- `no-user-impact`: documentation, tests, tooling, or process-only work that does not change product behavior.

When impact is not `no-user-impact`, update affected platform version source(s):
- Web/PWA: `apps/web/package.json`
- Mobile: `apps/mobile/app.config.js` `APP_VERSION`

Shared/Core changes must bump every product platform that consumes the changed behavior.

## Why
Monorepo work can affect Web/PWA, Mobile, or both. Explicit classification prevents version drift and makes release notes traceable from PR to store submission.
