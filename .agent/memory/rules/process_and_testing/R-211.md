# [R-211] Automated ESLint Architecture (Flat Config)

## Contexto
O projeto utiliza uma configuração centralizada do ESLint (`eslint.config.js`) em formato Flat Config para garantir a integridade do código em todo o monorepo (Web, Mobile, Server, API).

## Regras
1. **Unidade de Configuração:** Todas as validações devem residir no root `eslint.config.js`.
2. **Scoping por Domínio:**
   - **Web:** Foco em React 19, imports de features e design tokens.
   - **Mobile:** Foco em React Native, acessibilidade e aliases locais.
   - **Server/API:** Foco em Node.js (`eslint-plugin-n`), permitindo `console.log` para observabilidade, mas proibindo `process.exit()`.
3. **Guardrails de IA:**
   - Regras críticas (R-020, R-204, R-116, R-122) são automatizadas via `no-restricted-syntax`.
   - Violações nessas regras bloqueiam o commit via `lint-staged`.
5. **Integração CI (Remoto):**
   - **Linting Incremental:** Em Pull Requests, as validações de lint devem rodar apenas sobre o delta de arquivos alterados (usando `tj-actions/changed-files`).
   - **Economia de Recursos:** Workflows devem utilizar `concurrency` (cancel-in-progress) e `paths-ignore` (docs, scripts, agent memory) para otimizar o uso de minutos do GitHub Actions.
   - **Progressive Enforcement:** O CI deve bloquear regressões nos arquivos alterados, mesmo que o projeto possua dívida técnica em arquivos não tocados.

## Benefícios
- Prevenção de regressões comuns causadas por agentes de IA.
- Feedback imediato durante o desenvolvimento.
- Consistência arquitetural entre diferentes stacks (Node, React, React Native).
