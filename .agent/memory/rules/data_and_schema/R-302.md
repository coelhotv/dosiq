# R-302 — DROP de coluna: o gate é o banco perguntando por ela, não o `grep` do código

**Camada:** hot · **Status:** active · **Origem:** 029 F6 (2026-07-21) · **Criada em:** 2026-07-21
**Aplica-se a:** qualquer DDL destrutivo (DROP COLUMN/TABLE, rename, mudança de tipo) em prod
**Relacionadas:** [[R-295]] · [[R-289]] · [[R-270]] · [[AP-300]] · [[AP-315]]

## Regra

Antes de dropar uma coluna, o `grep` em `apps/ packages/ server/ api/` é **necessário e
insuficiente**. Ele cobre o código versionado; não cobre o que vive DENTRO do banco. Rodar,
sempre, e colar o resultado:

```sql
with pat as (select '(col_a|col_b)' p)
select 'view', schemaname||'.'||viewname, null from pg_views, pat
  where schemaname not in ('pg_catalog','information_schema') and definition ~ p
union all select 'matview', schemaname||'.'||matviewname, null from pg_matviews, pat where definition ~ p
union all select 'function', n.nspname||'.'||f.proname, pg_get_function_identity_arguments(f.oid)
  from pg_proc f join pg_namespace n on n.oid=f.pronamespace, pat
  where n.nspname not in ('pg_catalog','information_schema') and f.prosrc ~ pat.p
union all select 'constraint', conname, pg_get_constraintdef(oid) from pg_constraint, pat
  where pg_get_constraintdef(oid) ~ p
union all select 'index', indexname, indexdef from pg_indexes, pat where schemaname='public' and indexdef ~ p
union all select 'default/generated', table_name||'.'||column_name,
  coalesce(column_default,generation_expression) from information_schema.columns, pat
  where table_schema='public' and (coalesce(column_default,'') ~ p or coalesce(generation_expression,'') ~ p);

-- E, separado (pg_policies não entra no union acima sem cast):
select tablename, policyname, qual, with_check from pg_policies
 where (coalesce(qual,'')||coalesce(with_check,'')) ~ '(col_a|col_b)';
```

**Por que os dois lados.** Uma view que referencia a coluna faz o Postgres **abortar** o DDL com
erro de dependência — barulhento, você descobre na hora. Uma **função/RPC** não: `prosrc` é texto,
o Postgres não valida corpo de função no DDL, e ela só quebra **em runtime**, no primeiro usuário
que acionar aquele caminho. Uma **policy RLS** quebrada é pior ainda: falha como negação de acesso,
que parece problema de permissão e manda a investigação para o lado errado.

## Prova de saída, em três tempos

Não basta dropar e rodar os testes (o client de teste está mockado — [[AP-300]]). O DROP só está
provado com:

1. **Antes:** cada select alterado executado contra o PostgREST real → `200`.
2. **Depois:** os MESMOS selects → `200` de novo.
3. **Controle:** um select pedindo explicitamente a coluna dropada → **`42703`**.

O passo 3 é o que costuma faltar e é o mais informativo: ele prova ao mesmo tempo que o DDL
aconteceu de verdade **e** que o seu gate detecta um select desatualizado. Sem ele, "os selects
deram 200" pode significar apenas que você testou selects que já não pediam a coluna.

## Ordem inegociável

`repontar → grep zero → varredura do banco → curl (antes) → DROP → curl (depois) + controle`,
tudo no **mesmo PR**. Separar limpeza de DROP é criar, de propósito, a janela em que existe código
pedindo coluna inexistente — o `42703` do #750, que derrubou web+mobile+cron (sem dose, sem estoque)
e atravessou tsc, lint, 2068 testes, RC5 e review externo.

## Farol

Se a justificativa para dropar é "o `grep` deu zero", pergunte: *grep de quê?* Código versionado é
uma das cinco superfícies que podem pedir a coluna. As outras quatro moram no banco e nenhuma
ferramenta de build as enxerga.
