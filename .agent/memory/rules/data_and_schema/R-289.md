# R-289 — Regenerar `database.types.ts` no MESMO PR que aplica a migração

**Classe**: data_and_schema · **Status**: active · **Layer**: hot
**Criada**: 2026-07-11 (044 F2 / PR #736-#737)

## Regra

Toda migração que altera o schema de prod (coluna, tabela, assinatura de RPC, enum) DEVE vir
acompanhada do regen dos tipos no MESMO PR:

```bash
npm run supabase:types    # exige `npx supabase login` (Personal Access Token sbp_ da conta)
```

Se o regen não for possível na sessão (sem autenticação), é permitido **editar o tipo à mão**
para destravar o trabalho — mas o PR **declara a dívida explicitamente** e o regen entra antes
de fechar a fase. Migração mergeada com tipos não-regenerados é dívida silenciosa, não "detalhe".

## Por que (evidência)

Descoberto no 044 F2: o regen — feito só no fim, por insistência do PO — revelou que os tipos
estavam desatualizados **desde a 043**: faltavam `notification_outbox` (043) e as FKs
`user_id → auth.users` das tabelas de dose (046). Duas migrações em prod, **dois épicos**, sem
regen. Ninguém sentiu porque nenhum código tipado tocava essas tabelas ainda — mas o primeiro
a tocar receberia tipos MENTINDO sobre o schema real, e o TS teria "aprovado" o código errado.

O erro é assimétrico: o custo do regen é 1 comando; o custo de descobrir tarde é um bug que o
compilador jurou não existir.

## Como aplicar

1. Aplicou/escreveu migração → rode `npm run supabase:types` no mesmo PR.
2. **Confira o diff**: ele deve conter APENAS o que a sua migração mudou. Qualquer coisa a mais
   é **drift acumulado** de migrações anteriores — reporte no PR (foi assim que a 043/046
   apareceram), não engula junto em silêncio.
3. Sem token na sessão → hand-edit + dívida declarada no PR + regen antes do fim da fase.

## Nota de credencial (armadilha real)

`supabase gen types --project-id` autentica na **Management API** e exige um **Personal Access
Token da conta** (`sbp_...`, em supabase.com/dashboard/account/tokens ou via `npx supabase
login`). A `service_role` key do `.env.local` **NÃO serve** — é credencial de runtime do banco,
não de gerenciamento. Sem o token o comando falha **em silêncio, gerando arquivo vazio**: sempre
conferir `git diff --stat` depois (o modo de falha é o arquivo encolher para ~1 linha).

Alternativa sem PAT: `npx supabase gen types typescript --db-url "postgresql://postgres:[SENHA]@db.<ref>.supabase.co:5432/postgres"`.
