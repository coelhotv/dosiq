# R-270 — DB Change Preflight (migração / RPC / função SQL)

**Layer**: hot · **Category**: data_and_schema · **Created**: 2026-06-07 · **Updated**: 2026-06-07 (#651)
**Pack**: schema-data, infra-api · **Motivação**: PRs #650/#651 (022 Fases A/B) — revisor externo pegou 11 defeitos comportamentais que o C1.5 estrutural não viu. Gemini aposenta ~07/2026; o gate passa a ser disciplina de processo (sem revisor de IA).

## Regra
Antes de aplicar QUALQUER migração/RPC/função SQL **OU schema Zod / serviço com lógica numérica ou de coerção**, preencher o **Preflight** abaixo no `analysis.md` (Tier 2) ou no gate C2 (Tier 1). Cada item é PASS explícito ou correção — não "parece ok".

### 1. Failure Modes & Degenerate Inputs (tabela obrigatória)
Pra cada função/RPC/schema/serviço novo, enumerar e responder ANTES de codar:

| Input / condição | Degenerado | Comportamento esperado | Coberto? |
|------------------|-----------|------------------------|----------|
| cada arg nullable | `NULL` | (raise / default / skip) | |
| numérico divisor | `0` / `NULL` | sem divisão por zero (`NULLIF` / guard) | |
| quantidade | arredonda p/ `0.00` | não consumir silenciosamente → raise | |
| JOIN/FK opcional | linha ausente (ex: `protocol_id NULL`) | default seguro, nunca pior-caso | |
| coluna de filtro | valor `NULL` | comparação NULL-safe (ver item 2) | |
| boundary | min/max/vazio | definido | |
| **split monetário/ratio** (`total / n`, custo/ml) | **centavo-limite** (R$0,04÷6 → arredonda p/ cima > total) | **truncar** (`Math.floor`), resíduo no último ≥ 0 — nunca preço negativo (#651) | |
| **campo numérico Zod opcional** (`z.coerce.number`) | **`''`** (form limpo) | `z.preprocess('' => null)` — `coerce` NÃO pode virar `0` e falhar `.positive()` (#651) | |
| **string numérica localizada** | **vírgula** (`'1,0'`) | normalizar `,`→`.` antes de `Number()` (senão `NaN` quebra singular/comparações) (#651) | |

### 2. Semântica SQL (3-valued logic)
- Comparação `col != 'x'` **exclui NULL** silenciosamente → usar `(col IS NULL OR col != 'x')` ou `col IS DISTINCT FROM 'x'` quando NULL deve passar.
- `NOT IN (subquery com NULL)` → sempre falso. Evitar.

### 3. Integridade estrutural
- Coluna TEXT de domínio finito consumida por match exato → **CHECK** sincronizado com o enum do core ([[R-271]]).
- `CREATE OR REPLACE` de função existente → **diff vs `pg_get_functiondef`** de TODOS os overloads ([[AP-217]]); grep callers por overload ([[AP-215]]).
- SECURITY DEFINER → `search_path = ''` + refs `public.` qualificadas + REVOKE PUBLIC/anon + GRANT explícito.
- Migração idempotente (`IF [NOT] EXISTS` / `DROP … IF EXISTS`) + validação de contagem pós-migração.

### 4. Teste por failure mode (não só happy-path)
Cada linha "Coberto?" da tabela do item 1 precisa de um teste — preferência por harness transacional `BEGIN … ROLLBACK` no DB ao vivo (prod intocado, asserts reais), incluindo os casos que **devem levantar exceção**.

## Evidência
- **PR #650** (Fase A, SQL): protocol_id NULL, units_per_ml=0, dose→0, entry_type NULL ×2, CHECK intake_unit — 7 defeitos. Commit 53d3c09f.
- **PR #651** (Fase B, core/Zod/serviço): unit_price negativo em centavo-limite (split monetário), `z.coerce('')→0` em 2 campos opcionais, vírgula→NaN no plural — 4 defeitos da **mesma classe comportamental**, mas em schema/serviço (não SQL). Por isso o escopo do preflight foi ampliado p/ schema Zod + serviços numéricos. Commit f8c8a005.

Lição transversal: defeitos estão quase sempre nos **inputs degenerados** (NULL, 0, vazio, centavo-limite, vírgula, FK ausente), raramente no happy-path. Estrutura (símbolo existe/casa) ≠ robustez. Relacionados: [[AP-217]], [[AP-215]], [[R-082]], [[R-271]].
