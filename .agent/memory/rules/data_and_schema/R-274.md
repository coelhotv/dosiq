# R-274 — Zod v4: separar base schema quando schema tem `superRefine` + `validateUpdate`

## Regra

Sempre que um schema Zod usar `.superRefine()` **e** existir uma função `validateXxxUpdate`
que chama `.partial()`, o schema DEVE ser dividido em dois:

```js
// ✅ OBRIGATÓRIO quando superRefine + validateUpdate coexistem
const xBaseSchema = z.object({ ... })           // sem refinements

const xSchema = xBaseSchema.superRefine(...)    // com cross-field validation

export function validateXCreate(data) {
  return xSchema.safeParse(data)                // superRefine ativo
}

export function validateXUpdate(data) {
  return xBaseSchema.partial().safeParse(data)  // .partial() funciona
}
```

## Por quê (Zod v4)

Zod v4 proíbe `.partial()` em schemas com refinements. O erro lança **em runtime**,
não em build nem em lint — invisível até chegar em produção (AP-223).

```
Error: .partial() cannot be used on object schemas containing refinements
```

## Verificação no C1 / ao adicionar superRefine

Antes de adicionar `.superRefine()` a qualquer schema:
1. Verificar se existe `validateXxxUpdate` no mesmo arquivo
2. Se sim → extrair `BaseSchema` imediatamente, antes de escrever o superRefine
3. Atualizar `validateXxxUpdate` para usar `BaseSchema.partial()`

## Nota sobre semântica

Update é PATCH — campos ausentes são ignorados. Cross-field validation do superRefine
(ex: `action_type === 'navigate'` exige `action_payload.screen`) só faz sentido
quando ambos os campos estão presentes. O frontend já valida antes de submeter;
o backend valida shape individual via `.partial()`.
