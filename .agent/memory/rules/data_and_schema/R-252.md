# [R-252] Timeline event-agnóstica (FP-3): builder puro + adapter isolado

**Status:** active · **Layer:** warm · **Domain:** data_and_schema
**Criado:** 2026-05-31 (PR-F4.1 / Fase 4)

## Regra
O histórico é uma **stream de eventos tipados** (`TimelineEvent = {id,type,occurred_at,payload}`),
ordenada por **instante absoluto** (`occurred_at`, UTC). Realização do FP-3 (ADR-050):

1. **Builder PURO** (`buildTimeline`): só ordena por instante e deriva `localDay` no `tz`.
   Não conhece nenhuma fonte concreta. Agrupamento por dia é derivação de exibição
   (`groupByLocalDay`) — nunca altera a ordem absoluta. Cross-meia-noite é natural.
2. **Adapter ISOLADO** (`doseInstancesToEvents`): único ponto que conhece `dose_instances`
   /`medicine_logs`. Converte → `TimelineEvent[]` de `type='dose'`. Um tipo futuro
   (`biomarker`/`note`) entra como NOVO adapter + renderizador, **sem tocar builder nem UI**.
3. **UI** itera por `event.type` com um **registry** de renderizadores.

## Invariantes do adapter
- Instância ancorada (`taken`) + seu `medicine_log` = **1 evento** (não 2).
- `taken` usa `taken_at` real como `occurred_at`; `missed`/`pending` usam `scheduled_for`.
- `skipped_*` ocultos da timeline (neutros).
- Log avulso (sem elo) coberto por slot representado dentro da tolerância é **suprimido**
  (AP-193) — estado real prevalece; PRN/freeform legítimos viram eventos próprios.
- Limites de janela em UTC real (AP-194); `tz` só na derivação de dia local.
