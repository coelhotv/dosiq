# R-253 — Captura de fuso do device no onboarding + reconciliação passiva

## Regra

Capturar o fuso **real do device** no **primeiro ponto determinístico da conta —
a confirmação de signup** (verifyOtp `'signup'` OK), ANTES do onboarding, e
gravá-lo em `user_settings.timezone`. Capturar no signup (não só no fim do
onboarding) cobre **quem pula o wizard** e deixa o tz pronto para a geração do
**1º tratamento** (passo 3 do onboarding) já no fuso correto. O
`completeOnboarding(tz?)` mantém a gravação como **rede de segurança**
(idempotente). Detalhes:

- Fonte: `Intl.DateTimeFormat().resolvedOptions().timeZone` (helper core
  `getDeviceTimezone()`), chamado em **escopo de função** (R-199/AP-155 — nunca
  module-scope; Hermes legado → try/catch retorna `null`).
- Normalizar com `resolveSupportedTz(deviceTz)` → opção da lista curada
  (`TIMEZONES_BR`, ADR-053) ou `DEFAULT_TIMEZONE` (`America/Sao_Paulo`). Fora da
  lista / nulo → SP. Nunca lança.
- Armazenar **SEMPRE o nome IANA**, nunca offset (DST = identidade por nome).
- **Sem dependência nativa nova** no mobile (`Intl`, não `expo-localization`) —
  evita rebuild de provisioning (AP-179). Helper core compartilhado web↔mobile
  (R-231).
- O writer compartilhado (`createProfileRepository.completeOnboarding(timezone?)`)
  só grava o tz quando vier válido; ausente **preserva o DEFAULT do DB** (R-082) —
  nunca sobrescrever com SP às cegas.

Reconciliação dos **usuários existentes** (que nasceram no DEFAULT porque a UI
nunca capturou o fuso): **nudge passivo** no Perfil (card dispensável → CTA p/ o
seletor de fuso). NUNCA prompt de fuso no app-load, NUNCA auto-write de tz no
boot. Dismiss persiste (localStorage web / AsyncStorage mobile).

## Por quê

`timezone` com `DEFAULT 'America/Sao_Paulo'` é **artefato do default**, não prova
de localização — expat silencioso (fisicamente fora, tz=SP errado) existe.
Backfill é impossível (tz real desconhecido). Capturar na criação corrige daqui
pra frente sem perturbar dados; reconciliar existentes só por convite respeita a
autonomia (a troca real é uma ação consciente — ver F4.3f.2 prompt de intenção).
