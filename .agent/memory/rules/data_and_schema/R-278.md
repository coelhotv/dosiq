# R-278 — Contexto de IA escopa tratamentos ativos com prescrição válida

**Domínio:** dados / IA / contexto clínico
**Origem:** 2026-06-22 (endurecimento do Chatbot IA, parte B)

## Regra

Ao montar o contexto do paciente para o LLM (web `contextBuilder.js` e Telegram
`chatbotServerService.buildServerContext`), considerar **somente tratamentos ATIVOS com
prescrição válida na data da interação**:

```js
protocols.filter(p => p.active && isProtocolActiveOnDate(p, hoje))
```

`isProtocolActiveOnDate` (core) = `start_date ≤ hoje ≤ end_date` (end_date = validade da
prescrição). Exclui finalizados (end_date passado), pausados (`active === false`) e
não-iniciados (start_date futuro).

## Por quê

Iterar **todos** os `medicines` (independente do status do protocolo) fazia o bot raciocinar
sobre cursos já encerrados — ex.: sugerir repor estoque de um antibiótico (Amoxicilina+Clavulanato)
cujo tratamento já terminou. Para respostas de estoque/reposição/doses, só o que está vigente importa.

## Aplicação

- Filtrar protocolos por `active && isProtocolActiveOnDate` ANTES de montar `medsContext`.
- Só incluir medicamentos com protocolo válido (Set de `medicine_id` válidos).
- No Telegram, a query de `protocols` precisa trazer `start_date, end_date` (além de `active`)
  para o filtro funcionar.
- Surface de runway (consumo diário + dias restantes) e doses (próximas/atrasadas via
  `splitDayTimeline`) só dos tratamentos válidos.
