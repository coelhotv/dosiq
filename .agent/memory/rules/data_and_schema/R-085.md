# R-085 — Nullable Schema Fields [HIGH]

## Rule
When a field can receive `null` from external sources (APIs, databases, parsers), use `.nullable().optional()` in Zod. Using only `.optional()` allows `undefined` but rejects `null`.

## Pattern
```javascript
// CORRECT — accepts undefined, null, or string
const schema = z.object({ suggestion: z.string().nullable().optional() })

// WRONG — rejects null
const schema = z.object({ suggestion: z.string().optional() })
```

## Source
Sprint 7 (PR #151) — suggestion field rejecting null from Gemini response

## Consolidated anti-patterns
- `AP-S02` — model nullable external data as optional-only

Use this rule as the canonical guidance for nullable Zod fields. The AP remains as a negative lookup.
