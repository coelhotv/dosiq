## Regra

Adicionar campo à tabela `protocols` (ou qualquer entidade central com Zod
schema + múltiplos selects distribuídos) exige atualização em 4 lugares.
Esquecer qualquer um causa bug silencioso.

## Checklist obrigatório

### 1. Schema Zod (packages/core)
```
packages/core/src/schemas/protocolSchema.js
  → adicionar campo em protocolSchema (base)
  → verificar protocolUpdateSchema = protocolSchema.partial() (herda automaticamente)
  → verificar protocolCreateSchema se existe
```

### 2. Todos os service selects que buscam protocols
```bash
grep -r "from('protocols')" apps/ packages/ server/ --include="*.js" --include="*.jsx" -l
# Para cada arquivo: verificar se o .select() inclui o novo campo
```

Arquivos críticos no dosiq (2026-06-04):
- `apps/mobile/src/features/dashboard/services/dashboardService.js` → `getActiveProtocols`
- `apps/mobile/src/features/treatments/services/treatmentsService.js`
- `apps/web/src/services/api/*.js` (web equivalents)

### 3. Telas de detalhe
Toda tela que exibe os dados de um protocolo deve mostrar o novo campo
(ou ocultá-lo explicitamente com justificativa).

No mobile: `ProtocolDetailScreen.jsx` deve espelhar a ordem de campos do form de edição.

### 4. Migration SQL
Seguir o template CLAUDE.md:
```sql
ALTER TABLE public.protocols ADD COLUMN <campo> <tipo> DEFAULT <valor>;
-- + GRANT se tabela nova (existentes têm grants)
```

## Por que 4 lugares?

- **Schema Zod**: `safeParse()` stripa campos desconhecidos → AP-214
- **Selects**: slim select por performance (R-127) → campo ausente → sempre `undefined`
  → lógica derivada (`hasCriticalProtocol`) sempre falsa → AP-215
- **Telas de detalhe**: campo salvo mas não exibido → usuário não vê estado → confusão UX
- **Migration**: campo não existe no DB → insert/update falha silenciosamente

## Relação com APs

- AP-214: schema sem campo → Zod stripa em update
- AP-215: select sem campo → hook com side effect cancela tudo prematuramente
