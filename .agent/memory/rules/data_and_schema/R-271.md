# R-271 — CHECK constraint em toda coluna TEXT de domínio finito

**Layer**: hot · **Category**: data_and_schema · **Created**: 2026-06-07
**Pack**: schema-data · **Generaliza** [[R-082]] (Zod ↔ CHECK sincronizados).

## Regra
Toda coluna `TEXT` cujo conjunto de valores é **finito e conhecido** — e especialmente se alguma lógica (RPC, trigger, app) faz **match exato** sobre ela — DEVE ganhar uma `CHECK` sincronizada com o enum equivalente no core (`packages/core/src/schemas`).

Sem CHECK, o DB aceita `'UI'`/`'ui'`/`'Gotas'`/typos → a lógica de match exato falha silenciosamente (cai em branch errado, não converte, etc).

```sql
ALTER TABLE public.<t> DROP CONSTRAINT IF EXISTS <t>_<col>_check;
ALTER TABLE public.<t> ADD CONSTRAINT <t>_<col>_check
  CHECK (<col> IN ('val1','val2'));  -- NULL passa automaticamente; alinhar caixa com o core
```

## Cuidados
- **Caixa exata**: alinhar com o enum do core (ex: `intake_unit` usa `'UI'` maiúsculo, não `'ui'`).
- **Valores legados**: antes do ADD, `SELECT DISTINCT <col>` — garantir que todos cabem no set (ou migrar primeiro), senão o ADD falha em tabela viva.
- NULL passa CHECK por padrão; se NULL não for válido, adicionar `NOT NULL` separado.

## Evidência
PR #650 (022 Fase A): `protocols.intake_unit` nasceu `TEXT` sem CHECK; RPC `consume_stock_fifo` faz `v_intake_unit='gotas'` (match exato). Adicionado `protocols_intake_unit_check ('gotas','ml','UI')`. Relacionados: [[R-082]], [[R-270]].
