# R-297 — Campo que o gerador consome vem de um select: prove o embed com teste de CONTRATO, não com teste de unidade

**Classe:** guard de string de select · paridade write-path
**Origem:** spec 052 Slice A (PR #761), gap G1 achado no C1.5
**Relacionadas:** [[AP-300]] · [[AP-301]] · [[AP-308]] · [[R-295]] · [[CON-032]]

## O problema que ela resolve

Um select do PostgREST é **string**. Quando uma função pura (aqui, `generateInstances`) consome um
campo que chega por embed, existe um caminho de falha que **nenhum gate do projeto enxerga**:

- `tsc` não vê — a string não é tipada;
- `lint` não vê — é literal válido;
- o teste da função pura não vê — recebe o objeto **montado à mão** no fixture, com o campo presente;
- o teste do service não vê — o client está mockado e devolve o que o mock quiser.

Resultado: adicionar o campo ao tipo e esquecê-lo em **um** dos selects dá `undefined` em runtime,
naquele caminho só, em silêncio. Foi exatamente o gap G1 da 052: `medicine_id` não existia em
nenhum dos 6 embeds `titration_steps(...)`, e implementar o plano ao pé da letra teria congelado o
medicamento errado por escrita — permanente e invisível.

## A regra

Quando um campo novo alimenta um gerador/motor **através de um embed**, o PR que o adiciona escreve
um **teste de contrato** que varre os arquivos-fonte e falha se qualquer select do inventário
esquecer o campo. O teste é sobre o CONJUNTO de caminhos, porque o defeito não mora em nenhum
arquivo errado — mora no vão entre eles (mesma raiz de [[AP-301]] e [[AP-308]]).

Implementação canônica: `packages/core/src/utils/__tests__/titrationEmbedContract.test.ts`.

```ts
const EMBEDS_QUE_ALIMENTAM_O_GERADOR = [ /* caminhos dos N selects */ ]

it.each(EMBEDS_QUE_ALIMENTAM_O_GERADOR)('%s traz medicine_id no embed', (arquivo) => {
  const embeds = [...readFileSync(arquivo, 'utf8').matchAll(/titration_steps\(([^)]*)\)/g)]
  expect(embeds.length).toBeGreaterThan(0)          // não passar por vacuidade (AP-279)
  for (const e of embeds.filter((x) => /\bdose\b/.test(x))) expect(e).toContain('medicine_id')
})
```

Três detalhes que fazem o teste valer:

1. **Assertar que achou algo** (`length > 0`). Sem isso, apagar o embed faz o teste passar por
   vacuidade — o falso-verde da família [[AP-279]].
2. **Filtrar por um campo âncora** (aqui `dose`): só os embeds que alimentam o gerador precisam do
   campo. Embed de contagem/badge não precisa, e exigir dele geraria ruído que leva a afrouxar o guard.
3. **Lista explícita de arquivos**, não glob: caminho de escrita novo entra na lista **no mesmo PR**
   que o cria — a lista é o inventário versionado, e revisá-la é revisar a cobertura.

## Complemento obrigatório (R-295)

O teste de contrato prova que o campo está **na string**. Ele NÃO prova que o PostgREST aceita o
select nem que o campo chega preenchido. Antes do merge, executar o select alterado:

```bash
curl -s "$SUPABASE_URL/rest/v1/protocols?select=$(echo "$SELECT" | tr -d '[:space:]')&limit=1" \
  -H "apikey: $KEY" -H "Authorization: Bearer $KEY"
```

`200` + **campo preenchido com dado real** é a prova completa. Um `200` sozinho só diz que a sintaxe
passou.
