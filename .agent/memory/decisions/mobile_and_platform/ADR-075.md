# ADR-075 — Abordagem nativa iOS para Live Activity (config plugin custom Swift agora; expo-widgets no roadmap)

**Status:** accepted (spec 039, Planning 2026-06-27)
**Contexto de origem:** épico 039 Dose State Machine (Fase 3 — MVP iOS)

## Contexto

A Fase 3 do épico 039 exige uma **Live Activity + Dynamic Island** com **botões interativos**
(Registrar/Adiar) que agem sem abrir o app. Live Activity é Swift (Widget Extension) por
construção — não há caminho 100% JS/RN. Três opções avaliadas no Specifying (§4 da spec):

1. **`expo-live-activity`** (Software Mansion, 517★): **DEPRECADA** (v1.0.0 jun/2026) e **sem
   App Intents / botões interativos** → não permite Registrar pela ilha → inviável (Registrar é
   core do MVP). **Descartada.**
2. **`expo-widgets` / `@expo/ui`** (oficial Expo): viva, suporta Live Activity + Dynamic Island
   + Button `onPress` (iOS 17+). **PORÉM exige Expo SDK 56** — dosiq está no **SDK 53** (3 majors
   acima = épico de upgrade separado, arriscado, fora do escopo server-free do 039). Runtime do
   widget isolado (`@expo/ui/swift-ui`, sem hooks/RN/async).
3. **Config plugin custom + Widget Extension Swift + App Intents** (escolhida): roda no **Expo 53
   atual**, App Intents completos, alinhado aos plugins nativos já existentes no projeto
   (`withFirebaseFix.js`, `withAlarmPermissions.js` em `apps/mobile/`). Custo: mais código Swift
   mantido à mão.

## Decisão

**(c) Config plugin custom + Widget Extension Swift + App Intents, agora, no Expo 53.**
Migração para `expo-widgets` fica como **roadmap**, condicionada a um futuro upgrade Expo 53→56
(épico próprio). Isto desbloqueia o 039 imediatamente sem amarrá-lo a um upgrade de 3 majors.

## Consequências

**Positivas:**
- 039 avança sem bloquear no upgrade de SDK (risco isolado).
- App Intents completos → Registrar/Adiar direto da ilha (paridade funcional com Android, FR-004/005).
- Consistente com a infra nativa existente (config plugins + prebuild `ios/`).

**Negativas / custos:**
- Código Swift custom mantido manualmente (Widget Extension + App Intent handler + App Group bridge).
- **iOS 17+ efetivo** para botões interativos (display-only = 16.2). dosiq hoje `minimumOSVersion 15.5`
  → abaixo de 17 cai em fallback (notificação interativa atual). Impacto na base a confirmar.
- Comunicação app↔widget via **App Group** (escrita do registro pelo App Intent handler) — exige
  revalidação de sessão viva no handler (cruza PO-SEC-2; nunca usar userId cacheado).

## Caminho de migração (roadmap)

Quando o upgrade Expo 53→56 acontecer (épico separado), reavaliar trocar o Widget Extension custom
por `expo-widgets`/`@expo/ui` — reduz superfície Swift mantida à mão. Não-breaking para o core
(`DoseActivityState` é platform-agnostic; só muda a camada de render iOS).
