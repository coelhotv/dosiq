# ADR-034 — Política Wave N2 de notificações

## Status

Proposed.

## Contexto

Wave N1 reduz spam de doses simultâneas agrupando notificações por blocos semânticos. Wave N2 precisa resolver o próximo nível do problema: permitir que o usuário controle quando e onde recebe avisos, e transformar telas nativas soltas em uma experiência coerente.

O estado atual usa `user_settings.notification_preference` como enum legado (`telegram`, `mobile_push`, `both`, `none`). Esse modelo não escala para Web Push (PWA), porque `web_push` não cabe no enum sem quebrar compatibilidade e porque a existência de uma subscription web não deve, sozinha, significar opt-in.

## Decisão Proposta

1. Adicionar em `user_settings` campos explícitos para política temporal:
   - `quiet_hours_start`
   - `quiet_hours_end`
   - `notification_mode` (`realtime`, `digest_morning`, `silent`)
   - `digest_time`

2. Adicionar flags explícitas de canal:
   - `channel_mobile_push_enabled`
   - `channel_web_push_enabled`
   - `channel_telegram_enabled`

3. Manter `notification_preference` como compatibilidade legada, mas não usá-lo como fonte de verdade para `web_push`.

4. Atualizar `resolveChannelsForUser` para retornar:
   - `mobile_push` apenas com flag App ativa e device Expo ativo.
   - `web_push` apenas com flag Web ativa e device `provider = 'webpush'` ativo.
   - `telegram` apenas com flag Telegram ativa e vínculo Telegram ativo.

5. Organizar a experiência nativa em quatro níveis:
   - Perfil
   - Avisos
   - Preferências
   - Telegram

## Consequências

Positivas:
- O usuário ganha controle granular sem depender de enum legado.
- Web Push pode ser ativado/desativado sem interferir em App/Telegram.
- O app nativo deixa de ter entradas paralelas e passa a ter uma jornada única.
- Quiet hours e digest ficam consistentes entre web, app e dispatcher.

Custos:
- Requer migration em `docs/migrations`.
- Requer sync de schema/validação em web, mobile e server.
- `CON-017` passa a aceitar `web_push` como canal adicional.
- Settings web precisa chamar `webpushService.subscribe()` ao ativar Web (PWA).

## Critérios Para Aceite

- Wave N2 implementada sem regressão em App push e Telegram.
- `web_push` depende de flag explícita e subscription ativa.
- `silent` não envia canais externos, mas mantém Inbox/auditoria.
- `digest_morning` envia um resumo simples no `digest_time`.
- Fluxo nativo Perfil → Avisos → Preferências → Telegram validado em device.
