# ADR-087 — Alvo do upgrade de SDK: Expo 55

**Status:** proposed
**Data:** 2026-07-21
**Spec:** 055 (`plans/specs/055-expo-55-target-api-36/`) — local-only, não versionado
**Categoria:** mobile_and_platform

## Contexto

Notificação do Google Play Console (2026-07-21): o app precisa targetar **Android 16 / API 36**.
Target atual = **35** (default do Expo SDK 53, sem override em `expo-build-properties`).
**A partir de 2026-08-30 updates do app ficam bloqueados na loja** — o app publicado continua no ar,
mas nenhuma correção alcança a base.

Prazo duro + app de saúde em produção com base ativa.

## Opções consideradas

### (a) Override `targetSdkVersion: 36` no Expo 53
Manter o SDK 53 e forçar o target via `expo-build-properties`.
**Descartada.** Era o fallback caso o upgrade tivesse blocker nativo — a auditoria F0 provou que não
tem (`@bacons/apple-targets` v5.0.0, `peerDependencies: { expo: '>=52' }`, confirmado por
`npm view`). RN 0.79 não é testado contra API 36; e ficar no 53 só adia o problema, que reaparece
todo ano.

### (b) Expo SDK 54
Cumpre o requisito (SDK 54 targeta API 36; RN 0.81 / React 19.1; iOS mín. 15.1).
**Descartada.** Medido em `npm view expo dist-tags` (2026-07-21): `sdk-54 → 54.0.36`,
`sdk-55 → 55.0.28`, `sdk-56 → 56.0.16`, `latest → 57.0.7`. O SDK 54 é de ~set/2025 — **3 majors
atrás**. Subir para ele contradiz o próprio racional do upgrade ("não ficar atrás") e garante um
segundo épico de upgrade em pouco tempo.

> A auditoria automatizada do F0 (modelo barato) tratou o 54 como se fosse a versão atual. O gate
> Opus pegou. Ver §Lição.

### (c) Expo SDK 55 — **ESCOLHIDA**
RN 0.83 / React 19.2. Targeta API 36+. **iOS mínimo 15.1** (inalterado). **Xcode mínimo 26**.
Fica 1 major atrás do topo estável em vez de 3.

### (d) Expo SDK 56 ou 57 (topo)
Mataria a dívida por completo.
**Descartada por dois custos concretos, nenhum ligado ao requisito da loja:**
1. **iOS mínimo sobe para 16.4** — dropa iPhone 6s/7, iPad mini 4, iPad Air 2 e todo usuário em
   iOS 15 / 16.0–16.3. Isso é **decisão de produto** (perder usuários de um app de saúde), não de
   compliance. Não se toma dentro de um épico com prazo duro.
2. **Xcode mínimo 26.4** — a máquina de build está em **26.3**. Exigiria upgrade de ferramenta no
   caminho crítico do prazo.

## Decisão

**Expo SDK 55.** É o último degrau que satisfaz a exigência da Play Store **sem custo de produto
(iOS 15.1 mantido) nem custo de ferramenta (Xcode 26 ≤ 26.3 local)**.

**Destravador que torna o 55 barato:** o dosiq **já roda New Architecture**. O SDK 53 habilitou New
Arch por default em todos os projetos e o `app.config.js` não faz opt-out (nenhum `newArchEnabled`).
O maior breaking do 55 — remoção da Legacy Architecture — **custa zero** para nós.

**Execução:** dois degraus (53→54, depois 54→55), dois commits, **um PR**. Expo recomenda um SDK por
vez; dois commits dão bisect trivial, um PR evita pagar dois ciclos de review contra o prazo.

## Consequências

**Positivas**
- Requisito da loja satisfeito antes de 30/ago/2026; updates destravados.
- Dívida de SDK cai de 3 majors para 1.
- Nenhum usuário perde o app (iOS mín. inalterado).
- Breaking changes do 55 medidos e quase todos já neutros: New Arch ✅, plugin `expo-notifications` ✅,
  `expo-av` ✅, `app.config.js` ✅, `removeSubscription` ✅, metro private imports ✅.

**Negativas / dívida assumida**
- 🔴 **`expo-widgets` exige SDK 56.** O [[ADR-075]] escolheu o config plugin custom + Widget Extension
  Swift para a Live Activity "no Expo 53 atual", registrando "migração p/ expo-widgets = roadmap
  pós-upgrade 53→56". **Ir ao 55 NÃO destrava essa migração** — a Live Activity segue no plugin
  custom. Isso é dívida registrada, **não regressão**: nada que funcionava para de funcionar.
- `expo-file-system` foi reescrito (v18→v19+); `ExportSheet.tsx` usa a API legada e passa a importar
  de `expo-file-system/legacy` (shim). A migração para a API nova fica como dívida — o `/legacy`
  sai em SDK futuro.
- Um segundo épico de upgrade (55 → topo) continua no horizonte, agora acoplado à decisão de
  produto sobre iOS mínimo 16.4.

**Neutras**
- `eas update` passa a exigir `--environment` — sem efeito hoje (OTA não montado), mas **afeta a
  spec 051** (runbook OTA). Handoff previsto no F3.

## Lição (processo)

A auditoria de compat foi delegada a um modelo barato (Haiku) para economizar token — decisão certa
para levantar terreno. Mas ele **tratou o SDK 54 como se fosse o topo**, alucinou versões de pacotes
SDK-pinados (`expo-updates ~1.0.x` quando o real é `29.0.19`), não auditou `devDependencies`, e
**afirmou sem fonte** justamente a claim decisiva (`@bacons/apple-targets` compatível — que por sorte
era verdadeira).

Sem o gate, o épico teria entregue um upgrade nascido obsoleto.

**Regra adotada:** modelo barato levanta terreno, **nunca fecha decisão**. Toda claim decisiva passa
por verificação executável (`npm view`, changelog oficial) antes de virar premissa de plano.
