## Decisão

Auth logic (signIn, signUp, sendPasswordReset) permanece em `apps/mobile/src/platform/auth/authService.js`. Não será movida para `@dosiq/core` nesta sprint.

## Contexto

Durante o sprint de fluxos iniciais mobile, surgiu a questão de unificar auth entre web e mobile via `@dosiq/core`. Análise revelou:

- **Web** (`apps/web/src/shared/utils/supabase.js`): `signIn/signUp` são thin wrappers sem Zod, sem tradução PT-BR
- **Mobile** (`authService.js`): `signInWithEmail` tem Zod validation + error translation PT-BR + supabase client específico (`nativeSupabaseClient` com SecureStore)
- **@dosiq/core**: apenas schemas Zod (authSchema.js) — sem funções de auth

Consolidar exigiria:
1. Refatorar web para usar @dosiq/core (risco de regressão)
2. Adaptar supabase client para ser injetável (breaking change)
3. Testar ambos workspaces

## Consequências

- Mobile continua com authService.js bem testado (19 testes passando)
- Web mantém seu padrão atual (thin wrapper)
- Duplicação aceitável por agora — propósitos diferentes (web não tem Zod nem tradução)

## Revisão Futura

Reavaliar quando/se: (1) web também precisar de validação Zod no signup, (2) terceiro cliente (ex: CLI) precisar de auth, (3) @dosiq/core amadurecer para incluir lógica de negócio.
