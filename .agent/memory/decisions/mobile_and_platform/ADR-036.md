# [ADR-036] JS Stack for Legacy Android Compatibility

## Status
Accepted

## Context
Production crashes were reported on Android 7 (API 24) when navigating back from notification settings to the inbox. The crash was identified as a native `IndexOutOfBoundsException` in `react-native-screens` 4.11.1 (Expo SDK 53).

The root cause is a synchronization bug between the native `ScreenStack` and the underlying `ViewGroup` hierarchy when handling rapid view drawing on older Android versions.

## Decision
We will use `@react-navigation/stack` (JS-based) instead of `@react-navigation/native-stack` specifically for the Profile navigation flow and any other flow identified as unstable on legacy devices.

## Consequences
- **Stability**: Resolves the `IndexOutOfBoundsException` completely as it bypasses the buggy native stack rendering.
- **Performance**: Transitions are handled by the JS thread, which might result in slightly less fluid animations compared to native-stack on high-end devices, but provides a consistent and stable experience on legacy hardware.
- **Dependencies**: Adds `@react-navigation/stack` and `react-native-gesture-handler` to the mobile project.

## Update (2026-05-25 — Fase 4 S4.2)
O navigator **raiz** (`Navigation.jsx`) era o último outlier em native-stack e
crashava na API 24 (`CalledFromWrongThreadException` / `IndexOutOfBoundsException`)
ao desmontar a árvore no `SIGNED_OUT` (logout). Migrado para
`createStackNavigator` (JS), alinhando com RootTabs/ProfileStack. Logout
confirmado funcional no Android 7. A decisão agora cobre **toda** a árvore de
navegação, não só o fluxo de Perfil.
