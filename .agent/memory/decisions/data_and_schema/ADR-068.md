# ADR-068 — `injection_container` por LOTE (reverte a premissa medicine-level da B2)

**Status:** accepted
**Data:** 2026-06-13
**Contexto:** 012 Fase B4 / FR-030 (smoke PO 2026-06-12)
**Relaciona:** ADR-067, FR-019/FR-020 (B2, medicine-level — corrigidos aqui)

## Contexto

A B2 cravou `injection_container` em `medicines` (valor único, capturado na 1ª compra —
[`packages/core/src/schemas/medicineSchema.js:202`](../../../../packages/core/src/schemas/medicineSchema.js#L202)).
**Errado:** a apresentação é atributo do **lote comprado**, igual ao volume. O paciente pode comprar
canetas pré-preenchidas e depois migrar para refis (mais econômico) no mesmo tratamento — dois lotes
do mesmo medicamento com containers diferentes. Medicine-level força um valor único e o rendimento
(FR-020 "≈3 canetas") fica errado quando o lote ativo é refil.

## Decisão

**`injection_container` passa a viver no LOTE** (`stock`/`purchases`), não no medicamento:

- Migração move/copia os valores existentes de `medicines.injection_container` para os lotes
  correspondentes e **DROPA `medicines.injection_container`** (decisão PO 2026-06-13 — fonte única =
  lote; sem coluna duplicada de "default"). Sem prefill automático na 1ª compra.
- Rendimento (FR-020) calculado **por lote**: "≈3 canetas" no lote A + "≈2 refis" no lote B.
- Form de compra (web + mobile) exibe o campo de container em **TODA** compra — remover o gate
  `!isEdit` / `!medicine?.injection_container` que omitia as compras subsequentes.
- Grants + RLS dos lotes já existem (tabela `stock`/`purchases`); coluna nova segue o template
  CLAUDE.md se necessário.

**Rejeitado:** manter `medicines.injection_container` como "default opcional/sugestão" — duplicaria a
fonte de verdade e exigiria sync medicine↔lote (drift garantido). Fonte única no lote é mais simples
e correta.

## Consequências

- (+) Rendimento e rótulo corretos quando o tratamento mistura caneta + refil.
- (+) Fonte única (lote) — sem sync nem drift medicine↔lote.
- (+) Alinha container com volume (ambos atributos do lote comprado).
- (−) Migração com **mutação de schema em prod** (move valores + DROP COLUMN) — autorização PO
  explícita; read-path completo (R-267): todo select/form/detalhe que lia
  `medicines.injection_container` migra para o lote.
- (−) Sem prefill na 1ª compra (aceito): o paciente informa o container a cada compra; campo curto,
  baixo atrito.
- Coordenação: schemas Zod (`medicineSchema` perde o campo; schema de stock/purchase ganha),
  formatters de rendimento e badges (ADR-067) leem o container do lote.
