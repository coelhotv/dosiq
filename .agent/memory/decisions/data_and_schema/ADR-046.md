# ADR-046 — Padronização `"unidade(s)"` no `formatDoseUnit` (sem mapping por `dosage_unit`)

**Status**: accepted (2026-05-17)
**Contexto**: Fase 2 — formatter de dose por tomada (`dosage_per_intake`) no detalhe do tratamento.

## Decisão

`formatDoseUnit(qty)` SEMPRE retorna `"<qty> unidade(s)"` independente do `medicine.dosage_unit`. A apresentação por unidade farmacêutica (`50mg`, `2ml`, `100UI`) fica visível separadamente no `DosagePill` do hero card.

```js
// packages/core/src/utils/doseUnit.js
export function pluralizeDoseUnit(qty) {
  return Number(qty) === 1 ? 'unidade' : 'unidades'
}

export function formatDoseUnit(qty) {
  const display = String(qty).replace('.', ',')
  return `${display} ${pluralizeDoseUnit(qty)}`
}
```

## Opções consideradas

**Opção A (descartada)**: mapping por dosage_unit
- `mg` → `comprimido(s)`
- `ml` → `ml`
- `gotas` → `gota(s)`
- `UI` → `UI`

Bug detectado em smoke: Apidra (2ml por ampola) com `dosage_per_intake=1` renderizava `"1 ml"` no card de dose — semanticamente ERRADO. O paciente toma 1 unidade DE 2ml, não 1 ml.

**Opção B (aceita)**: sempre "unidade(s)"
- Sem ambiguidade semântica
- DosagePill do hero (`2ml`) já dá o contexto de quanto cada unidade contém
- Helper genérico, sem if/else por `dosage_unit`

## Consequências

- **Positivas**: zero bug semântico; helper trivial; cobertura test simples; web pode adotar mesmo helper no G3.
- **Negativas**: termo "unidade" é mais abstrato que "comprimido" pra alguns user types (pacientes idosos podem preferir contagem em forma farmacêutica). Reavaliar se PO sinalizar pushback de usabilidade.

## Quando NÃO seguir

- Telas de adherence/relatórios podem precisar verbo específico (`"tomou 2 comprimidos hoje"`) — usar helper distinto que combina `qty + medicine.type + dosage_unit` ad-hoc na tela. NÃO modificar o `formatDoseUnit` canônico.
