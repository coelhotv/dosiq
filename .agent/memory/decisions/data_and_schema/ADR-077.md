# ADR-077 — Audit trail de dose crítica: tabela append-only + emits fail-open + beacon offline + pg_cron prune

- **Status:** proposed
- **Date:** 2026-07-02
- **Spec:** 042 (critical-audit-trail) · relacionado: CON-026, CON-029/030, AP-257
- **Tags:** data, schema, mobile, server, observability, lgpd

## Contexto

Debug de dose crítica é cego pós-fato: superfícies (alarme/nag/LA) e máquina de estados deixam só o
estado final (`dose_instances.status`), nunca a trajetória. Incidente 2026-07-02: ~1h de arqueologia
(`adb dumpsys` + SQL) pra descobrir alarme suprimido por `importance=NONE` — fato que só o device via.
Relato remoto de usuário ("não tocou ontem") = indebugável. Cliente do wedge = dev/PO (debug);
log visível a paciente/cuidador = épico 009 futuro (tabela reutilizável, UX fora).

## Decisão

1. **Tabela única append-only** `dose_critical_events` (user_id, dose_instance_id, event, platform,
   actor, detail jsonb, created_at). CHECK no enum (11 eventos) + Zod sincronizado (R-270).
2. **Acesso:** RLS `user_id = auth.uid()` (SELECT + INSERT WITH CHECK); `authenticated` SEM
   UPDATE/DELETE (imutável pelo cliente); prune só `service_role`/cron. Server emit (service_role)
   deriva `user_id` da própria `dose_instance` (nunca de input — IDOR órfão).
3. **Emit helper único no core** (`createCriticalAuditService`) consumido por web/mobile/server;
   TODO emit é fail-open (falha de log nunca quebra alarme/registro/push).
4. **Transporte:** eventos com round-trip existente = emit inline (~1 linha no site). Únicos eventos
   sem round-trip garantido (`alarm_fired`/`suppressed`/`nag_fired`) = **beacon device**: fila
   AsyncStorage (cap 200, overflow FIFO + marker) + flush no foreground. iOS não roda JS no disparo
   (AP-257) → outcome derivado retroativamente no foreground (`captured_at_foreground: true`).
5. **`detail` minimizado (LGPD):** só IDs + estado + snapshots não-PII (permission, status APNs).
   NUNCA rótulo de medicamento (join on-demand) nem token/segredo.
6. **Retention:** prune 90 dias via **pg_cron** (job na migração; cron por ÚLTIMO — falha do cron não
   derruba a tabela). Zero função serverless nova (R-090 intacto).

## Alternativas rejeitadas

- Log em analyticsService/localStorage: morre no device, não serve relato remoto.
- Endpoint serverless de ingestão: fura budget R-090 sem ganho (supabase-js + RLS basta).
- Gravar label do medicamento no detail: duplica PII, stale após edição, pior p/ 009/LGPD.
- Dedupe estrita de eventos: custo alto; duplicata em trail de debug é tolerável (risco aceito).

## Consequências

- +1 tabela, +1 extensão (pg_cron), +1 contrato (CON-031). Duplicatas possíveis (aceito).
- Cliente pode forjar o próprio evento — trail NÃO é forense; 009 revisita se expor ao paciente.
- Reversível (two-way door): `cron.unschedule` + `DROP TABLE`; emits são best-effort removíveis.
