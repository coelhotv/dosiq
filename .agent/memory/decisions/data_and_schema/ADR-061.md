# ADR-061 — Tolerância não-diária derivada do período da frequência (sem cap de 2h)

**Status:** accepted
**Date:** 2026-06-04
**Tags:** dose_instances, tolerance, adherence, glp1, diabetes, generator
**Spec:** 012-diabetes-t2-support (Fase B)
**Relaciona:** ADR-050 (FP-2), R-248 (adesão lê tolerance_minutes), MASTER_PLAN §6

## Context

GLP-1 é semanal com **janela de perdão clínica ~72h**. O gerador atual
(`computeTolerances`, `doseInstanceGenerator.js:76-94`) retorna **120 min FIXO** para qualquer
frequência não-diária (`!isDaily → MAX_TOLERANCE_MINUTES`), insuficiente p/ semanal. Diário multi-dose
usa `min(floor(gap/2), 120)`. Remover o cap **globalmente** afrouxaria o caso 1×/dia (público atual)
de 2h→12h, inflando adesão histórica.

## Decision

1. **Só frequências não-diárias** (`semanal`, `dias_alternados`) passam a derivar a tolerância do
   **período entre ocorrências**: `floor(período/2)` **sem `MAX_TOLERANCE`**
   (semanal=10080min → 5040; alternados=2880min → 1440).
2. **Diário inalterado:** mantém `min(floor(gap_intra-dia/2), 120)` — preserva a semântica de adesão
   do público atual 1×/dia.
3. `computeTolerances` ganha consciência de `frequency` (hoje só recebe `sortedMinutes` + `isDaily`) —
   passar a frequência ao gerador.
4. Leitura permanece por instância (`dose_instances.tolerance_minutes`, R-248/FP-2) — nada de
   hardcode 120 em runtime.

## Consequences
- **+** GLP-1 ganha a janela de perdão semanal sem afrouxar o caso comum.
- **+** Coerente com a regra clínica metade-do-intervalo (MASTER_PLAN §6), agora sem o teto p/ não-diário.
- **−** Sweep `pending→missed` (R-246/AP-190) precisa respeitar a tolerância larga — testar.
- Sem migração de dados: tolerância é computada na geração; instâncias futuras pegam o novo valor.

## Alternatives
- Remover cap global (rejeitado: infla adesão do público 1×/dia).
- Coluna de tolerância manual por protocolo (rejeitado: fricção; derivável da frequência).
