# ADR-059 — Validade biológica (TTL) via `stock.opened_at` + `medicines.shelf_life_days`

**Status:** accepted
**Date:** 2026-06-04
**Tags:** schema, stock, medicines, diabetes, ttl, insulin
**Spec:** 012-diabetes-t2-support (Fase A)
**Relaciona:** ADR-018 (status de estoque 4-tiers por dias-de-suprimento), ADR-058

## Context

Insulina (e biológicos) vence **28–30 dias após aberto**, mesmo com volume restante — a proteína
perde eficácia. O status de estoque atual (ADR-018) mede só **dias-de-suprimento por volume**; não
captura expiração por tempo-de-uso. `expiration_date` (validade da caixa, data fixa) é conceito
**distinto** — não reaproveitar.

## Decision

1. **`medicines.shelf_life_days`** (INTEGER, nullable) — TTL pós-abertura; propriedade do **produto**
   (insulina ≈ 30). NULL = eixo de validade biológica inativo.
2. **`stock.opened_at`** (TIMESTAMPTZ, nullable) — abertura do **lote**. **Inferido na 1ª tomada**
   que debita o lote (`opened_at IS NULL` → `now()`); não há cenário de "abrir sem usar". Best-effort
   (R-245) no caminho de consumo.
3. **Alerta = computado**, não armazenado: `opened_at + shelf_life_days*interval ≤ now`. Helper puro
   no core. **Eixo paralelo** ao status 4-tiers de volume (ADR-018) — coexiste, não substitui. Render
   dedicado (relógio vs gota).
4. **Sem tabela nova:** TTL é propriedade 1:1 do lote → coluna em `stock`; tabela própria = join inútil.

## Consequences
- **+** Diferenciador real (apps comuns não avisam por tempo-de-uso).
- **+** Dois eixos de fim-de-estoque (volume × validade) cobrem insulina corretamente.
- **−** `opened_at` depende de o consumo passar pelo caminho instrumentado (web/mobile/bot) — testar cross-superfície.
- Migração: colunas nullable, nascem inativas; nenhum lote vira "aberto" retroativo.

## Alternatives
- Tabela `stock_openings` dedicada (rejeitado: 1:1 com `stock`).
- Reusar `expiration_date` (rejeitado: conceito distinto — caixa vs abertura).
- `opened_at` por ação manual "abrir caneta" (rejeitado: fricção; ninguém abre sem usar).
