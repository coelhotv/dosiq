# ADR-053 — Multi-timezone: escopo, default e abrangência do seletor

## Contexto

O dosiq nasceu BR-only. O seletor de fuso ([`userSettingsSchema.js`](../../../packages/core/src/schemas/userSettingsSchema.js))
restringe via `timezone: z.enum(TIMEZONES_BR).default('America/Sao_Paulo')` — 17 zonas
IANA brasileiras. Pós-lançamento iOS, brasileiros morando fora (casos diretos:
Londres e Nova York) demonstraram interesse em testar.

### Estado real hoje (auditado em 2026-05-30)
- **DB/schema:** enum trava em BR. `Europe/London`/`America/New_York` → `safeParse`
  rejeita no save (R-082). Expat **não persiste** o fuso real.
- **UI:** `useSettingsState` semeia de `Intl…resolvedOptions().timeZone` (browser),
  mas o dropdown só lista `TIMEZONE_OPTIONS` (BR) → valor não casa → cai no default;
  save rejeitado pela enum.
- **Display:** widgets hardcodam `timeZone: 'America/Sao_Paulo'`
  (`LastDosesWidget`, `DoseListItem`, `LogEntry`) — ignoram o tz salvo. G1 (≈250
  callers) só fecha na **Fase 4**.
- **Efeito p/ expat:** tz preso em SP; geração de `dose_instances` e fronteira de
  "hoje" computadas em SP → lembrete "08:00" dispara 08:00 SP (= 11–12h Londres /
  06–07h NY). Instantes são `timestamptz` absolutos → histórico não corrompe, só desloca.

## Decisão

1. **Multi-timezone global é escopo da Fase 4** (onde G1 fecha). Nada de tz novo
   durante a F3 — a F4 deve nascer **tz-agnóstica de verdade** (default → tz do
   usuário em geração + leitura + fronteira-de-dia + display), não SP-default.

2. **Caminho B — enum curado** (após a F4 injetar tz): estender `TIMEZONE_OPTIONS`
   com um punhado de destinos expat reais (ex.: `Europe/London`, `America/New_York`,
   `America/Lisbon`, `America/Los_Angeles`) além das 17 BR. DST é resolvido
   automaticamente pelo **nome IANA** via `Intl` — não depende de offset.

3. **Caminho C (IANA completo, ~340 zonas + picker com busca) fica gated** atrás de
   "base expat > base nacional" — gate que na prática não deve disparar. YAGNI.

4. **Armazenar SEMPRE IANA, nunca offset.** Offset ≠ identidade por causa de DST
   (Londres/BST, NY/EDT-EST têm horário de verão; BR não tem desde 2019). Agrupar/
   colapsar por GMT quebra na virada do DST. As cidades BR de mesmo offset seguem
   distintas de propósito (clareza + divergência futura de política).

## Consequências

- **F3 não toca tz** — risco zero de regressão de fuso nesta fase.
- A F4 ganha um item explícito: trocar `tz = 'America/Sao_Paulo'` default → tz do
  usuário nos pontos de geração/leitura/display, e **só então** aplicar o Caminho B
  (enum curado). Adicionar Londres ao enum **antes** da F4 não muda o lembrete
  (display ainda hardcoda SP).
- Cap de risco: enquanto B não entra, expat usa app com lembrete em SP (documentado,
  não-bloqueante).

## Alternativas descartadas

- **A — BR-only permanente:** mata o caso de uso dos próprios testers voluntários.
- **C — IANA completo agora:** UI de picker maior + perde ordenação BR-first; sem
  retorno enquanto a base for majoritariamente nacional.

Ver [[R-248]] (leitura de adesão por instância usa tz só na fronteira de dia) e
CON-022 (`getUserTime` tz-aware). Amarrado na spec da Fase 4
(`plans/dose_instances_refactor/EXEC_SPECS_PHASE_4.md`).
