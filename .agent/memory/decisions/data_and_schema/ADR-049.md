# ADR-049 — Core tz-aware + `user_settings.timezone`

## Status
**ACCEPTED** (2026-05-27 — aprovado pelo operador; libera S1.3)

## Contexto

`packages/core/src/utils/dateUtils.js` hardcoda `America/Sao_Paulo` em `getSaoPauloTime` (`dateUtils.js:199-218`) e `getStartOfDayISO` (`dateUtils.js:158-171`). Todas as primitivas temporais derivam daí: `getNow`, `getTodayLocal`, `getYesterdayLocal`, `getEndOfDayISO`. Adesão (CON-018), logs, dashboards e o futuro motor de `dose_instances` (ADR-048) computam instantes nesse fuso fixo.

App na App Store + Brasil multi-fuso (America/Sao_Paulo, America/Manaus, America/Belem, etc.) → usuário fora de Brasília tem doses computadas no fuso errado. Pré-requisito de ADR-048: `scheduled_for` é instante absoluto e depende do fuso correto no momento da geração.

Cluster de APs confirma a fragilidade do domínio temporal: AP-005, AP-W14, AP-T10, AP-W16, AP-H14, AP-113, AP-071.

## Decisão

1. **Parametrizar por tz, default retrocompatível.** `getUserTime(date, tz)` é a primitiva nova; `getSaoPauloTime(date)` vira wrapper que chama `getUserTime(date, 'America/Sao_Paulo')`. `getNow(tz)`, `getTodayLocal(tz)`, `getYesterdayLocal(tz)`, `getStartOfDayISO(dateStr, tz)`, `getEndOfDayISO(dateStr, tz)` recebem `tz` opcional com default `'America/Sao_Paulo'`.
2. **Fonte de verdade = `user_settings.timezone`** (schema `public`, ratifica ADR-031). Core **não** lê DB — o caller injeta o tz.
3. **Não-breaking.** Adição de param opcional + wrappers preservam todo caller atual. CON-018 (`calculateAdherenceStats`) mantém assinatura; tz entra como param opcional ao fim, sem quebrar consumidores.
4. **Sem colisão de barrel** (AP-164): `@dosiq/core/index.js` exporta nomes distintos; nunca dois símbolos homônimos via `export *`.

## Consequências

- **Positivas:** fundação correta pra ADR-048; corrige fuso doméstico; refactor incremental sem big-bang.
- **Custos/risco:** double-shift em CI/UTC (AP-W14/AP-W16) — testes multi-fuso obrigatórios (S1.6). `Intl.DateTimeFormat` em escopo de módulo no mobile é unsafe em Hermes Android≤7 (AP-155/R-199) — atenção no S1.4/S1.5.
- **Migração de callers:** gradual; wrapper permite migrar caller a caller sem PR único gigante.

## Alternativas descartadas

- **Big-bang (trocar assinatura sem wrapper):** breaking em CON-018 e dezenas de callsites → ADR de breaking change + atualização simultânea. Rejeitado por risco.
- **tz só no client (sem persistir):** quebra serverless/bot que geram instâncias (ADR-048). Precisa de fonte persistida → `user_settings`.

## Verificação (DoD da Fase 1)
- Suite `dateUtils` existente passa sem mudança de comportamento (default SP).
- Testes novos cobrem ≥2 fusos (SP vs Manaus) + cruzamento de meia-noite.
- `rtk npm run test:critical` verde.
