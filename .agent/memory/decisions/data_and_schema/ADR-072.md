# ADR-072 — Sítio de injeção como coluna em `medicine_logs` + rotação global por query

**Status**: accepted (031 Planning, 2026-06-21).
**Tags**: data_and_schema, medicine_logs, injection, dose-logging

## Contexto

Spec 031 adiciona o local corporal de aplicação como metadado da tomada de injetáveis, com
auxílio de rotação (último local, alerta de repetição) e exibição no histórico. Três decisões de
modelagem com impacto arquitetural.

## Decisão

1. **Persistência**: coluna `medicine_logs.injection_site` (TEXT nullable + CHECK 8 valores),
   NÃO tabela dedicada nem `biomarkers_log`.
   - vs. tabela dedicada: FK polimórfica (`dose_instances`/`medicine_logs`) = ambiguidade + JOINs
     sem ganho funcional sobre coluna; só se pagaria com body-map rico (coordenadas/foto).
   - vs. `biomarkers_log`: sítio é categórico (sem `value/unit`) → type mismatch com ADR-060.
2. **Rotação GLOBAL no corpo** (cross-medicamento), implementada como **semântica de query** (SELECT
   sem filtro `medicine_id`/`protocol_id`, `ORDER BY taken_at DESC`), não como shape de storage.
   Diabéticos usam múltiplos injetáveis; "último por-med" colidiria no mesmo ponto físico.
3. **CHECK constraint** (não Zod-only) — domínio finito e estável (8 sítios anatômicos), único
   writer é RPC sob RLS → defense-in-depth barato (alinha R-271). **Contrasta ADR-070**, que removeu
   o CHECK de `biomarkers_log.context` por ser domínio EXTENSÍVEL. Sítio NÃO é extensível na v1;
   granularidade futura (sub-quadrante) custará 1 migração — aceitável.

## Consequências

- Write-path passa pela RPC `register_dose_atomic` (CON-026/ADR-071) → param aditivo
  `p_injection_site` (não-breaking, DEFAULT NULL). Idem `update_dose_log_atomic` (FR-011).
- Migração aditiva reversível (`DROP COLUMN`), sem efeito em FIFO nem adesão (`dose_instances`).
- Rotação correta com logs retroativos: ordena por `taken_at` (não `created_at`).

## Alternativas rejeitadas
- Tabela `injection_sites` dedicada — overhead sem ganho (ver acima).
- Rotação por-medicamento — colisão física entre injetáveis (lipo-hipertrofia).
- Zod-only sem CHECK — perde defense-in-depth num domínio finito (ADR-070 não se aplica).
