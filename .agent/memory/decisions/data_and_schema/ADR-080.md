# ADR-080 — Titulação N2: orquestrador `titrations` sobre executores `protocols`

**Status:** accepted (planning 029, 2026-07-12 — aceitar antes do slice F1)
**Contexto:** spec 029 (Clarifications 2026-07-07 + design 2026-07-12 + eng-review + RC-SEC).

## Decisão

1. **Entidade nova de primeira classe:** `titrations` (escada) + `titration_steps` (etapas
   `{medicine_id, dose, intake_unit, duration_days|NULL=contínua, position, status}`), user-owned
   (RLS `auth.uid()`, FK `auth.users` CASCADE R-287). `treatment_plan_id` opcional; TP intocado.
   Camadas: titration = orquestrador; protocols = executores (fonte de dose_instances/adesão/
   estoque). Step referencia o `protocol_id` que ativou (auditável).
2. **Dois tipos de transição, DERIVADOS** (`medicine_id` step N vs N-1 — sem coluna/enum):
   `dose_change` automática na data (preserva N1); `medicine_switch` pendente até confirmação
   (step `pending_confirmation` + push time-sensitive; RPC `confirm_titration_switch` SECURITY
   DEFINER template com claim atômico `WHERE status='pending_confirmation'` — R-288/AP-221/AP-276).
3. **Cutover strangler-fig:** `resolveTitrationStageAt`/`calculateTitrationData` mantêm
   ASSINATURA; implementação lê a entidade nova (dual-read por flag `TITRATION_SOURCE` até
   validação). Consumers (doseInstanceGenerator, cron, consulta/PDF, leitura web) migram num
   swap testável por paridade — zero reescrita de call-site.
4. **Migração N1→N2 silenciosa** e comportamento-preserving: jsonb → titrations/steps
   (normaliza `days`→`duration_days`; `titulando`→current, `alvo_atingido`→contínua current,
   `pausado` acompanha protocol; `migrated_from_protocol_id` p/ auditoria). jsonb intacto
   (read-only) até validação prod; drop em slice final (F6).
5. **Web:** write-freeze do wizard N1 (leitura preservada via adapter). Mobile = UI nova.

## Rejeitadas

- Flag/modo no `treatment_plan` (muda semântica do container, espalha condicionais — NC-1).
- jsonb estendido no protocol (não salta medicamentos; perpetua o motor N1).
- Reescrever call-sites um a um (14+ arquivos web; risco de drift vs swap único por paridade).
- Coluna `transition_type` persistida (derivável; enum a manter em 2 lugares).

## Consequências

+ Caso GLP-1 cross-medicamento suportado; N1 absorvido sem UX nova p/ caso simples (paridade 8 passos).
+ Blast radius controlado por adapter + dual-read + POs de paridade (PO-3/PO-5).
− 6 PRs; motor de confirmação exige trace de interleaving e testes de concorrência reais.
