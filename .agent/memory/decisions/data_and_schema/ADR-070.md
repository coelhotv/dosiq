# ADR-070 — `context` de `biomarkers_log` é domínio extensível (sem CHECK)

## Contexto

`biomarkers_log` nasceu **genérico-first** (ADR-060): `type` e `source` são **livres no DB**
(sem CHECK), guardados só por Zod, p/ crescer sem migração (glicemia → peso → PA → batimentos →
HealthSync futuro). Mas a Fase C (FR-012) travou `context` com CHECK SQL fechado:

```sql
context text CHECK (context IS NULL OR context IN ('jejum','pre_refeicao','pos_refeicao','ao_deitar','outro'))
```

Ao adicionar UI de PA (spec 032), descobriu-se que PA tem contextos próprios
(`ao_acordar`, `em_repouso`, `apos_exercicio`, `ao_dormir`, `pos_medicacao`) — nenhum no CHECK.
Gravar PA com contexto → CHECK rejeita o INSERT + `z.enum` rejeita na validação.

`context` é, por natureza, **extensível por família de biomarcador** (cada família tem seus
contextos; peso não tem nenhum). Era o **único campo extensível travado** — inconsistente com
`type`/`source`. Travar = cada nova família = nova migração (a fricção que ADR-060 quis matar).

## Decisão

**Remover o CHECK de `context`.** Alinhar com `type`/`source`: DB livre, **Zod é a autoridade
única** sobre o domínio (enums no core: `BIOMARKER_CONTEXTS` glicemia + `BIOMARKER_PA_CONTEXTS` PA
+ futuros). A UI filtra qual conjunto de chips mostrar por tipo; o `superRefine` cruza
`type ↔ família de contexto`. O DB não opina sobre o conteúdo de `context`.

Emenda a aplicação de **R-082/R-271** (Zod↔SQL sync) a esta coluna: sem CHECK, não há o que
sincronizar — Zod vira autoridade (padrão já vigente p/ `type`/`source`).

## Justificativa

- **CHECK só agrega quando há writer fora do Zod.** Único writer de `context` é o app, via core
  enum, sob RLS (`auth.uid() = user_id`). Nenhum service/RPC escreve `context`. O CHECK protege
  um vetor inexistente e cobra uma migração por família p/ sempre.
- **Blast radius de valor ruim = baixo.** `context` é label descritivo — não FK, não fronteira de
  segurança, não entra em matemática de dose/estoque. Valor estranho = label esquisito na UI, não
  corrupção.
- **Consistência ADR-060 restaurada** (`type`/`source`/`context` os três livres).

## Consequências

- **1 migração agora** (`DROP CONSTRAINT`) — porém a **última** sobre `context`.
- **Zod guard único**: helper de label/formatação DEVE degradar com elegância em valor desconhecido
  (fallback p/ raw string ou ocultar) — defensivo barato.
- **Risco mitigado**: fragmentação por typo em analytics futura — o app só emite valores do enum
  core (fonte de verdade); DB livre não significa entrada arbitrária pelo fluxo real.

## Alternativa rejeitada

**Estender o CHECK p/ incluir contextos PA** — mantém a esteira de migrações por família; perpetua
a inconsistência com `type`/`source`; mesmo custo de migração agora, sem encerrar o problema.
