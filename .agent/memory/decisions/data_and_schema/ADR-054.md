# ADR-054 — Adesão/streak: fonte única + contrato semântico único, dupla superfície espelhada

**Status:** accepted · **Data:** 2026-05-30 · **Domain:** data_and_schema
**Estende:** ADR-048 (dose_instances) · ADR-050 (FP-1/FP-3) · alinhado a R-248, R-249
**Origem:** reflexão durante F3.2b — usuário questionou fragmentação de cálculo de adesão.

## Contexto

Crescimento orgânico + redesign deixaram **4 superfícies de cálculo de adesão/streak
que não se falam**, com risco real de números divergentes na mesma sessão:

| Superfície | Onde | Estado |
|---|---|---|
| `compute*FromInstances` (canônico) | `packages/core/src/utils/adherenceLogic.js` | ✅ novo (F3) |
| `calculateAdherenceStats` (legado, logs ±2h) | core; usado por `consultationDataService` (PDF 30/90d) | ⚠️ a aposentar |
| Views SQL `v_daily_adherence` / `v_adherence_heatmap` | Supabase; Reports/HealthHistory/Consultation/heatmap | ⚠️ math própria, bug >100% (AP-191) |
| Inferência mobile/bot | `apps/mobile/.../_useTodayDerived.js`, `server/bot/_adherenceHelpers.js` | ⚠️ ±2h |

Consulta (`Consultation.jsx` + `consultationDataService`) chega a **misturar 3 fontes**
numa tela (legado + view + instances) → PDF pode mostrar adesão ≠ do anel.
Cartão de emergência: **sem adesão** (só lista regime) — fora de escopo.

## Decisão

**Não é "1 função"** — `R-249` (OOM device low-mid) proíbe cálculo long-range/heatmap
no client. O alvo é:

```
1 FONTE DE VERDADE   → dose_instances (ocorrências materializadas por status)
1 CONTRATO SEMÂNTICO → adesão = taken/(taken+missed); skipped_* neutro; denom vazio→null;
                       streak: dia conta se taken/(taken+missed) >= 0.8; hoje incompleto não quebra
2 SUPERFÍCIES ESPELHADAS (devem produzir o MESMO número):
   • JS core  (compute*FromInstances)  → janelas curtas/bounded (hoje, 7-90d)  [client]
   • SQL view/RPC (mesma fórmula)      → long-range/heatmap/relatório          [server, R-249]
N CONSUMIDORES finos → ring, sparkline, dica, smartAlerts, relatório 23h, heatmap,
                       consulta/PDF, mobile, bot — só APRESENTAM, nunca calculam
TESTE DE PARIDADE    → mesmo input → JS core == SQL view (trava schema drift, lição Sprint 7)
```

## Consequências

- **Convergência:** F3.2a (service ✅) · F3.2b (anel/hoje/streak/insight ✅) · **F3.3** (mobile+bot → core) · **F4/G6** (views ← dose_instances; migrar `consultationDataService`; teste de paridade JS↔SQL).
- Qualquer feature nova de adesão **deve** consumir uma das 2 superfícies — proibido novo cálculo ad-hoc (vira AP se aparecer).
- Risco residual até F4: Consulta/Reports ainda divergem (legado+view). Documentado.
