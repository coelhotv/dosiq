# ADR-058 — Colunas genéricas `medicines.units_per_ml` + `medicines.presentation` (coordenação 022↔012)

**Status:** accepted
**Date:** 2026-06-04 (accepted 2026-06-04)
**Tags:** schema, medicines, liquid-meds, diabetes, coordination, migration
**Specs:** 022-liquid-medications (origem), 012-diabetes-t2-support (consumidora)
**Relaciona:** ADR-050 (FP-1..FP-4), ADR-052 (roadmap diabetes), ADR-018 (status estoque), ADR-046 (formatDoseUnit)

## Context

A spec 022 (medicamentos líquidos) ia introduzir `medicines.drops_per_ml` (INTEGER, específico de
gotas) para a conversão gotas→ml no decremento por FIFO. A spec 012 (Diabetes T2) precisa da mesma
mecânica de conversão para insulina (UI→ml, U-100 = 100 UI/ml) e de um eixo de **forma farmacêutica** para distinguir injetável/pomada/líquido (`medicines.type` hoje é só categoria
`medicamento`/`suplemento`, não forma).

Como a 022 **ainda não foi mergeada** (Dev Ready), há janela para nascer já generalizada e evitar
um "refactor do refactor" (rename de coluna + migração dupla) quando a 012 chegar.

## Decision

1. **`medicines.units_per_ml`** (NUMERIC, default 20, nullable) — coluna **genérica de razão→ml**
   cujo significado se adapta à `dosage_unit`: `gotas`→20 (gotas/ml), `ui/ml`→100 (UI/ml), `ml`→1.
   Conversão uniforme no decremento: `ml = p_quantity / units_per_ml`. **Substitui** o
   `drops_per_ml` específico de gotas que a 022 previa (mesma semântica para gotas). A 012 reusa o
   mesmo campo para insulina **sem nova coluna**.

2. **`medicines.presentation`** (TEXT, default `'comprimido'`, CHECK) — forma farmacêutica
   explícita, **additiva**. Nome de coluna em **inglês** (convenção DB snake_case do dosiq); valores 
   do enum em **português** (R-021, igual `frequency`/`type`): `comprimido`/`capsula`/`liquido`/
   `injetavel`/`pomada`/`spray`/`outro` (alinha `MEDICINE_TYPES` Zod). Zod: `PRESENTATIONS`.
   **NÃO reverte a decisão-mãe da 022:** `is_liquid` continua **derivado** de
   `dosage_unit LIKE '%/ml'` no caminho de decremento. `presentation` é eixo **complementar** (forma
   explícita p/ UI + casos injetavel/pomada que a unidade não distingue); para líquidos deve ficar
   consistente com o flag derivado.

3. **Sequenciamento duro:** 022 mergeada **antes** do C-coding da 012. A 012 apenas **consome**
   ambas as colunas (`presentation='injetavel'`; `units_per_ml=100`) e estende o branch UI da
   `consume_stock_fifo` (fora do escopo da 022).

## Consequences

- **+** Sem rename/migração dupla; a 012 herda a fundação pronta.
- **+** `presentation` abre o eixo de forma para futuras apresentações (spray/pomada) sem nova migração.
- **−** A 022 carrega 2 colunas que ela mesma só usa parcialmente (`presentation` só seta `liquido`;
  branch UI de `units_per_ml` fica latente até a 012). Aceito — custo baixo, evita retrabalho.
- Migração de dados (022): líquidos migrados recebem `presentation='liquido'` + `units_per_ml=20`;
  remanescentes default `comprimido`. Idempotente.
- Re-sync feito nos artefatos da 022 (spec/plan/tasks/analysis/contracts) neste Planning (2026-06-04).

## Alternatives considered

- **Booleano `is_injectable`** (rejeitado): não cobre pomada/spray; menos extensível que enum de forma.
- **`units_per_ml` dedicada só p/ UI na 012** (rejeitado): duplicaria `drops_per_ml`; mesma
  aritmética razão→ml — um campo serve ambos.
- **Manter `drops_per_ml` na 022 e generalizar na 012** (rejeitado): rename de coluna viva +
  migração dupla; pior que alinhar na origem com a 022 ainda não mergeada.
