# ADR-073 — Núcleo on-demand ANVISA em @dosiq/core com storage adapter

**Status:** accepted (2026-06-23, Slice 1 — core+web verdes; mobile no Slice 2) · **Spec:** 037 · **Tier:** 2

## Contexto
A lógica on-demand da base ANVISA (manifest version + TTL 7d + fetch com timeout + normalize/search) existia só no mobile (`useMedicineDatabase.js`). A web embutia os JSONs no build PWA (~1.36 MB). Spec 037 (RC3) detectou triplicação: trazer a web pro padrão on-demand reimplementaria o que o mobile já tem; `normalizeText` já triplicado.

## Decisão
Centralizar o núcleo platform-agnostic em `@dosiq/core` (`createAnvisaDatabase`), parametrizado por um **storage adapter injetável** (`{read,write}`). Web injeta adapter Cache Storage API; mobile injeta adapter AsyncStorage. Plataformas consomem a mesma lógica de manifest/TTL/versão/fetch/normalize/search.

## Alternativas
- **(B) web reimplementa local:** menor escopo, mas perpetua duplicação web↔mobile. Rejeitado (RC3 + operador).
- **Adapter pattern no core (escolhido):** fonte única, testável uma vez; custo = upgrade Tier 2 (toca mobile) + bump mobile.

## Consequências
- (+) Mata triplicação; atualização da base sem redeploy; web tira ~1.36 MB do build.
- (−) Cross-platform (web+mobile+core) → Tier 2; refator mobile protegido por `useMedicineDatabase.test.js`.
- Storage adapter deve guardar `typeof caches` (web, FR-008) — jsdom/non-secure sem Cache Storage.
