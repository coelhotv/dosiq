# ADR-079 — Licença AGPL-3.0 + dual licensing como modelo OSS do dosiq

**Status**: accepted (Tese 2026, 2026-07-05)
**Contexto**: auditoria da Tese 2026 descobriu que o repo NÃO era legalmente open-source — README afirmava "MIT" mas não existia arquivo `LICENSE` (GitHub `licenseInfo: null`). Sem grant de licença, o default legal é "all rights reserved": ninguém pode usar/forkar/contribuir com segurança jurídica, e o projeto é inelegível para grants (DPG Alliance exige licença aprovada OSI). Ao mesmo tempo, o PO declarou pragmatismo: toparia fechar partes B2B se surgisse receita (objetivos: 1º ativo de carreira, 2º renda indie via OSS, 3º utilidade pública, 4º opcionalidade M&A).

## Decisão

Licenciar o monorepo inteiro sob **AGPL-3.0-or-later**, com **dual licensing** explícito:

- **AGPL-3.0**: qualquer um usa/forka/self-hosteia; quem oferecer o dosiq como serviço (SaaS) é obrigado a publicar as modificações — fecha a brecha "cloud provider" que o MIT deixaria aberta.
- **Dual licensing**: o mantenedor (único copyright holder) pode vender licenças comerciais para quem não quiser as obrigações do AGPL (farma, redes de farmácia, white-label B2B). Contato: `contact@dosiq.app`.
- **Cláusula de contribuição externa** no README: contribuições externas concedem ao mantenedor o direito de relicenciar (preserva o dual licensing sem CLA formal enquanto o volume de contribuidores for ~zero).

## Alternativas rejeitadas

- **MIT/Apache-2.0**: permissiva demais para os objetivos — qualquer player fecha um fork B2B sem retorno; mata o item 2 (renda) e enfraquece o 4 (M&A: o código deixaria de ser diferencial).
- **BSL/Fair-code (Elastic, n8n)**: não é OSI-approved → inelegível para DPG Alliance e enfraquece o pitch "open-source de utilidade pública" do ativo de carreira.
- **Fechar o repo**: contradiz o objetivo 3 e destrói o build-in-public (funil LinkedIn) que já opera.

## Consequências

- + Elegível para DPG Alliance e grants que exigem OSI; pitch "open-source de verdade" defensável.
- + B2B monetizável sem trair o OSS (dual licensing é padrão consolidado: MySQL, Qt, Grafana pré-2021).
- + Copyright 100% do mantenedor hoje = relicenciamento futuro possível sem caça a assinaturas.
- − AGPL afasta contribuidores corporativos casuais (aceitável: contribuição externa hoje ≈ 0).
- − Dual licensing exige disciplina: dependências copyleft de terceiros no core precisam de auditoria antes de vender licença comercial.
