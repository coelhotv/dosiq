# ADR-074 — Centralizar fetcher + builder de contexto do chatbot em @dosiq/core

**Status:** accepted · **Categoria:** architecture · **Spec:** 015 · **Data:** 2026-06-23

## Contexto
A construção de contexto do paciente para o LLM está duplicada: web client
(`apps/web/src/features/chatbot/services/contextBuilder.js::buildPatientContext`) e Telegram server
(`server/bot/services/chatbotServerService.js::buildServerContext`, "adaptado de contextBuilder.js").
Forks divergem (web passa 6 campos com `doseInstances`; server passa 5 sem) e toda melhoria de
contexto precisa ser feita 2× (R-278 teve de ser replicado). Mobile não tem chatbot. Decisão de
ampliar a spec 015 para: centralizar + melhorar contexto (agrupar por plano terapêutico) + portar mobile.

## Decisão
Centralizar em `@dosiq/core/chatbot/`:
1. **Fetcher canônico** `fetchChatbotContextData({ supabase, getUserId })` → uma única definição dos
   selects (consolidando os de web/server; protocols já trazem join `treatment_plan(id,name,...)`).
2. **Builder puro** `buildPatientContext(rawEntities)` → string; dono de TODA derivação (filtro de
   ativos R-278, dias-restantes, agrupamento por plano, ordenação); reusa `splitDayTimeline`,
   `isProtocolActiveOnDate`, `formatDoseItem` (já no core).
3. **Seam Zod (CON-028)** valida a saída do fetcher antes do builder.
As 3 superfícies chamam o fetcher no seu runtime (web/mobile client-side, bot server-side — "(A)
client-build", RC3). Forks locais removidos.

## Alternativas consideradas
- **(B) Server-build** (client manda só userId; serverless monta): consistência máxima por construção,
  mas força a web a abandonar o DashboardContext + refetch, mais mudança, zero ganho extra depois do
  fetcher canônico. Rejeitada (RC3).
- **Migração full p/ CRUD repos** (`createMedicineRepository` etc. nas 3): blast radius grande, mexe na
  espinha de dados da web; desnecessário. Rejeitada (RC3/F2). O fetcher estreito dedicado é o meio-termo.

## Consequências
- (+) fonte única; melhoria de contexto feita 1×; paridade clínica por construção; mobile herda de graça.
- (+) drift de input morto na origem (um fetcher, não disciplina).
- (−) web faz 1 fetch dedicado no chat (perde reuso do DashboardContext) → mascarado por fetch-on-open
  + loading branded "Iniciando IA do dosiq…" + cache por sessão (FR-012).
- Trava-drift: teste de paridade cross-surface (FR-011/PO-5) bloqueante de release.
